## Skill authoring alignment (branch docs/skill-authoring)

- **WHAT:** `skills/code-kb/SKILL.md` went from ~1,500 to ~550 words: a description that says what and when, a server-prefix line, one tool table with CLI twins, and only the rules that change a call. `skills/telemetry` became `skills/code-kb-telemetry`. Both slash skills got `argument-hint`. `.claude-plugin/skills/` was deleted, and the sync test was replaced by `test_skills_follow_agent_skill_frontmatter_rules`. `evals/` holds 9 cases (3 per skill) with code-kb MCP mocks. `scripts/plugin-eval.sh` runs them.
- **WHY:** The user asked for a comparison with https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices and approved all the fixes and the rename. Plan and outcome: `docs/plans/2026-10-02-skill-authoring-alignment.md`.
- **HOW / discoveries:**
  - `claude plugin eval` refuses a plugin folder with >20000 entries (target/), so the script copies the tracked files to a temp folder and symlinks target/release/code-kb.
  - Codex ignores unknown frontmatter keys (codex-rs/skills/src/parser.rs has no deny_unknown_fields).
  - A grader regex with `[^"]` fails on the JSON-escaped `\"` in the Bash input.
- **IMPACT:** With the plugin, 9/9 cases pass on a single run (~$2.4 total). The mean gain over no plugin is about 0.5. The code-kb skill itself never fired in its own cases: the SessionStart routing hook already drove the right tool calls.

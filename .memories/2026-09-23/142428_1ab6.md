## Isolated the 3.5.0 performance changes

**WHAT:** Re-ran 300 MCP search calls per index with the exact same code-kb 2.0.2 release binary against the existing 3.3.1 and 3.5.0 artifacts. Updated the 2.0.2 performance report with this control.

**WHY:** The initial comparison used two code-kb builds, so its 20% search increase and 2.93 MB PSS increase could not be attributed solely to extractor data.

**HOW:** Selected the matching extractor for each artifact and verified artifact metadata remained at 3.3.1 and 3.5.0. Search p95 was 8.84 versus 10.91 ms with one code-kb binary; search-table pages grew 0.983 to 1.122 MB. Median PSS was 12.12 versus 12.27 MB with that same binary. The larger source scan already showed 6.3% more symbols, 17.1% more artifact bytes, and a 19.5% median time increase.

**IMPACT:** The search cost follows new index contents, while the apparent large PSS change does not. No speculative query or memory optimization is warranted before the patch release. Keep the measured tradeoff in release notes; profile again if a real workload exceeds a defined budget.

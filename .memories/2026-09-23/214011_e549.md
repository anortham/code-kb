## Task 2 branch review round B: nested paths, prepare watcher, retries, test strength

This commit fixes the lead's round B findings (R1, R2, R3, R6, R8, R9, R10) on `feat/project-root`.

- **R3:** after the lexical inside check, `resolve_project_root` calls `Workspace::nested_project_root`. It refuses a path in a nested worktree, submodule, or indexed project with the verbatim text `Path '...' belongs to the nested project '...', not to project_root '...'. Pass '...' as project_root.` A stale `project_root=/repo` with a `/repo/.claude/worktrees/x/...` path no longer reaches the main index.
- **R1:** `spawn_index_prepare(ws, db, with_watcher)` starts the watcher inside the thread, after the scan and the FTS step and before the offline reconcile, and returns it (`IndexPrepare = JoinHandle<Result<Option<WatcherHandle>, String>>`). The join adopts it. `new` passes `watcher.is_none()`. The `ponytail:` note now covers the watcher held by a parked prepare.
- **R2:** a non-error answer given while `self.reconcile` is still pending (the "Indexing ... started" answer) skips the argument-file baseline, so telemetry records saved = 0 and known = false. The signal is derived in `server.rs`, and `protocol.rs` is not changed.
- **R6:** the no-index branch respawns the prepare. Both texts now end with `; it will be retried on the next tool call.`
- **R8/R9/R10 (tests):**
  - The initialize-roots tests (mcp_test and m3) point roots at a bait Cargo project and assert that it gets no `.code-kb` folder.
  - The home-launch test ends the session and checks the launch log.
  - A new test proves parked-prepare reuse with a slow wrapper script for `julie-extract`.

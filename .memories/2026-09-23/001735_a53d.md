## Live 2.0 tool dogfood and local fixes

**WHAT:** Exercised all ten shipped MCP tools against code-kb, reviewed their schemas and outputs, and recorded per-tool results in `docs/reviews/2026-09-22-v2.0-live-dogfood.md`. Corrected CLI and MCP text for `limit=0` on lookup, search, references, and facts; corrected two per-section limit descriptions; refreshed the benchmark's removed symbol target and added facts coverage.

**WHY:** Zero limits falsely said no symbols, callers, or facts existed. The benchmark still queried removed `validate_syntax`, so it failed mid-run and scored one nonexistent search target as a miss.

**HOW:** Preserved query validation and JSON CLI behavior, then replaced only misleading text responses. Confirmed failures before fixes in CLI and MCP tests. Used the existing `sanitize_fts5_query` symbol for search/body benchmark cases and ran 30 measured iterations against the shipped 2.0 binary.

**IMPACT:** All ten benchmark MCP calls complete; six checked targets rank first. Full Rust workspace tests, clippy, Python benchmark unit tests, formatting, and diff checks pass. Fresh MCP RSS rose from 20.98 MB to 40.83 MB in the benchmark; a 20-pass run leveled near 37 MB, above the older ~25 MB guideline but without observed ongoing growth. Search partial-match recall and file-level test prediction remain documented tradeoffs.

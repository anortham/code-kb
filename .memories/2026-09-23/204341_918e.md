## Task 2: required project_root in the MCP server (issue #3, 2.1.0)

Every MCP tool except `telemetry_summary` now requires `project_root`. The server resolves it once per call in `handle_call_tool` and switches its one active index to that root.

- **Resolution:** `resolve_project_root` reads `project_root`, then the silent aliases `workspace` and `root`, and calls `Workspace::from_project_root` (Task 1). An absolute or `file://` value in `path`, `file_path`, `file`, `subpath`, or `dir` must lie inside the root, else the call is refused with a text that names both paths.
- **Refused calls** change no state and record the launch root in telemetry. Accepted calls record the resolved root.
- **Switch:** `switch_root(Workspace)` replaces `bind_workspace`. `--db` pins only the launch root. The watcher is dropped on a switch and starts after the new root's prepare finishes. Running prepares of roots the server left are parked in a plain `Vec` and reused on switch back, so two prepares never write one `artifact.db`.
- **Bounded wait:** a call polls `JoinHandle::is_finished` for up to 5 s (`CODE_KB_INDEX_WAIT_MS` test override). A prepare still running returns `Indexing <root> started; call again in a few seconds.` (not an error).
- **Version check** now also runs inside the prepare thread.
- **Startup pre-warm** runs only when `from_project_root(launch root)` accepts it (lead addition), so a GUI start in the home folder never scans it.
- **Deleted:** root binding from `initialize`, the path-inspection rebind, and the `--root` configure text. The no-index text is `No index exists for '<root>'.`

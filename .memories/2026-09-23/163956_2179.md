## Issue #3 design: session root from roots/list, per-call repository selection

**WHAT:** Rewrote `docs/plans/2026-09-23-mcp-roots-worktree-binding.md` after a cross-model design review (codex, grok, agy) and online research. Not implemented.

**WHY:** Branch `chore/julie-3.5.0-code-kb-2.0.2` (commit `1f3f87a`) only documents a workaround for issue #3. The server stays bound to the launch root after Claude Code `EnterWorktree`, and absolute-path rebinding is sticky: one lookup in another repo moves every later unscoped call and every subagent.

**HOW (evidence):**
- Probes under `claude -p` (Claude Code 2.1.280): `roots/list` follows `EnterWorktree` and `ExitWorktree`, answers in 0.3-2 ms during an open tools/call, sends no `list_changed`. A Bash `cd` does not change roots.
- Clients: Claude Code and Antigravity declare roots; Codex and Grok do not.
- MCP 2026-07-28 deprecates roots (SEP-2577) and points to tool parameters or server config.
- archcore-ai/cli#31 independently found the same thing and proposed the same poll.
- Existing bug: with `serve --db`, a rebind reconciles repo B into A's index (`locate_db` returns the pinned file).

**Decision:** keep invariant 1 (no workspace param). Session root = `--root` > `roots/list` (polled per call, disabled after one timeout) > process cwd. An absolute path in an existing path arg selects a repo for that call only, output names the root, no watcher for secondary roots, refuse `/` and `$HOME`.

**IMPACT:** #2 and #4 are fixed on the branch (verified on a C# fixture, 405 tests pass). #3 needs this plan implemented; likely a minor release, not 2.0.2.

## Task 1 (2.1.0, issue #3): core resolver for a tool call's `project_root`

- **What:** Added `Workspace::from_project_root(input: &str) -> Result<Workspace, WorkspaceError>` in `crates/code-kb-core/src/workspace.rs`, plus three `WorkspaceError` variants: `RelativeProjectRoot`, `ProjectRootNotFound`, `ProjectRootRefused { path, reason }`.
- **Why:** Every MCP tool except `telemetry_summary` will take a required `project_root`. Task 2 (MCP server) calls this resolver once per call so a server never answers from the wrong worktree.
- **How:**
  - Trim, parse `file://` with `parse_file_uri`, `normalize_path`, refuse relative paths (shared `is_absolute_path` helper, now also used by `resolve_path`).
  - `dunce::canonicalize` (failure = not found), then `find_workspace_root` walks up; a worktree `.git` file binds the worktree itself.
  - Refuse a filesystem root, the home directory (from `HOME`/`USERPROFILE`, even with a dotfiles `.git`), and a folder with no project marker and no `.code-kb/artifact.db`.
  - Logic lives in private `from_project_root_with_homes(input, homes)` so tests pass a temp home and never set env vars.
  - Reads only; never creates `.code-kb` or logs.
- **Impact:** 12 new unit tests; `cargo test -p code-kb-core`, clippy `-D warnings`, and `fmt --check` pass. Task 2 can wire the resolver into `server.rs`.

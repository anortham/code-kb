## Task 3: adversarial MCP server tests migrated to required project_root

**What:** `adversarial_m2_server_test.rs` and `adversarial_m3_server_test.rs` now pass `project_root` on every `tools/call` (code-kb 2.1.0, issue #3).

**Why:** Task 2 made `project_root` required and removed binding from `initialize` roots and path arguments, so the old tests failed.

**How:**
- m3 initialize matrix -> `test_adversarial_mcp_project_root_variants_answer_from_the_fixture_while_initialize_roots_are_ignored`: each URI/path variant (plus a new percent-encoded one) is the `project_root`; `--root` and `initialize` roots name a different scanned project; assertions check the fixture's full signature.
- m3 Windows churn -> `test_adversarial_mcp_project_root_casing_slash_and_uri_churn_answers_from_one_index`: `project_root` toggles casing, slashes, and URI form; telemetry shows one root for all 12 calls and only one `artifact.db` exists.
- Invariant-1 tests in m2 and m3 renamed; they now require `project_root` (exact description) on every tool except `telemetry_summary`; the `workspace` alias call must still succeed.
- m2 worktree tests pass the worktree as `project_root`; the active-transaction test now also checks the answer comes from the worktree index.
- `CODE_KB_INDEX_WAIT_MS=60000` set on every server that must answer from an index on its first call.

**Impact:** `cargo test -p code-kb-cli`, clippy `-D warnings`, and `cargo fmt --check` pass. The Windows-only test compiles and passes a Linux adaptation; the lead runs it on Windows.

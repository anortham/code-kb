## Branch review round C (Task 1 worker): watcher ownership, nested rule, dotfiles launch, CLI guard

- **C1 + C2 (server.rs):** every index prepare now owns its root's watcher. `spawn_index_prepare` lost its `with_watcher` flag and always starts the watcher after the scan and before the offline reconcile. `self._watcher = None` runs before every spawn (switch, no-index respawn, prepare-error respawn), so one root never has two watchers, and a reused parked prepare always brings its watcher. `McpServer::new` no longer starts a main-thread watcher or runs the version check itself; it only spawns the prepare. The fallback watcher start after a join moved below the two error branches.
- **C3 (workspace.rs):** `nested_project_root` counts only `.git` (worktree or submodule). An index-only member of a non-git monorepo stays reachable through the parent root.
- **C4 (workspace.rs):** the dotfiles-home fallback moved into `Workspace::find_root_with_homes(start, homes)`, used by `from_project_root_with_homes` and by `Workspace::discover` (which reads `HOME`/`USERPROFILE` through `home_candidates`). `serve` started in `~/work/app/src` under a home with `.git` now pre-warms `~/work/app`.
- **C5 (docs):** AGENTS.md/CLAUDE.md invariant 1 now say the walk stops at a folder with an excluded name (`target`, `node_modules`, `.claude`).
- **C6 (main.rs):** CLI auto-index needs `Workspace::from_project_root(root).is_ok()`, so a CLI query in a markerless folder under a dotfiles home no longer scans the home.
- **Verification:** 4 new tests red first. `cargo test --workspace --locked` 452 passed; clippy `-D warnings` clean; fmt clean; `cmp AGENTS.md CLAUDE.md` identical.

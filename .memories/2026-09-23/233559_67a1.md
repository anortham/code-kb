## Dogfood pass over all 10 code-kb tools on v2.1.0 (uncommitted fixes on main)

**WHAT:** I ran every MCP tool, the CLI commands that match them, and the error paths (relative root, home root, path outside the root, file typo, ambiguous name).

**Fixed (uncommitted on main):**
- `formatters.rs`: `match_line`. A search `Match:` snippet had been cut at the first newline, which hid the matched word. Now the snippet shows on one line. It is left out when it only repeats the signature, and the Doc line shows instead.
- `formatters.rs`: `reference_name`. Unresolved callee chains printed as multi-line receiver expressions. Now a chain longer than 60 characters shows only `….last_call`.
- `queries.rs`: `suggest_file_paths` has a 4th rule. It suggests a basename within 1 or 2 edits (`workspce.rs` finds `workspace.rs`).
- `queries.rs`: `find_related_types`. The context `### Types` section used to list the target's own return type name (`Result`, `String`). Now it lists the workspace type definitions for the target, its parameters, and its locals, as `signature (path:line)`.
- `main.rs`: the `hook` help now names PreInvocation.
- CLAUDE.md and AGENTS.md: the file-hint doc line is updated.

**Not fixed (upstream):** julie-extract writes no type fact for `let x = f(...)?` bindings. `pending_target_predicate` then refuses `x.method()`. Result: `nested_project_root` has no production caller in refs or blast_radius, even though `resolve_project_root` (server.rs:275) calls it. The fix belongs in julie-extractors Rust type inference: infer the binding type from the called function's return type, with the Result and Option layers removed. That needs a julie release and a pin bump.

**Evidence:** cargo test --workspace --release passed (23 test binaries, 0 failed). Clippy is clean. node plugin tests: 17 passed.

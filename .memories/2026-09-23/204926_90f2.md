## Task 2 fix round 1: pinned --db index and deferred launch-root prepare

The lead review of `ac73dc5` found two Important defects. Both are fixed in one commit.

- **F1 (regression):** `serve --root <markerless folder> --db <existing file>` refused every call for that folder. `workspace.rs` now exports `NO_PROJECT_MARKER_REASON`, and the resolver uses it. A new `resolve_root` in `server.rs` accepts a no-marker refusal as `Workspace::new(path)` only when the path is the launch root and `--db` names an existing file. `new` (pre-warm check) and `resolve_project_root` (now `&self`) both use it. The home and filesystem-root refusals are unchanged.
- **F2:** a launch root whose pre-warm was skipped was never prepared later. The new `prepared: bool` field is false when `new` skips the pre-warm. `switch_root` returns early for an equal root only when that root is prepared; otherwise it prepares the root through the normal switch path, so `--db` still applies. The watcher state is not the signal.

### Tests (`mcp_test.rs`)
- `test_mcp_pinned_db_is_the_index_of_a_markerless_launch_root`: red, then green.
- `test_mcp_markerless_launch_root_without_a_pinned_db_is_refused`: a guard; it was green before the fix and stays green.
- `test_mcp_launch_root_indexed_during_the_session_is_reconciled_on_first_use`: red, then green, and green in 5 of 5 repeat runs.

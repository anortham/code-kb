## Issue #3 design changed: required `project_root` (2.1.0 plan rewritten)

**WHAT**
- Rewrote `docs/plans/2026-09-23-mcp-roots-worktree-binding.md`: every tool except `telemetry_summary` requires `project_root` (absolute path of the project or worktree). No roots polling, no path-inspection rebinding. Missing index: build on the call, 5 s bounded wait, then "Indexing ... started; call again".
- Added `scripts/mcp-probe.py`: a dependency-free stdio MCP server that logs cwd, protocol, and `roots/list` answers per tool call.

**WHY**
- Probe of 4 clients: Claude roots follow EnterWorktree; Codex and Grok send no roots; agy answers `[]` (and offers `server/discover` with 2026-07-28 first); `grok -w` starts MCP servers in the main checkout.
- Fresh Herdr sessions on 2.0.2 (fixture `~/source/kb-e2e/flask-base`): Claude x2 and Codex x1 all passed an absolute worktree path on the first code-kb call. Codex then made unscoped calls that were right only because 2.0.2 binding is sticky, so the old per-call design would have broken it.
- User approved breaking core invariant 1 (no workspace parameter) and chose a separate parameter named `project_root`.

**IMPACT**
- Next: implement the plan in a new worktree after the user restarts Claude. Then rerun the black-box test (Claude x2, Codex x1, Grok -w x1); pass = telemetry `workspace_root` is the worktree for every call after the worktree step.

## File-level blast-radius test prediction follow-up

**WHAT:** Updated `compute_blast_radius_scoped_with_ids` to use the immediate module directory for files under `src/<module>/` as an additional test-name term. `server.rs` now predicts `mcp_test.rs` with a distinct `module-matched test file` reason. Added a regression test and updated the live dogfood report.

**WHY:** The original v2.0 review found that `blast_radius(file=crates/code-kb-cli/src/mcp/server.rs)` returned only two adversarial server tests, missing the main MCP integration test. The heuristic used only the basename `server`.

**HOW:** Reused the existing bounded SQLite test-file query and term deduplication. The new term comes only from a module immediately below `src`, avoiding broad matches from generic top-level directories. The regression test failed before implementation and passed after. A fresh CLI run found `mcp_test.rs`; `scripts/benchmark_quality.py` still found only its specific test. Local backslash-path input produced the same forward-slash result.

**IMPACT:** Full Linux workspace verification passed 396 Rust tests, clippy, formatting, and diff checks. The exact blast-radius workload had no observed latency or RSS regression across 30 warm runs; the answer grew from ~207 to ~256 tokens because it includes the missing test. Windows guest verification remains to run after this clean commit.

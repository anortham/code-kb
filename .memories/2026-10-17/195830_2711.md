## Callers report: 3 s time limit and four wrong-exclusion fixes

**WHAT**
- `reference_report.rs`: `ACCOUNTING_TIME_LIMIT` (3 s) replaces the row budget. The target's judge runs in chunks of 2,000 rows, nearest first, and stops at half the limit (`judge_deadline`); cheap checks use the rest. Unchecked sites get `likely` (one definition) or `unresolved`, with the basis `not checked within the time limit`. The note counts merged sites.
- Four fixes for true callers labeled `excluded`: C# extension methods (`extended_type` of the `this` parameter counts as an owner); julie test labels (`is_test_label`, `test("x")` signatures) dropped from definitions and import matches; a receiver qualifier import (`z.coerce.boolean()`) must reach the owner file; `mark_hidden_receivers` flags a call whose name follows `.` after `)` or `]`.
- Docs: CLAUDE.md/AGENTS.md rules, RELEASING.md reach gate step 7, review `docs/reviews/2026-10-17-accuracy-base-gate.md`.

**WHY**
- Hermes `get` took 56 s; now 3.25 s (v2.6.0: 3.7 s).
- The gate scores only proven precision and accounted share, so 67 true C# callers hid in `excluded`.

**HOW / evidence**
- Gate PASS, proven precision 1.000 in all 7 languages, recall 0.803 (baseline 0.529). Excluded-true: C# 67 → 0, TS 34 → 2, Java 4 → 2.
- The first hidden-receiver rule (any `.` before the name) lost 17 Python `self.x()` proven sites from julie relationship rows; narrowed to `)`/`]` before the dot. `lost_proven.py` shows 0 lost proven sites across 7 repos.
- 704 tests pass, clippy clean.

**IMPACT / open**
- serve RSS 88–114 MB after big reports vs 32–38 MB in v2.6.0. Live heap is 12–17 MB; glibc keeps freed pages. `malloc_trim(0)` per call gives 38–53 MB, but the workspace forbids unsafe code: owner decision.
- An excluded-precision pass mark for the gate: owner decision.

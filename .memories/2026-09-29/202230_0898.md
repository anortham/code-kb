## Flaky Windows test fixed by following the server contract

- **WHAT:** `test_adversarial_worktree_parent_in_active_transaction_resilience` (crates/code-kb-cli/tests/adversarial_m2_server_test.rs) now calls `file_skeleton` again while the answer starts with `Indexing ` (up to 180 s). A failed assert prints the server logs from `<root>/.code-kb/logs` (`server_logs`).
- **WHY:** CI run 36602834350 attempt 1 (windows-latest) got `Indexing ... started; call again` after the 60 s wait. Passing Windows CI runs take 8-14 s; Linux and the win-test guest take 5-9 s (25/25 guest loops passed).
- **Evidence for the normal time:** the worktree copy waits 5 s for `wal_checkpoint(TRUNCATE)` on the locked parent, fails, and falls back to a full `julie-extract scan`.
- **Root cause of the 60 s outlier: not proven.** Suspect a slow first start of `julie-extract.exe` on a fresh runner: this is the first test in the Windows job that starts the extractor. No server log survived the failed run; the new log dump captures it next time.
- **Rejected:** a product change to the checkpoint wait (no evidence that it caused the 60 s).

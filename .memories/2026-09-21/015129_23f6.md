## WHAT

Added `test_path_predicate(alias)` in `crates/code-kb-core/src/queries.rs`. It is one SQL boolean over `lower(replace(alias.path, '\', '/'))` that mirrors the Rust `is_test_path` rule for rule. Three query sites now add `AND NOT <predicate>` when tests are excluded: `candidate_filters` (all three recall branches), the `name_search` fallback in `fts_search_symbols_explained`, and the lookup SQL in `search_symbols_scoped`. The qualified-name early return in `search_symbols_scoped` got the same guard in Rust. `is_test: true` (MCP) and `--include-tests` (CLI) lift the flag checks and the path rule together. Their description text says so now.

## WHY

`julie-extract` sets `is_test` only on callable symbols with a test marker. Helpers, fixtures, and constants inside test files stay unflagged, so README-phrased queries sometimes ranked a test-file helper first. code-kb already owned the path rule; this reuses it instead of changing the extractor.

## HOW

Three new tests in `queries.rs` `mod tests`. One runs both forms over a 17-path list through an in-memory SQLite connection and asserts they agree. Two cover the hide-and-lift behaviour for search, lookup, and the qualified early return. Red was proved by stubbing the predicate to `(0)`: the three tests failed, the other 54 passed. Green: `cargo test -p code-kb-core --lib -- queries::tests` 57 passed. Ceiling: `cargo test -p code-kb-core` 251 passed, `cargo test -p code-kb-cli --test cli_test --test mcp_test` 45 passed, `cargo fmt --all -- --check` and `cargo clippy -p code-kb-core -p code-kb-cli --all-targets -- -D warnings` both clean. No rerank change, no new table, no schema property change.

## Post-v1.3.0 review and plan 024

**WHAT:** Wrote `docs/plans/024-v1.3.1-lookup-fixes-and-v1.4-edit-file.md` (13 tasks, two releases) after a review of telemetry, TODO files, a Codex second opinion, and julie/miller edit-adoption data.

**WHY:** Telemetry (2,584 calls) showed `replace_symbol_body` never called, `find_structural_facts` unused since 09-15, and every error a plain "not found" with no recovery. Four lookup defects reproduced on main at 2d965c6:
- exact-name lookup of a test function hidden by the v1.3.0 test-file rule
- qualified names accept a bogus ancestor (only the immediate parent is checked)
- qualified name plus a directory `--path` fails
- lookup full-text fallback swallows DB errors with `unwrap_or_default()`
Also: `facts sql` returns `css.media_query.v1`; facts and literals share one limit with no cap notice; routing hook uses non-canonical parameter names.

**HOW:** Edit-tool evidence: julie `edit_file` 2,521 calls (7.1%) vs symbol rewrites 126; miller `replace_text` 694 vs `replace_symbol_body` 65; code-kb 0. So v1.4 adds `edit_file(file_path, old_text, new_text, occurrence)`: exact then whitespace-tolerant match, refuses non-unique match unless occurrence given, reuses the validate/write/reindex/rollback tail of `replace_symbol_body`. It reads the file from disk; no indexed content needed.

**IMPACT:** Plan is a draft awaiting owner approval. Codex opinion saved at `~/.code-kb/search-eval/reviews/2026-09-21-codex-v1.4-direction-opinion.md`. Housekeeping (two merged worktrees, two merged branches) stays outside the releases.

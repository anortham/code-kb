## One reference row per site

`find_references_internal` in `crates/code-kb-core/src/queries.rs` collected caller rows from three statements. A QML root object emits both an `extends` pending relationship and a `base_type` `type_usage` identifier at the same file and line, so `refs` printed every extending component twice.

- **Fix:** the identifier statement now carries two `NOT EXISTS` clauses. One drops an identifier row when a `relationships` row for the same target covers the same `path` and `start_line`. The other drops it when a `pending_relationships` row with the same `target_terminal_name` covers that site. The filter runs in SQL, so `LIMIT` still counts the rows the caller sees.
- **Test:** `a_site_with_both_a_relationship_and_an_identifier_yields_one_row` in `crates/code-kb-core/tests/references_test.rs`. The fixture is Python (a concrete relationship) plus TypeScript (a pending relationship), not QML, because the extractor that code-kb selects at runtime is the pinned 3.1.3 at `/home/murphy/source/code-kb/.tools/julie-extract`, and that build emits no QML root-extends rows.
- **Live:** Omarchy `refs BarWidget --file shell/Ui/BarWidget.qml` now prints 12 `extends` rows and no `type_usage` rows; `refs Panel --file shell/Ui/Panel.qml` prints 10 `extends` and 1 `instantiates`.
- **Impact:** QML reference lists lose the doubled rows in every language whose extractor records both a relationship and an identifier for one site.

## Release v1.2.0 CI: two real defects found by CI, both fixed

**WHAT:** Three commits after 3b0f9ae on main: 1eb9edd (tests tolerate SQLite sidecars beside a test DB; *.db-wal/*.db-shm/*.sqlite-wal/*.sqlite-shm hard-excluded; MCP start test prints the response), 98a0aaf (plan 021), and a fix commit: `scan_workspace` treats extractor exit 1 with status `partial` as success with a warning when the artifact exists.

**WHY:** (1) The reconcile tests keep test.db at the workspace root, so the extractor's WAL sidecar showed up as an added file on macOS. (2) On Windows the initial scan raced with the test's telemetry journal file inside the workspace; julie-extract reported `partial` (exit 1), and code-kb treated the whole first scan as failed, so the first tool call errored. Per julie-extract's cli-contract.md, exit 1 + `partial` means the artifact is valid minus the unreadable files.

**HOW:** Partial scans now log and continue; the next reconcile retries the skipped files. Test covers it with a chmod 000 file (unix).

**IMPACT:** Release waits on the third CI run. Then: tag v1.2.0, release-binaries workflow, checksums into docs/release-notes/v1.2.0.md, gh release edit, cargo publish core then cli. Plan 021 is committed and awaits approval.

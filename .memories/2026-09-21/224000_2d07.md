## Signal handlers get a handler / handler (candidate) label

Plan 025 wave 2, item 2 (G6 / B6) on `feat/v1.5-qt`.

- **Problem:** the next `julie-extract` marks every QML signal handler with a `member_access` identifier carrying `{"role":"signal_handler","receiver":"<owner>"}`. `refs <signal>` listed all of them as plain `member_access`, so an unowned match looked as certain as an owned one.
- **Fix (one SQL CASE, language-agnostic):** the identifier branch of `find_references_internal` labels a row with that role `handler` when its receiver equals the target's parent name, or the target's own name when the target is a type. A missing or foreign receiver gets `handler (candidate)`. Rows without the role keep `i.kind`.
- **No formatter change:** `format_references` prints the kind verbatim (`formatters.rs:385`), confirmed with the CLI before editing.
- **Tests:** `references_test.rs` scans a QML fixture, then inserts four synthetic identifier rows: owned receiver, absent receiver, foreign receiver, and a plain `member_access`. The kinds come back `handler`, `handler (candidate)`, `handler (candidate)`, `member_access`.
- **Verified on the final tree:** `cargo test -p code-kb-core`, `cargo test -p code-kb-cli`, `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, all green.

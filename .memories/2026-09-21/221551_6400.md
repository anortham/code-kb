## B1: the skeleton renders nested objects as containers

Plan 025 Part B, item B1 (gap G1, code-kb side). The skeleton flattened QML
object trees because only a fixed kind list could hold children.

- **What:** `is_container_kind` in `crates/code-kb-core/src/formatters.rs` no
  longer names a kind list. A kind is now a container when it is not skippable
  (`variable`, `parameter`, `import`) and does not hide a body
  (`function`, `method`, `constructor`, `destructor`, `operator`).
- **Why:** The extractor 3.2.0 release emits a nested QML object as kind
  `field` with the signature `localPluginReloadTimer: Timer` and parents its
  bindings, handlers, and functions under it. Those children were dropped.
- **How:** Functions stay leaves, so local variables and parameters stay
  invisible and a body is still hidden.
- **Impact:** A field or property with children renders as
  `name: Type { ... }` with the children nested. Two side effects on real
  data, both wider information, not lost information: a Rust enum variant with
  named fields now lists its fields, and a TOML inline table lists its keys.

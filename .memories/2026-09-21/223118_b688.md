## A one-line symbol with children renders as a skeleton leaf again

**WHAT** — `render_symbol_skeleton` in `crates/code-kb-core/src/formatters.rs` now renders any symbol whose `start_line == end_line` as a leaf, even when the symbol has children.

**WHY** — Commit 80a7881 promoted every non-skippable, non-body-hiding symbol with children to a container. That is correct for multi-line QML objects, but a one-line symbol then printed four lines. The skeleton of `crates/code-kb-core/Cargo.toml` grew from 40 to 88 lines, because each inline table such as `rusqlite = { workspace = true }` printed as an open brace, a child line, a close brace, and a blank line. That breaks the token-density invariant in CLAUDE.md.

**HOW** — One guard in the shared render path: `let spans_multiple_lines = sym.end_line > sym.start_line;` is added to the container condition. `sanitize_skeleton_sig` is unchanged, so the Cargo.toml row prints `rusqlite =; // L15-15` as it did on main. Multi-line symbols with children keep the container rendering from 80a7881.

**IMPACT** — The Cargo.toml skeleton is 40 lines again. Both QML tests from 80a7881 stay green.

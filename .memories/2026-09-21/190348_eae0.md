## v1.4.0 release blocked by a racy Windows test, replaced with a unit test

**WHAT:** CI run 35641858904 on f9622ed (main, after the fast-forward of feat/v1.4) failed on both Windows jobs. The only failure was `test_edit_file_detects_concurrent_modification` in `crates/code-kb-core/tests/edit_test.rs`. It got `NoMatch` instead of `ConcurrentModification`.

**WHY:** The test raced a 30 ms sleep against `edit_file`. On the Windows runners `ensure_fresh_file` on a 20 000-function file took longer than 30 ms, so the rival write landed before the edit's first read. The edit then saw the rival content and reported no match. The behavior under test is fine; the test was timing-based.

**HOW:** Deleted the integration test. Added `test_commit_file_edit_refuses_bytes_read_before_a_rival_write` to the in-module tests of `crates/code-kb-core/src/edit.rs`. It calls the private `commit_file_edit` with stale `existing_bytes` and asserts the `ConcurrentModification` error and an untouched file. No thread, no sleep.

**IMPACT:** Release path restarts: commit, push, CI, preflight, tag v1.4.0, publish crates. Lesson: never gate a race on a sleep; test the check directly.

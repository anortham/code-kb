## Task 8: distinct-term scorer behind `CODE_KB_RERANK`

**WHAT.** A second rerank scorer in `crates/code-kb-core/src/queries.rs`, selected by an
environment switch, plus the explain field and printer that make it measurable.

**WHY.** The current scorer adds three field coverages, so a row that repeats two query
words across name, signature, and doc beats a row that covers three different words once.
Candidate-sample rarity also inflates prose words.

**HOW.**

- New `Scorer` enum with `Coverage`, `Distinct`, `DistinctRarity`. `Scorer::from_env`
  reads `CODE_KB_RERANK` once. `rerank` became `rerank_with(.., scorer)`, resolved by
  `fts_search_symbols_explained`, so tests stay hermetic.
- `term_credits` gives each query term one credit from its strongest field: name whole
  token 3, name stem 2, signature 2, doc 2, name substring 1, nothing 0.
- `term_score` = 52 * sum(credit * w) / (3 * sum(w)). Variant A uses uniform weights,
  variant B the existing rarity weights.
- Under both new scorers the all-words tier needs every term at name strength 2 or more,
  so a substring-only name no longer earns the 60-point bonus.
- `SearchExplain` gained `terms: Vec<(String, String, u8)>`, filled by every scorer.
  `explain_line` prints it.

**IMPACT.** Both scorers now run on identical candidates, so task 9 can pick one. The
switch is removed when a winner is promoted.

## Task 9: global IDF weights and experiment knobs for the distinct scorer

Plan 022, design 2, round 2. Branch `feat/search-v1.3`, on top of `4d187fa`.

### What changed

- `db.rs`: `ensure_fts_index` now creates `symbols_fts_vocab` (an `fts5vocab` row view over `symbols_fts`) on both exit paths, outside the `fts_rule` marker guard, so a ready index gains it without a rebuild. Creation is best effort.
- `queries.rs`: `Scorer` became a struct carrying `distinct`, `weights`, `text_credit`, `sig_bytes`, `nameless_cap`, read from the `CODE_KB_RERANK*` variables once per search. New `idf_weights` reads global document frequency from the vocabulary table, with a `symbols_fts MATCH` count as the fallback. `term_credits` credits are now `f64`.
- `models.rs`: `SearchExplain.terms` is `f64`; new `scorer` field carries the effective knob line.
- `formatters.rs`: the rerank header prints the knob line when the distinct scorer runs.

### Why

The uniform distinct scorer gained file@1 but not symbol@1, and lost regression symbol@1. Two causes: name-less rows collected too much text credit, and uniform weights treat every term alike.

- 5 new tests, 83 in the red-green scope, 15 core binaries, 34 CLI, 11 MCP, 1 trigger test, fmt, clippy: all pass.
- The default scorer is byte-for-byte unchanged: the regression set on the default scorer matches the task 8 baseline (25 file@1, 22 symbol@1, no case worse).

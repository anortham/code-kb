## code-kb v1.5.0 queries lane: plan 025 Part B items B4, B5, B3, B2

Four red-green cycles in the worktree `wf_be0f6c05-f1d-1`, one commit each, all in
`crates/code-kb-core`.

- **B4 test path rule.** `is_test_path` and its SQL mirror `test_path_predicate` add the Qt
  `tst_` file-name prefix and the KDE `autotests` directory. The mirror's substring guard now
  admits `tst_`, because a bare `tst_foo.qml` holds neither `test` nor `spec`. Eleven new cases
  in the shared `TEST_PATH_CASES` list cover both forms.
- **B5 fact aliases.** `CATEGORY_ALIASES` gains `signal`/`signals`, `import`/`imports`,
  `binding`/`bindings`, `component`/`components`, `module`/`modules`, and `pragma`. Each names a
  pattern-id family in the `.name.` contains form, so the rule reaches any language that emits
  the same fact, not only QML.
- **B3 receiver matches.** `find_references_internal` runs a second identifier query after the
  name query: a type-like target also collects `member_access` rows whose `metadata_json`
  receiver is the target name. A row that carries a `receiver_qualifier` counts only when the
  qualifier is the target's own parent name.
- **B2 import aliases.** `pending_target_predicate` accepts a `target_receiver` that equals the
  `alias` or `local_name` of an import symbol in the same file, inside the unqualified branch, so
  the target still ranks by name and proximity.

### Why the predicate now takes a connection

Many synthetic test fixtures build a `symbols` table without `metadata_json`. Referring to that
column unconditionally broke two lib tests at prepare time. `pending_target_predicate` now takes
`&Connection` and drops the alias clause when the column is absent, the same pattern
`not_documentation` already uses.

### Left undone on purpose

The identifier owner check keeps no import-alias branch. On both corpora the check drops no row
whose receiver is an import alias, because the exclusion needs a workspace symbol that carries
the receiver name and owns a member of that name. Adding the branch would only fire in the case
where it is wrong, for example `Theme.color` claiming to be `Button.color`.

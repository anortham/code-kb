## Plugin launcher: download-on-first-run (plan 017 distribution follow-up)

**WHAT:** `bin/code-kb-launcher.cjs` (dependency-free Node, adapted from the miller launcher): reads the version from `.claude-plugin/plugin.json` (or `CODE_KB_VERSION`), downloads `code-kb-v<ver>-<target>.<ext>` and its `.sha256` sidecar from GitHub Releases into `~/.code-kb/dist/<ver>/<target>/`, verifies, unpacks with `tar` (Windows: `System32\\tar.exe`), keeps one older version, then runs `code-kb <args>`. `CODE_KB_BIN` skips the download; `CODE_KB_HOME` moves the cache. All manifests now go through it: `.claude-plugin/plugin.json`, `hooks/claude-codex-hooks.json` (timeout 60 for first-run download), `.codex-plugin/plugin.json` via `.mcp.json`, and new Antigravity files `plugin.json`, `mcp.json`, `mcp_config.json`, `hooks.json`. Tests: `tests/plugin/code-kb-launcher.test.cjs` (loopback HTTP server, fake tar.gz) and `plugin-manifests.test.cjs`; wired into CI, `release-preflight.sh` (also checks root plugin.json version), and `run_tests.sh`.

**WHY:** User wants one install command per harness with no manual binary download; Node assumed present.

**HOW:** Red first (13 tests), then launcher. `claude plugin validate .` and `agy plugin validate .` pass. Real smoke against the 1.0.1 release on Linux: download, verify, run, then cache hit.

**IMPACT:** README now leads with plugin installs and moves binary download to a Manual Configuration section. CLAUDE.md/AGENTS.md invariant 7, RELEASING.md, release notes v1.0.2 updated. Windows launcher smoke still pending.

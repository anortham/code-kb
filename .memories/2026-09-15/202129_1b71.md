## Windows lock test was timing-based and broke once syntax checks became a subprocess

**WHAT:** `test_adversarial_rollback_fails_cleanly_when_dest_locked` (Windows only) slept 5 ms and then locked `calc.rs`, assuming the edit's write had already happened. With `validate_syntax` now spawning `julie-extract check`, the write happens later, so the lock landed before the write and the edit failed with `Io(PermissionDenied)` instead of a rollback error.

**HOW:** The lock thread now polls the file until its bytes differ from the initial content (10 s cap), then takes the share-mode lock. It passed 8 times before on Windows and failed once after the change, on the first run with the new syntax path.

**IMPACT:** Any future step added before the write in `replace_symbol_body` will not break this test again.

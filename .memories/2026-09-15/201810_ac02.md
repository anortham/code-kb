## Syntax validation moves to julie-extract check (plan 017 finding 6)

**WHAT:** `crates/code-kb-core/src/syntax.rs` no longer bundles tree-sitter grammars. `validate_syntax(file_path, content)` keeps its signature but now spawns `julie-extract check --path <rel> --json` with the proposed file text on stdin and maps the report: `ok` → `Ok(true)`, `unsupported` → `Ok(false)`, `failed` → `ParseError(path, first message (+N more))`, spawn or report problems → new `SyntaxError::CheckFailed`. Six tree-sitter crates removed from the workspace and core `Cargo.toml`; `serde_json` added to core. Pin moved to julie-extract 3.0.0 (`PINNED_JULIE_VERSION`, `scripts/julie-pins.json` with blank sha256s until the release exists, CLAUDE.md/AGENTS.md invariant 7). `.tools/julie-extract` is a local 3.0.0 build from julie branch `feat/syntax-check`.

**WHY:** User decision: code-kb must not do tree-sitter work; julie-extractors owns parsing. Side effect: every extractor language is now validated, not five.

**HOW:** Red test first: broken Ruby body accepted before, rejected now (`edit_test.rs`). Plus `validate_syntax` unknown-extension and clean-Rust test. Docs: invariant 3 text, both SKILL.md, both routing-block copies (hooks/ and crates/code-kb-cli/src/, which must stay identical), README, release notes v1.0.2 section 5, plan 017 finding 6.

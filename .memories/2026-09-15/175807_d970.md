## find_references returns type usages and member accesses (branch fix/extractor-seam)

**WHAT:** `find_references_internal` callers branch now also reads `identifiers` rows of kind `type_usage` and `member_access` matching the name (skipping rows whose containing symbol is an import, since the `imports` edge already reports those). New `has_table` helper. Tests: `crates/code-kb-core/tests/references_test.rs` (struct type usage from a function, field member access). Tool description, README, SKILL.md copies, routing block, CLAUDE.md/AGENTS.md, release notes v1.0.2, plan 017 updated.

**WHY:** 99% of relationship rows are `calls`; asking for references to a class, type, or field returned constructor calls only. The user chose option 2: keep only the type-usage and member-access identifier rows at the julie `facts` level.

**HOW:** TDD red (kind missing) then green after rebuilding julie with the revised facts level (identifier walk runs at facts; `strip_to_level` retains the two kinds and keeps literals). hermes-agent facts scan: 52 s, 2.6 GB RSS, 1.7 GB index, 367k identifiers (286k member_access, 81k type_usage).

**IMPACT:** code-kb 1.0.2 answers "who uses this type or field" without resolution. Still requires julie-extract 2.43.0 (unpublished). `blast_radius` still uses call edges only.

## Remediate macOS Telemetry Summary Symlink Matching in CI

- **WHAT:** Fixed test failure in `test_mcp_telemetry_summary_scoped_errors_no_cross_workspace_leak` on macOS CI runner by supporting symlink/canonical path reconciliation and macOS `/private/var` <-> `/var` path equivalence in telemetry queries, and ensuring `code-kb serve` records `self.workspace.canonical_root` instead of `self.workspace.root`.
- **WHY:** On macOS, `/var` is a symlink to `/private/var`. Temp directories created by tests had paths starting with `/var/folders/...`, but `Workspace::new` canonicalized them to `/private/var/folders/...`. When `telemetry_summary` queried `self.workspace.canonical_root`, SQLite exact string equality `workspace_root = ?1` failed to match rows stored with the uncanonicalized symlink path.
- **HOW:**
  1. Implemented `workspace_root_match_candidates(ws)` in `code-kb-core::telemetry` to compute both canonical and symlinked path representations (including macOS `/private/var`, `/private/tmp`, `/private/etc` symmetry).
  2. Updated `get_telemetry_summary` and `generate_bug_report` to query `(workspace_root = ?1 OR workspace_root = ?2)` when alternate representations exist.
  3. Canonicalized `workspace_root` before inserting in `record_tool_call_conn`.
  4. Updated `mcp/server.rs` to record `&self.workspace.canonical_root` on tool calls.
  5. Updated `mcp_test.rs` to use canonical workspace roots for test assertions.
  6. Added unit test `test_telemetry_summary_symlink_and_macos_private_var_matching`.
- **IMPACT:** Telemetry scoping and error privacy now function identically and robustly on macOS runners and filesystems with symlinked roots.

### WHAT
Documented the release notes authoring and publication process in `docs/RELEASING.md`, updated `.github/workflows/release-binaries.yml` to support `body_path` with `docs/release-notes/v${VERSION}.md`, authored full release notes for `v1.0.0` and `v1.0.1`, and published them directly to GitHub Releases.

### WHY
GitHub releases were previously published with auto-generated commit log notes (`Full Changelog:` link only). Maintainers and users need clear, structured, informative release notes covering highlights, capabilities, bug fixes, invariant guarantees, and asset checksums.

### HOW
1. Created `docs/release-notes/v1.0.0.md` and `docs/release-notes/v1.0.1.md`.
2. Updated `.github/workflows/release-binaries.yml` to check for `docs/release-notes/v${VERSION}.md` and supply `body_path` to `softprops/action-gh-release@v2`.
3. Updated `docs/RELEASING.md` with step 3 (Prepare Release Notes) and instructions for `gh release edit vX.Y.Z --notes-file docs/release-notes/vX.Y.Z.md`.
4. Published the new notes to GitHub via `gh release edit` for both `v1.0.0` and `v1.0.1`.
5. Verified live release pages via `gh release view`.

### IMPACT
Future releases will automatically include structured markdown release notes in GitHub Releases when `docs/release-notes/vX.Y.Z.md` is present. Existing `v1.0.0` and `v1.0.1` releases now feature complete release notes and asset checksum tables.

## Verified julie-extract 3.6.0 (call-initializer type facts) with code-kb, pin moved to 3.6.0

**WHAT:**
- julie-extractors `main` at a967cc58 (3.6.0, 132 commits ahead of origin, not pushed). The default tier has 6,670 passed and 7 ignored. The contract tier has 187 passed. The merged branch `feat/call-initializer-type-facts` is deleted.
- In code-kb (uncommitted on main), `PINNED_JULIE_VERSION` and `scripts/julie-pins.json` are now 3.6.0. The sha256 values are still for 3.5.0 and must be refreshed from the julie 3.6.0 GitHub archives. `.tools/julie-extract` is a local 3.6.0 build. The version references in CLAUDE.md, AGENTS.md, README, and docs/site are updated.
- Corpus gate fixes:
  1. It now fails when an index records a different `binary_version` than the offered extractor. code-kb prefers its pinned extractor over `JULIE_EXTRACT_BIN`, so the first 3.6.0 run was a false PASS on 3.5.0.
  2. A new "typed receiver calls" diff. code-kb resolves `local.method()` at query time, so the `relationships` table never showed the gain.
  3. It deletes `-wal` and `-shm` before it creates or copies a database. A stale sidecar left by the Python read-only reader damaged an upgrade copy. code-kb's own `rebuild_index` already deletes them.
- `find_related_types` now uses `type_declaration_line`, which drops attributes and gives one line of at most 120 characters. The multi-line C# record signatures had flooded the output.

**Results:** The corpus is PASS on 15 entries. Typed receiver calls: 519 gained, 0 lost. Call edges: 1 lost, which is correct (Elixir alias scope). The spot-checked samples were correct in Swift, Python, TS, C#, and Rust. The 206 removed C++ type facts were macros and keywords, all wrong. `refs nested_project_root` now lists `resolve_project_root`. The code-kb suite passes with 3.6.0 (23 test binaries). Scan times did not change.

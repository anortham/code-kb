## julie 3.7.0 upgrade: code-kb loses bare implicit-this callers

- Branch `chore/julie-3.7.0` (commit 1e8929a): pin 3.7.0 locally, `.tools/julie-extract` = julie a3c042d0 build; old binary saved as `.tools/julie-extract.published-3.6.3`.
- Fixed: julie 3.7.0 refuses incremental update on a foreign index (`fingerprint_mismatch`, exit 3); code-kb served stale rows. Now `write_incrementally` + scan arm run `scan --force` in place (rename swap broke callers holding a connection).
- Corpus check vs v2.2.2: PASS (`target/release-corpus-3.7.0`). Dogfood round 20260927T220921Z: no wrong answers; blast_radius noise identical to v2.2.2 (known gap).
- **Regression:** julie 3.7.0 no longer resolves calls by file-unique name; they stay pending. code-kb's bare pending rule only matches same-parent or top-level targets, so `refs` loses ~half of those callers (72/140 sampled lost edges; script in scratchpad `edgecheck2.py`, checks by `--symbol-id`). Patterns: inherited method via implicit this (Swift `store`, Java/C#), C# partial class (`CheckNotNull`, receiver_type metadata = class name), enclosing namespace/class (`assertString`, `RootSomethingElse`, RSpec `cookie_route`), Ruby mixin (`halt` in Helpers -> Base), JS `this.` in prototype mixins (typeahead), C++ `get_number` (julie gives wrong parent `byte_swap`).
- Plan: extend bare-call branch of `pending_target_predicate` for implicit-this languages: lexical ancestors, extends chain, same-file partial classes.

## Resolver rules for julie 3.7.0 pending calls (queries.rs `pending_target_predicate`)

- **Bare call, implicit-receiver languages** (java, csharp, kotlin, swift, cpp, scala, dart, ruby, vbnet): matches a method of the caller's class chain (nearest wins) and another part of the same class in the same file (C# partial).
- **Bare call, any language:** matches a definition in an enclosing function/namespace/module scope (nearest scope that defines or imports the name wins); enclosing class bodies contribute only nested types, in implicit-receiver languages (julie parses C++ doctest macros as fake methods of fake classes).
- **this/self/cls:** also match a sibling member at depth 0 (julie no longer resolves `this` in ordinary JS functions / object literals).
- **Pending extends:** a base class named by name counts unless a same-named class is strictly closer to the subclass file (fixed Sinatra::Base vs Rack::Protection::Base false matches).
- Evidence: sampled lost callers 72 -> 42 (rest are wrong v2.2.2 targets julie fixed); false-match samples of new rows all real; hermes-agent Python timings unchanged; blast_radius --file 10-40% slower on C#/Java, Sinatra 0.11 -> 0.32 s (more results), Miller one file 0.74 -> 1.2 s (plan change, cause not isolated).
- Remaining gaps: Ruby mixin calls (halt in Helpers -> Base), Kotlin anonymous object base, C++ julie wrong/missing parents (get_number, assertString), C++ template alias ctor, namespace-qualified lookup names.

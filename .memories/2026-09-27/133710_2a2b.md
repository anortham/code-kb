## WHAT
Added two receiver-query indexes in `ensure_fts_index`, including upgrades of already-ready FTS databases. Added a regression test checking exact rows and fewer than 100 SQLite VM steps for each hot lookup. AGENTS.md and CLAUDE.md describe maintenance.

## WHY
The 20-second Hermes query repeatedly looked up common variable names across the index and scanned same-name pending calls when suppressing duplicate references. A warm cache hid physical disk I/O but not CPU and cached-read costs.

## HOW
Create indexes on `type_facts(resolved_type, symbol_id)` and `pending_relationships(target_terminal_name, path, start_line)` using existing startup initialization. No query semantics or public interfaces change. Ancestry aggregation, UNION changes, and extra symbols indexes were rejected after measurement. Initial whole-query probes improve references from about 20 s to 2 s with identical rows, at about 37 MiB index growth. A read-only Astra review found no blockers. New test failed at 6,012 and 10,018 VM steps before each fix and passes afterward.

## IMPACT
Full Linux gate passes (546 Rust tests, format, lint, release build). Repeated paired CPU/I/O/latency measurement and Windows verification remain before final claims. Work stays on fix/receiver-reference-reliability; no publication authorized.

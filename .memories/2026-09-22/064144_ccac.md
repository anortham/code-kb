## K2: the `property` fact alias

Added a `property`/`properties` category alias so one query reaches both the QML and the Qt C++ property facts.

- **What:** `PROPERTY_FAMILIES = [".property_declaration.", ".qt_property."]` in `crates/code-kb-core/src/queries.rs`, plus the `("property", ...)` and `("properties", ...)` rows in `CATEGORY_ALIASES`. Invariant 6 alias list in `CLAUDE.md`/`AGENTS.md` names them now.
- **Why:** julie-extract 3.3.0 emits `cpp.qt_property.v1` for each `Q_PROPERTY`. QML already emitted `qml.property_declaration.v1`. Without the alias, `code-kb facts property` fell back to a substring match and `facts properties` returned nothing.
- **How:** TDD in `crates/code-kb-core/tests/disambiguation_test.rs`. The `qt_facts_fixture` gained one QML property row and one Qt C++ property row under `src/layouts/`. Three tests extended: the alias table, the path filter, and the category listing.
- **Impact:** `code-kb facts property --path <dir>` is the single command for both languages. Feeds the K5 README claim.

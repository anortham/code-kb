## K3: a Qt C++ header through the tools

Added `crates/code-kb-core/tests/qt_cpp_test.rs`, eight tests over a Kirigami-shaped `src/layouts/columnview.h`.

- **What:** skeleton rows for every `Q_PROPERTY` and every signal, no parse-error banner, exactly two class rows (no forward declaration), one `ColumnView` definition row, the `Q_PROPERTY(...)` signature on a property row, four `cpp.qt_property.v1` facts with the owning class, and no `handler` row for a signal declaration.
- **Why:** plan 025 Part C item 6 claims Qt C++ headers work through the tools. The tests are the regression net for that claim.
- **How:** No code change was needed. Every row already renders correctly on julie-extract 3.3.0, which the brief allows. Measured the difference directly: julie-extract 3.2.0 on the same header gives 19 parse diagnostics, three `class` rows including two named `KIRIGAMI2_EXPORT`, zero `property` symbols, zero `event` symbols and zero facts; 3.3.0 gives 0 diagnostics, two correct class rows, 4 properties, 2 events and 4 facts.
- **Impact:** The claim is now test-backed. The skeleton does not mark a signal row as a signal; the `event` kind is visible through `lookup` only. Left as is, because the skeleton labels no kind for any language.

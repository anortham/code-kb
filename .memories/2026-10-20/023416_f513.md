## Java holdback truth fix and Java bare-call rule (phase 3, task 2.2)

**WHAT**
- code-kb rule: a bare Java call reaches only the caller's classes, their ancestors, and static imports. Otherwise it is `excluded` with basis "a bare call reaches only the classes of `X` and its static imports" (`java_bare_call_outside_classes` in `reference_report.rs`).
- Two guards were added after the reach gate showed wrong exclusions:
  - The rule applies only to calls (`is_call`). An annotation element `alternate = {…}` is a `variable_ref`, and gson's `SerializedName.alternate`/`value` dev lines were excluded before this guard.
  - The rule skips a call inside an anonymous class. julie hangs anonymous-class methods on the field or method that builds it, so the supertype is unknown.
- Harness: `truth_lines` gets a Java filter, `java_use_filter` in `scripts/edit_replay.py`. A bare call of a Java method counts as truth only through a static import, or through a class chain that reaches the defining class via the project's `extends`/`implements`/anonymous clauses.
- `select holdback --keep FILE` recomputes the truth of existing cases. It keeps the ids, splits, and verdicts.

**WHY**
- 10 dev truth lines of the gson `MoreAsserts.assertEquals` case were bare `assertEquals` calls in `TestCase` subclasses with no static import. Java binds them to JUnit's `TestCase.assertEquals`. The truth was wrong, and the code-kb rule was right.
- Rejected: loosening the code-kb rule to keep those 10 lines. That would bring back 1343 false `likely` outside rows.

- Java dev outside rows 1345 → 2.

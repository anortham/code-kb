## Three corrections after the first julie 3.9.0 replay

- **julie 1f413aa6:** a bare name as the assigned JavaScript value (`app.route = route`, `api.render = render`) writes no property. Replaces c81388f3's same-name-function rule. The binding a bare name refers to already has a definition, and a parameter's value is unknown.
- **C# `#if` rule turned around:** a use is `unresolved` only when its file *always* opens a namespace that another file opens under `#if X`; a file that opens it under `#if X` keeps `likely`, because the build without `X` loses the fallback (the author rewrote exactly those uses). Tests: `a_csharp_use_of_an_if_not_fallback_in_a_file_that_always_opens_the_paired_namespace_is_unresolved`, `a_removed_csharp_fallback_lists_a_use_beside_a_using_under_the_condition`.
- **`code-kb scan` on an old-schema index:** `scan_workspace` treats `schema_migration_required` like `schema_incompatible` (remove, scan a new one). Not in `write_incrementally`: the version guard already rebuilds real old indexes from their metadata, and the fallback deleted a metadata-less test index under load. Test `test_cli_scan_rebuilds_an_index_the_extractor_must_migrate`.

**Gotcha:** a julie rebuild that keeps version 3.9.0 is not caught by the version guard, so stale 3.9.0 indexes (gate cache, replay trees) must be recreated by hand.

**Evidence:** fmt, clippy, 1540 tests; express case lists the 11 Router.route sites again.

## Released code-kb v2.11.1 (GitHub + crates.io)

**WHAT**
- `22da4eb` (PR #74): text answers of `file_skeleton`, `get_symbol_body`, and `get_symbol_context` fit `OUTPUT_BUDGET_CHARS` (32,000 chars, about 8K tokens). Worst real calls were 100K-440K chars.
- `7d89411` (PR #75): three wrong answers from the dogfood round:
  - `check_edit` reported inherited attribute writes (Flask `debug`, `_got_first_request`) as removed fields after any edit that moved their lines. The base scan holds only changed files, so it could not see the base class. New `queries::inherited_write_names` asks the current index by name, with the class as owner.
  - A pending `extends` that names the class's own name (`class EnvironBuilder(werkzeug.test.EnvironBuilder)`) resolved to the class itself, so its own `self.app` was dropped as an inherited write. `inherited_attribute_write` now excludes `c.symbol_id = parent`.
  - Open-end text now says "may call them, or nothing does".
- `0b72661` bump, tag `v2.11.1`, release workflow green, 12 assets, crates core + cli published, binstall and cargo install verified.

**HOW / LEARNED**
- `record-fix` refuses to run until the dogfood report has exactly one `## Result: PASS`; write the triage first, then record.
- One commit for all fixes avoids stale fix records when fixes share a file (queries.rs).
- `pgrep -f "pattern"` in a wait loop matches its own shell; use `pattern[x]` bracket trick.
- The v2.11.0 release review of corpus diffs: changed skeleton/body/context rows were all budget cuts; blast-radius rows were the open-end text only.

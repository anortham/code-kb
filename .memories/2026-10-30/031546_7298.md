## notify 9 merged; reconciles after lost events now 1 s apart

- **WHAT:** Fast-forwarded fix/v2.10.1-followups to ckb/notify-9-fix (60b5d2d: notify =9.0.0-rc.7, debouncer recopied from upstream 7d09a58, Windows RDCW errors/rescans reach code-kb, root-watch check each second, EventKindMask::CORE, macOS recursive root). Then added `MIN_OVERFLOW_RECONCILE_GAP` (1 s) and `next_overflow_reconcile_at` in `crates/code-kb-core/src/watcher.rs`: the next overflow reconcile waits max(1 s, last reconcile duration).
- **WHY:** The adversarial review found that with notify 9 a build writing into an ignored folder (target/) can overflow the 16 KiB ReadDirectoryChangesW buffer again and again; each pathless rescan started a full reconcile back to back, keeping one core busy. notify 8 silently lost these events.
- **HOW:** The worker drains the queue while the gap runs (the pending reconcile covers it). Tests: `a_rescan_soon_after_a_reconcile_still_reconciles_after_the_gap`, `reconciles_after_lost_events_start_at_least_the_gap_apart`.
- **Decision kept:** macOS recursive root watch (notify 9 refuses FSEvents streams with more paths than RLIMIT_NOFILE/12). Not tested on a Mac; macOS CI is the first check.
- **IMPACT:** Full suite 2250/0, clippy, fmt, plugin 20/20 on Linux. Windows full suite passed on 60b5d2d (2206/0); gap change not yet run on Windows.

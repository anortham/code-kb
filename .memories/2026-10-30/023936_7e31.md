## notify 9 access events filled the watcher batch on Linux

- **What:** notify 9 defaults to `EventKindMask::ALL`, which adds inotify `CLOSE_NOWRITE` to `OPEN`. Each file read gave two debounced events, so 26 reads filled the 50-event batch and forced `watch_again` plus a full scan.
- **Evidence:** new test `reading_more_files_than_a_batch_holds_watches_nothing_again` (60 fresh files). With ALL mask, 30 files: the startup reconcile never settled (the scan's own reads refilled the batch, a loop). With a notify-8-like mask (OPEN + CLOSE_WRITE): 30 files pass, 60 files loop (old limit). With `EventKindMask::CORE`: 60 files pass.
- **Fix:** `new_debouncer` in `crates/code-kb-core/src/watcher.rs` passes `Config::default().with_event_kinds(EventKindMask::CORE)`. code-kb ignores every access event anyway. CORE keeps DELETE_SELF/MOVE_SELF, rescan (`EventKind::Other`) events, and Windows flags are fixed in the backend.
- **Also:** xxhash-rust is a notify 9 dependency on every platform (poll backend), not macOS-only. Only the objc2 crates are macOS-only.
- Branch `ckb/notify-9-fix` from `ckb/notify-9` (b36c64b).

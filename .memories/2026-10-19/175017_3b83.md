## Fixed the four wrong answers from the 2.7.0 corpus delta review

The delta review workflow (wf_fee16489-1a5) checked 77 changed corpus outputs. Verifiers confirmed four wrong answers; all four are fixed on `fix/release-tests` with regression tests.

- **zod type use shadowed by a value** (`is_not_named_by` in `reference_report.rs`): a bare TS type use is never named by a variable, constant, parameter, field, property, function, or method. Test `a_typescript_type_use_is_not_shadowed_by_the_value_of_the_same_name`. Test helper `first_definition_report` now skips `import`/`export` rows (julie writes an `export` row on the interface line).
- **Rust `mod git;` cited for a local read** (`reads_a_module`): a Rust `variable_ref` never names a `namespace`/`module`, as a rival (judge loop + `can_reach`) or as the target (`decide_cheap`, basis "`git` is a module, which a read of a value never names"). Two tests `a_rust_*module*`.
- **blast_radius false depth advice**: the walk now goes one level past `max_depth` (up to `MAX_BLAST_DEPTH` = 5); `stopped_at_depth` is set only when a row lies past the depth. Rows past the depth sort last and never count. Three tests in `blast_radius_test.rs`. Cost: aspnetcore `ThrowIfNull` 16.2 s → 17.5 s, inside v2.6.0's own 15.6–17.6 s spread.
- **F# one-line definition name line counted as text only** (`definition_spans`): with the text-scan hits, a head that holds no line with the name keeps the first body line. Test `a_one_line_definition_after_its_attribute_counts_its_name_line_as_a_definition_line`.

Refuted by verifiers (gaps, not wrong): Rust pattern bindings stay `likely` (added to Known gaps), sinatra depth text (covered by the same fix anyway), julie-fixtures rerun hint (harness only).

Verification: fmt, clippy, 1494 nextest tests pass. Docs: CLAUDE.md/AGENTS.md (identical), v2.7.0 notes.

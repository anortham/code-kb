## Fixes from the release corpus review (phase 2)

**WHAT:** Fixed the wrong and lost answers that the corpus-review workflow (wf_ce64a953-2de) found, on `feat/accuracy-phase2`.
- `definition_spans`: Python, Ruby, Lua, F#, VB.NET end the definition span before the first body line; others keep the body-start line (Kotlin annotated fn).
- `import_spans`: an import row named by its full path (`a.b.name`) counts for `name`. A trigram query (`symbol_names_tri MATCH '".name"'`) finds those rows; the plain `substr` suffix scan cost ~20 ms on hermes-agent.
- A function nested in a function (Python, Rust, Kotlin, C#, Swift, Scala, Dart) excludes sites outside its parent.
- Java `member_access` never reaches a method; a group of test labels excludes every site.
- C++ template parameters do not count as a receiver type; shadow checks prefer the nearest definition above the site.
- Identifier pairing stays inside the caller's span; private Java/C#/Kotlin/Scala methods have no overrides.
- `CallingTest.name_only`; `blast_radius` says when the depth stops the walk and falls back to the callers report's tests.

**WHY:** Wrong answers block the 2.7.0 release (fix-round policy).

**HOW / evidence:** nextest 1486/1486, clippy and fmt clean. Reach gate PASS (`~/.cache/code-kb-accuracy/phase2/fix/tri/gate/report.md`), tables equal to slice 4 except Java (90 sites unresolved→excluded, 0 truth lines). lost_proven 0 on 7 repos. MCP latency within noise; hermes ActionRow +6.8 ms (was +25 ms).

**LEARNING:** A `code-kb` binary copied outside the repo with no `julie-extract` next to it finds `~/.local/bin/julie-extract` 3.7.2 on PATH and rewrites indexes with it. The first gate rerun this way shifted 245 labels and looked like a regression. Always copy `.tools/julie-extract` next to a test binary.

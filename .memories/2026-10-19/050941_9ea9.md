## Phase 2 slice 2: reach sections in the callers report

**What:** `find_references` for callers (CLI `refs`) now adds up to six sections after the labeled sites: Overrides, Overrides of, Constructions, Variant uses, Registrations, and Tests that call it (each with a run command, or none when no runner can run it alone). New `crates/code-kb-core/src/reference_report/sections.rs` and `crates/code-kb-core/src/test_commands.rs`; JSON arrays `overrides`, `overridden`, `constructions`, `variant_uses`, `registrations`, `tests`. The full rules are in `docs/reach-sections.md`; CLAUDE.md/AGENTS.md keep a summary.

**Why:** one call should give an agent every site a change must reach (plan `docs/plans/2026-10-18-accuracy-phase2.md`).

**How:** 6 review and fix rounds (wrong answers fixed, gaps documented as limits). Test commands were proved with real vitest, jest, mocha, node, pytest, go, and cargo runs; mvn, gradle, and dotnet only by printed arguments.

**Decision:** the judge SQL keeps the `i.name` index. A unary plus (`+i.name`) from fix round 3 cut gson CLI peak RSS by 4 MB but cost zod `parse` +27% p50 and +20 MB; the live server showed no memory gain.

**Evidence:** 1073 tests, clippy, fmt, plugin tests pass; reach gate report identical to slice 1 (binary `~/.cache/code-kb-accuracy/phase2/code-kb-s2`); `lost_proven_p2.py` empty on 7 repos; live bench p50 within +6% on 10 symbols, RSS within 3 MB.

**Impact:** slice 3 (arity) is next: julie 3.8.0 is committed at 7f604183 in the julie worktree.

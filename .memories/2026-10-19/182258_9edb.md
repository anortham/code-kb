## Stop hook blocks only on proven sites (2.7.0)

**WHAT:** `format_stop_reason` in `formatters.rs` now blocks only on `proven` sites of changes that `blocks_a_stop` accepts. A `likely` site, a `signature changed` row, and a parameter change of a `.js/.jsx/.mjs/.cjs` function never block. `check_edit` still lists every row.

**WHY:** A clean-commit check (`code-kb check --base C^` on recent commits of cobra, gson, flask, zod, express, Newtonsoft.Json, code-kb) found 76 commits with a shape change. The old rule (proven or likely) blocked 18 of them, and none needed an edit. Most came from type-only signature changes and JavaScript parameter counts.

**Two wrong rows fixed in code:**
- `java_static_import` in `reference_report.rs`: a bare Java call is excluded when its file has `import static C.name` and C plus the caller's class chain own no group member (gson `toIntExact`).
- `inherited_group_arity` in `reference_report.rs`, used by `SiteLister::list` in `edit_check.rs`: a Java/C#/Kotlin call is judged against inherited overloads too (Newtonsoft `IsMatch` 2 → 3 with a base 2-arg overload).

**IMPACT:** Under the new rule the old binary blocks 1 of 76 (1.3%), below the 2% mark of the phase 3 plan. The rerun with the new binary checks for 0. Docs updated: CLAUDE.md/AGENTS.md, docs/edit-check.md, README, site, SKILL.md, release notes v2.7.0. Phase 3 task 2.1 is now partly done.

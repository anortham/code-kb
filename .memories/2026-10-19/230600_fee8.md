## Phase 3 replay harness: holdback truth and session rebuild fixes

**WHAT:** Task 1.2 committed (e993a44, holdback set, 219 cases, 92 dev). Task 1.3 session harness fixed; run in progress.

**WHY:** The first holdback and session runs were dominated by harness errors, not check misses.

**HOW (holdback truth rules, scripts/edit_replay.py):**
- JS/TS imports resolve relative sources to the defining file or an ancestor folder/index (zod `deno/lib` mirror is apart from `src`).
- JS/TS function or type statements reach other files only through imports: bare use needs a named import; `recv.name` needs recv bound by a whole-module import or any package import.
- Keys/labels/named args, block comments, Python triple strings, Go raw strings are not truth.
- Parameter renames are no change outside Python and C# (names blanked by `parameter_shape`).
- A head whose generics continue on the next line is neither removed nor changed.
- Parameter-change truth needs a call or member read (no imports, no type uses).
- Caught = any change in the defining file lists the line; a multi-line import line is caught by a row on its first line.
- New miss causes: `import not listed`, `not a call`, `fits the new shape` (count fits new range, no old named arg, or an overload remains). `cut by a limit` only when the name has a kind the check compares.

**HOW (sessions):** blocker only for git state of the session tree or a shell write to a code file of the tree; formatters do not block; `cat > f <<'EOF'` heredocs replay as edits; the tree is the checkout holding most edits (worktree inside cwd or another repo); Claude fail_line is the tool_use line, so the fail text is its tool_result.

## MCP catalog evaluation: keep tools, rewrite boundaries

### WHAT
Evaluated the 11 MCP tools against live `tool_definitions`, `handle_call_tool_inner`, and Miller lessons.

### WHY
Shared `symbol` in names is not the failure. Two pairs overlap in schema and copy.

### HOW
- `find_symbol` and `search_symbols` share the same parameters (`query`, `path`, `kind`, `is_test`, `limit`).
- `find_symbol` description says "semantic lookup" and `query` says "search pattern". Both invite concept search.
- `find_symbol` already falls back to FTS5 when the name LIKE query is empty, so the tools overlap at runtime.
- `get_context_slice_op` calls `get_symbol_body_op` then adds callees, types, and tests. Body is a cheaper subset, not a rival.
- Initialize instructions treat body and slice as equals ("Call get_context_slice or get_symbol_body").

### IMPACT
Do not merge (Miller Trap 3 god-tools, Trap 5 conceptual noise). Rewrite exclusive descriptions and initialize routing before shipping. Optional: find_symbol miss text should name `search_symbols`.

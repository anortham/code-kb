## Implemented Conservative Reference Resolution (Phase 1)

Fixed phantom dependencies where calls to external types with identical terminal names (e.g. `Vec::new()`, `Command::new()`) matched arbitrary workspace symbols (`McpServer::new`, `Workspace::new`).

- **Root cause:** `pending_relationships` joins in `queries.rs` only matched `s_to.name = p.target_terminal_name`, ignoring `target_namespace_json` and `target_receiver`.
- **Approach:** Tightened SQLite queries in `find_callee_signatures`, `find_references_internal` (callers and callees), and `impact_walk` (blast radius CTE) to inspect `target_namespace_json` against parent symbols, `Self`, and module paths. Maintained backward compatibility for test fixtures lacking `target_namespace_json` via `has_pending_namespace_column`.
- **Verification:**
  - Added unit test `test_conservative_pending_resolution_ignores_unmatched_namespace` (confirmed RED then GREEN).
  - Verified live CLI: `code-kb slice find_callee_signatures` no longer outputs `McpServer::new` or `Workspace::new`.
  - Verified `code-kb refs --direction callees find_callee_signatures` no longer outputs phantom `new` / `push`.
  - All 159 tests passing across `code-kb-core` and `code-kb-cli`.

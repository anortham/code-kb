## Task 3: Disclose Result Caps and Truncation in Formatters

- **WHAT**: Added explicit result cap notices in `format_context_slice` and `format_blast_radius`.
- **WHY**: Context slices cap dependencies at 10 and related tests at 5, and blast radius CTE queries cap rows at 200. Previously these caps were silent, giving agents the false impression that result lists were exhaustive.
- **HOW**:
  - In `format_context_slice`, if `callee_signatures.len() >= 10`, append `[Showing 10 dependencies (limit reached)]\n`.
  - In `format_context_slice`, if `related_tests.len() >= 5`, append `[Showing 5 tests (limit reached)]\n`.
  - In `format_blast_radius`, if `total >= 200`, display `### Downstream Impact (200+ symbols - traversal ceiling reached; increase depth/limit or narrow target)\n` instead of `### Downstream Impact (200 symbols)\n`.
  - Added unit tests in `crates/code-kb-core/src/formatters.rs` (`mod tests`).
- **IMPACT**: Agents now receive unambiguous feedback when results are truncated by query caps, preventing misassumptions about dependency or downstream impact completeness.

## Telemetry fixes done in worktree `worktree-telemetry-fixes` (uncommitted)

**WHAT:** All five telemetry findings are fixed in `.claude/worktrees/telemetry-fixes`:
1. `link_impl_owners` (db.rs) links a parentless Rust method that has `impl_type_name` to the nearest type with that name, and leaves it unlinked on a tie. It runs in `ensure_fts_index` and after each incremental update or delete (`write_incrementally` in sync.rs). It uses the partial index `idx_symbols_unlinked_impl`. The skeleton shows a method whose parent is in another file as a root row.
2. `symbol_not_found_parts`: when a wrong file filter hides an exact name, the text is "`path` does not define it; it is defined in: ...".
3. `find_related_tests`: the name LIKE now runs before the test-path predicate. Miller context went from 995 ms to 122 ms (hyperfine), with identical output.
4. Overloads: `name_candidates` was split out of `get_symbol_by_name_internal`. New `get_symbol_overloads`, `get_symbol_bodies_selected_op`, and `get_context_slices_selected_op` (at most 4 overloads for context). MCP and CLI use them. CLI JSON is an array for overloads.
5. A folder as `file_path` narrows the name lookup. The `IsADirectory` error is removed.

**WHY the DB write is safe:** julie's FK is `ON DELETE SET NULL`. julie runs a whole-database `foreign_key_check` on each write, so the UPDATE guards that the owner exists (EXISTS) inside an IMMEDIATE transaction.

**Verification:** 609/609 workspace tests pass, clippy and fmt are clean. On live index copies: julie has 210 of 219 methods linked (the other 9 belong to external types), the callers of apply_store_changes match rg, the overloads of DashboardIndexFactsCache.Read are returned, and the wrong-file hint names the correct file.

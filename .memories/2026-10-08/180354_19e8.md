## Telemetry review (7d to 2026-10-08): four fixable code-kb defects found, none fixed yet

**WHAT:** The user asked for last week's telemetry, then asked why `DashboardIndexFactsCache.Read` keeps failing and what else to fix. Errors: 239 of 2712 calls (144 symbol not found, 60 ambiguous, 31 file not found).

**Findings (all reproduced live with code-kb 2.5.2):**
1. **Rust methods in an `impl` block in another file lose their owner.** julie (extractor) sets `parent_symbol_id` NULL but writes `metadata_json` `{"impl_type_name":"QueueRuntime","impl_parent_id_resolved":false}`. In ~/source/julie, 219 of 1593 Rust methods have this. Effects: `QueueRuntime.apply_store_changes` is not found (12 telemetry errors), `lookup QueueRuntime.` misses the methods, the skeleton shows no owner, and **`find_references apply_store_changes` / `process_queue_batch` return 0 callers, but each has real `self.` callers (wrong answer)**. Fix in code-kb: read `impl_type_name` where code uses the parent (`get_symbol_by_name_internal` in queries.rs, `ancestor_names`, `qualify_members`, `owner_members`, self-call receiver matching).
2. **A wrong `file_path` gives "No similar name is indexed"**, but the name exists in another file (`code-kb context stop_file_watching -f src/handler.rs` in julie). `suggest_symbol_names` scopes suggestions to the path filter. Fix: retry without the filter and name the real file.
3. **`get_symbol_context` is slow in miller (C#, 253k symbols)**: average 1.3 s, 96 calls over 2 s. Cause: the name stage in `find_related_tests` runs `test_path_predicate` (rtrim/replace per row) before the cheap name/signature LIKE. Putting the LIKE first takes the query from 802 ms to 49 ms (python repro in the session scratchpad).
4. **Ambiguous errors**: 29 of 60 are true overloads (same owner, same file, mostly C#). `DashboardIndexFactsCache.Read` has a public wrapper (line 39) and an internal overload (line 42). Product question: should body/context return all the overloads?

**Correction:** My first reply said `DashboardIndexFactsCache.Read` failed 17 times. That was wrong: my GROUP BY on the first 40 characters of the error merged different symbols. The real count is 6 (1 `.Read` + 5 `::Read`).

**IMPACT:** Finding 1 makes callers, blast radius, and related tests silently wrong for split Rust impls.

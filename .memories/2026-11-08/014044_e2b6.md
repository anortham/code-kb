## Stop hook false "removed" rows on Razor files

The Stop hook on another machine said `LoadAsync`, `DescribedBy`, and `Invalid` of ceres `ThemeDesigner.razor` were removed while the build passed.

- **Root cause:** julie 3.12.0 (tree-sitter-razor fba8571) parses a Razor file with a `@* … *@` comment inside an `@if`, `else`, or `@foreach` block as one `error` from line 1 to the end; the file keeps ~10 of 302 symbols. The grammar's `_razor_comment_text: repeat1(/.|\n|\r/)` never stops before `*@`. Filed julie-extractors #29.
- **Repro:** scratch clone of ceres, `code-kb check --base 7b9bad2^` at commit 7b9bad2 (branch fix/content-safety): 67 fields and 15 methods of `ThemeDesigner` reported removed.
- **Fix (code-kb, uncommitted on main):** `ParseErrors` in `edit_check.rs` reads the working file's `parse_diagnostics` error rows; a missing base symbol, field, or variant whose name still stands inside such a span is left out and counted in `Cut: Not compared: N symbols of `path` …`. 3 new tests in `edit_check_test.rs`; docs/edit-check.md, CLAUDE.md, AGENTS.md updated.
- **Verified:** edit_check_* (67+18+34+216), edit_hook_test (46), lib edit_check unit tests, clippy workspace, fmt check all pass; the ceres replay now prints the cut instead of the removed rows.

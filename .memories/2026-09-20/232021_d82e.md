## Reconcile no longer re-extracts unsupported files on every start (uncommitted on main)

**WHAT:** `crates/code-kb-core/src/sync.rs`: `reconcile_offline_edits` records files that have no `files` row after an update in a new `skipped_files` table (path, content_bytes, mtime_ns) in `artifact.db`, and skips them on later walks until size or mtime change. `.miller` added to `is_hard_excluded` beside `.julie`. Regression test `test_reconcile_offline_edits_remembers_files_the_extractor_skips` in freshness_test.rs; exclusion test in workspace.rs.

**WHY / root cause:** `julie-extract scan` records unsupported files (Cargo.lock) in `files`, but `julie-extract update` on the same file reports `unsupported_file` and deletes the row. After the first edit to such a file, every reconcile saw it as added, spawned the extractor (about 8 ms), and the row never came back. Benchmark tool state (`.julieignore`, four `.miller/` files) made this visible: 65 ms per search instead of 24.

**IMPACT:** Warm `code-kb search` on the code-kb checkout 24.2 ms -> 17.6 ms (hyperfine, 20 runs). Second command after a start logs no reconcile changes. Affected tests, clippy -D warnings, fmt all green.

**Follow-up for julie-extract:** make `update` and `scan` agree on unsupported files (keep or write the `files` row) so code-kb's table becomes unnecessary.

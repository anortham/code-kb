## Issue reporting: extended `bug-report` plus `/report-issue` skill

### WHAT
- `code-kb bug-report` gained `--description` (inserted into the body), `--logs N` (default 40, 0 disables), and index facts. The bundle now reports extractor version, schema, index level, updated_at, file and symbol counts from `.code-kb/artifact.db`, the last 10 telemetry errors, and the tail of the newest `.code-kb/logs/code-kb.log.*` file, with home paths masked as `~`.
- `generate_bug_report(conn, root, title, description, log_lines)` in `crates/code-kb-core/src/telemetry.rs`; new `IndexFacts` struct exported from the core crate.
- Log path helpers moved to core: `workspace::log_dir` and `workspace::latest_log_file`. The CLI `logs` command and `logging::get_log_dir` reuse them.
- New skill `skills/report-issue/SKILL.md` (mirrored in `.claude-plugin/skills/`): one question to the user, `bug-report --json`, privacy check, then `gh issue create --body-file` or the pre-filled URL fallback.
- New `.github/ISSUE_TEMPLATE/bug_report.md` that tells users to run `code-kb bug-report`.
- README and the code-kb skill doc line updated.

### WHY
The user asked what helps a user submit an issue. `bug-report` existed but lacked logs, index state, a description slot, and a `gh` submission path. No issue template or skill existed.

### HOW
- The pre-filled GitHub URL omits the log tail because browsers and GitHub truncate long query strings; `markdown_body` carries it and the skill writes it to a body file for `gh`.
- Each log line runs through `sanitize_error_message`, so home directories are masked.
- Test `test_bug_report_includes_index_facts_description_and_masked_log_tail` builds a temp workspace with a small artifact.db and a log file.

### IMPACT
- Full checks pass: cargo test workspace (all targets green), clippy `-D warnings`, fmt, 16 plugin tests, preflight sync check. Dry run against this repo: 40 log lines, 115 files, no home-path leak.

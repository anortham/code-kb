## Operational release audit and repair

### WHAT

- Corrected the site test example in `docs/site/index.html` so the two Cargo test filters run as separate commands.
- Added a `verify-release` job to `.github/workflows/release-binaries.yml`. All binary builds now wait for it.
- The gate verifies the tag or dispatch version against Cargo, both plugin manifests, the marketplace entry, and the root plugin. It resolves an annotated tag to its commit and requires that exact commit's `ci.yml` run to be `completed/success` before release assets can be published.
- Documented that automated gate in `docs/RELEASING.md`.

### WHY

The release workflow previously published after package builds alone. The documented local preflight could be skipped, so an arbitrary tag or dispatch version could publish untested assets or assets whose version did not match the plugin launcher.

### HOW

- Reused the existing cross-platform CI evidence through `gh run list`; added `actions: read` and `GH_TOKEN` rather than duplicating a Linux-only test suite.
- Kept the change scoped to release safety and a broken documentation command.

### IMPACT

A release now fails before any asset publication unless its metadata is internally consistent and the exact release commit already passed CI on the existing matrix.

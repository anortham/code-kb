## WHAT
Completed a bounded live performance measurement and wrote `/tmp/code-kb-health-performance.md`.

## WHY
The health audit needed evidence for the documented retained-memory and warm-query claims, plus an assessment of the benchmark harness.

## HOW
Measured four persistent direct MCP server lifecycles and four launcher lifecycles on the already-indexed code-kb workspace. The installed/release binary is v1.1.1 while the source manifest is v1.1.3. Direct server PSS was 12.0–12.1 MiB (RSS 18.4–18.5 MiB); warm lookup empirical p95 was 2.41 ms. The Node launcher retained ~49.9 MiB PSS alongside the 12.0 MiB Rust child, about 61.9 MiB process-tree PSS. Did not scan/rebuild the shared index; no extractor child was observed. Ran `scripts/benchmark_quality.py --iterations 3` and inspected its measurement behavior.

## IMPACT
Direct Rust server satisfies a PSS interpretation of <15 MiB but not RSS. Plugin/GUI launcher deployments exceed the budget materially. The benchmark’s reported warm/peak values are fresh CLI process metrics, lacking p95 and persistent-server/process-tree coverage. Prioritize launcher architecture only after a safe cross-platform design; add an opt-in disposable-index reconciliation benchmark before tuning.

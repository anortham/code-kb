### WHAT
- Probed and addressed Area 2 (Launcher memory reduction) from `docs/2026-09-20-health-review.md`.
- Updated `bin/code-kb-launcher.cjs` to use opportunistic `process.execve` on supported POSIX Node runtimes (Node 22+) when running as the main entry point (`require.main === module`).
- Gracefully falls back to `childProcess.spawn` on platforms without `process.execve` (Windows, Node 18/20).
- Passed all 16 plugin tests in `node --test tests/plugin/*.test.cjs`.

### WHY
- The health review identified that the Node parent process added ~50 MiB RSS to the process tree, keeping an idle Node runtime alive for the entire MCP session.

### HOW
- Evaluated Node's `process.execve`: on Node 22+ (Linux/macOS), calling `process.execve(binaryPath, [binaryPath, ...args], process.env)` atomically replaces the Node process image with the compiled `code-kb` binary.
- This preserves the process PID, inherited stdio pipes, and harness process monitoring while discarding the entire Node runtime and V8 heap.
- Guarded with `require.main === module` so imported library usage (such as test runners) is never replaced in-process.
- Guarded with `typeof process.execve === 'function'` with try/catch fallback to standard `childProcess.spawn` for Windows and Node 18/20.

### IMPACT
- Measured before: 77.61 MiB total process-tree RSS (53.70 MiB Node + 23.91 MiB Rust).
- Measured after: 30.48 MiB total process-tree RSS (0 MiB Node + 30.48 MiB Rust).
- Eliminates 47.13 MiB (~61%) of memory overhead on modern Node/POSIX environments with zero regression on Windows and Node 18/20.
- Unblocks Area 3: Persistent-MCP & large-corpus benchmark.

## Plan 020 task 5, fix round 1: rarity-weighted coverage inside the candidate set

Branch `feat/search-v1.2-recall-rerank` (worktree `.worktrees/feat-search-v1.2`), on top of b757458.

- **WHAT:** `rerank()` now runs two passes: per-candidate per-word hit booleans (name, signature, capped doc), then `idf_w = ln(1 + N / (df_w + 1))` from the admitted set, then scores. Partial name, signature, and doc coverage are idf-weighted fractions; tiers stay binary. New `W_NAME_ANY = 5.0` floors the partial tier so any name hit beats a zero-coverage definition's kind prior for queries of any length. `trigram_name_terms` also emits the `split_identifier` parts of each word (`collapse_name` -> `collapse_name`, `collapse`, `name`), so the name branch reaches `CollapseName`. Trigram-only snippets bracket the longest matching term. `SearchExplain.word_weights` carries the words with their idf; the text header prints them once (`rerank: N candidates in X µs; words ...`).
- **WHY:** reviewer findings 1-4 on b757458: binary coverage lost BM25's term-rarity signal (4 regression-set cases worse than v1.1.4), long queries could let the kind prior beat a name hit, snake_case queries could not reach PascalCase names, and bracketing picked the first term.
- **HOW:** tuned on the development set only: `W_DOC` 10 -> 18 (plateau 17-20 at 68/89 file@1, 60/89 sym@1; 10 gave 67/58, 26 gave 66/58); `W_SIGNATURE` stays 4, `W_NAME_PARTIAL` 30. `-0.0` from `Iterator::sum` on empty float iterators replaced by explicit folds so explain lines never print `-0.00`.
- **IMPACT:** development set 68/60 (was 69/60 before the fix round; v1.1.4 55/42). Regression set 25/26 file@1, 21/26 sym@1 (v1.1.4 22/17); two cases still worse: `concept-fts` (file 1 -> 2; `create_index` doc gets stem credit for "stemming" because "system" contains "stem") and `concept-telemetry` (sym 1 -> 2; whole-name struct wins, lead ruled no change). Rerank timer 0.44 ms at 177 candidates; warm search medians 24.9 / 23.4 ms.

Open for the lead: substring containment of short stems in doc/signature text (`stem` in `system`, `sha` in `shape`) is the remaining false-credit source; a word-boundary match would need a plan decision.

## Plan 020 task 5: deterministic rerank with explain output

Branch `feat/search-v1.2-recall-rerank` (worktree `.worktrees/feat-search-v1.2`), on top of 6997b20.

- **WHAT:** `rerank()` in `queries.rs` scores every admitted `Candidate` from one const weight table (name tiers whole/all/partial from token-run, substring, and Porter-stem coverage; signature and doc coverage; kind prior; path role; documentation row; test intent). `fts_search_symbols_explained(..., explain)` is the shared code path; `fts_search_symbols_scoped` is its `explain = false` wrapper. `SearchExplain` lives in `models.rs`; `SymbolSearchResult.explain` is skipped in JSON when `None`. `score` is now the rerank score for every caller. CLI `code-kb search --explain` prints `rerank: N candidates in X µs` plus one `explain:` line per result; JSON carries `explain`. MCP `search_symbols` has no explain parameter; its description, the routing block (both copies), the skill file (both copies), README, CLAUDE.md/AGENTS.md say the same thing.
- **WHY:** plan 020 design 4 (precision after the trigram recall of tasks 3-4) and design 5 (explainability, score semantics).
- **HOW:** `rust-stemmers` 1.2 (English) for stems; weights tuned on `~/.code-kb/search-eval/development.json` only: `W_SIGNATURE` 8 -> 4, `W_DOC` 6 -> 10 (68/89 -> 69/89 file@1, 58 -> 60 sym@1), `W_DOCUMENTATION_ROW` -100 -> -200 so documentation rows are a strict last tier (max positive sum is 123). Corpus gate 12/12 with the five `#[ignore]` attributes removed.
- **IMPACT:** development set v1.1.4 -> now: file@1 55 -> 69, sym@1 42 -> 60 (code-kb 20 -> 21, hermes-agent 11 -> 14, julie 14 -> 18, miller 10 -> 16). Regression set report-only: 22 -> 24 file@1, 17 -> 20 sym@1, but 4 cases rank worse (concept-fts, concept-telemetry, concept-discover, concept-normalize) because binary coverage fractions lose BM25's term-rarity weighting; task 6 / lead decision. Rerank timer ~0.5 ms at 177 candidates; warm search median 24.4 ms (v1.1.4 binary 21.9 ms mean).

Open findings for the lead: 7 development cases lose file@1 to a whole-name variable/enum member/namespace (`sha256`, `slice`, `croniter`, `stt enabled`, `shim`, `glob`, `prune`) by the plan's "exact names win" rule; 5 cases are admission gaps (snake_case query vs PascalCase name: trigram terms are whole query words; OR-of-common-words name cap of 20).

### WHAT
- Added phase-separated latency metrics (`reconcile_ms` and `query_ms`) and version-aware filtering to `code-kb` telemetry.
- Updated `crates/code-kb-core/src/telemetry.rs` with `reconcile_ms` and `query_ms` DB columns, migrations, nearest-rank percentile calculations (`p50_ms`, `p95_ms`), and phase averages (`avg_reconcile_ms`, `avg_query_ms`).
- Added `version` and `all_versions` filters in `code-kb-cli` CLI (`stats`/`telemetry`) and MCP (`telemetry_summary`). Defaulting to current binary version (`env!("CARGO_PKG_VERSION")`), with `--all-versions` or `all_versions: true` to query legacy data.
- Added migration in `init_telemetry_db` supporting legacy `version` -> `code_kb_version` column renaming.
- Passed full test suite, clippy `-D warnings`, `cargo fmt`, and node plugin tests.

### WHY
- Addresses Area 1 from `docs/2026-09-20-health-review.md`: distinguish server/indexer startup time (reconcile) from query runtime, and isolate metrics by binary version while preserving 12 legacy versions in telemetry.db.

### HOW
- Stored `reconcile_ms` and `query_ms` as `INTEGER DEFAULT NULL` in `tool_telemetry`.
- Measured startup reconciliation join duration in `McpServer::handle_call_tool_inner` and recorded phase timings alongside overall `duration_ms`.
- Computed nearest-rank percentiles in Rust to avoid SQLite percentile extension dependencies.

### IMPACT
- Accurate measurement of tool query execution vs cold start/reconciliation. Telemetry reports now cleanly reflect the current version's performance without historical skew. Unblocks Area 2 (launcher memory reduction probe).

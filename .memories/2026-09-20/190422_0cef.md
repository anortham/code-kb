## Plan 020 task 3: transactional FTS migration plus the trigram name table

Worktree `.worktrees/feat-search-v1.2`, branch `feat/search-v1.2-recall-rerank`.

- **What:** `ensure_fts_index` now creates a second FTS5 table `symbol_names_tri` (trigram tokenizer, `name` column only, external content on `symbols`). The `symbols_ai`/`symbols_ad`/`symbols_au` triggers mirror every `symbols_fts` statement for the new table. DDL, `'delete-all'` for both tables, the local-excluding population of both, and the `fts_rule` marker run in one `unchecked_transaction`; the marker is written last. Marker bumped to `exclude-locals-v1+names-trigram-v1`. Readiness requires marker match plus both tables present plus both `_docsize` tables populated when `symbols` has rows.
- **Why:** design 1 needs substring name recall (`sha256` finds `parseSha256Sidecar`); design 2 needs a migration that cannot leave a half-built index and a failure that is visible instead of silently ignored.

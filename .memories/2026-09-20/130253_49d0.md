### WHAT
- Implemented Area 3 (Persistent-MCP & large-corpus benchmark) from `docs/2026-09-20-health-review.md` in `scripts/benchmark_quality.py`.
- Added `PersistentMcpClient` managing persistent stdio JSON-RPC sessions with `code-kb serve`.
- Added `measure_persistent_mcp`: benchmarks `initialize` handshake latency, live retained memory (`rss_mb`, `pss_mb`, `anon_mb` from `/proc/<pid>/smaps_rollup`), persistent tool round-trip latencies (`codebase_outline`, `file_skeleton`, `lookup_symbol`, `search_symbols`, `get_symbol_body`, `get_symbol_context`, `find_references`, `blast_radius`, `telemetry_summary`), and changed-file reconciliation latency via live file injection/extraction.
- Added `measure_large_corpus`: opt-in synthetic large repository generator (`--large-corpus [N]`) measuring `code-kb scan` time, peak memory, `artifact.db` size, and large-corpus query latencies.
- Added CLI selection flags `--skip-cli`, `--skip-mcp`, `--large-corpus N_FILES`.

### WHY
- Health review noted: "The existing benchmark creates a fresh CLI process for each sample. Its cache-warm CLI timings and exited-process peak RSS cannot prove persistent MCP latency, retained memory, launcher process-tree memory, or large-repository performance."

### HOW
- Structured persistent MCP benchmark using standard stdio JSON-RPC without third-party dependencies.
- Read live memory stats from `/proc/<pid>/smaps_rollup` before, during, and after workload.
- Tested and verified with both debug and release builds, including changed-file reconciliation roundtrip (~6.5 ms).

### IMPACT
- Persistent MCP latency and retained memory are now repeatably measured and reported alongside CLI metrics.
- Unblocks Area 4 (Answer-quality & reference resolution test corpus).

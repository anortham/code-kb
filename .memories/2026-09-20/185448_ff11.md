## Plan 020 task 2: synthetic corpus gate for search

**WHAT:** New integration test `crates/code-kb-core/tests/search_corpus_test.rs` (12 tests). Fixture files in Rust, TypeScript, Python, C#, Go, and Markdown are scanned by the real julie-extract into a temp db; the query strings live only in the test binary, so they cannot be indexed (the plan 019 self-contamination).

**WHY:** Plan 020 design 6 asks for an in-repo regression gate before the trigram table and the rerank land. It is red today for: substring in name (`sha256`), digit runs (`sha 256`), the kind rule (`scan` -> Go function over the Rust enum member), the path rule (`verify checksum` -> `src/` over `scripts/`), and admission past the 160-row word cap.

**HOW:** Those five tests carry `#[ignore = "red until plan 020 task 5 lands the rerank"]` so each commit on the branch keeps `cargo test --workspace` green; task 5 removes the attribute. Seven groups pass already (exact, camel/snake, short tokens, Unicode, stems, concept over enum variant, minority language).

**IMPACT:** Tasks 3-5 have a fixed target. Observation for task 4: the admission distractors `sidecar_helper_NNN` also trigram-match `sidecar` with the same name length as the target, so the name branch must rank by matched words (bm25 on the OR query), not by name length alone — already ruled in the task 4 brief.

## WHAT
Updated `scripts/benchmark_quality.py` labels and JSON fields so the harness reports what it actually measures.

## WHY
The health audit established that the script launches a new CLI process per iteration, so prior “warm” and peak-RSS language could be mistaken for persistent MCP server or plugin process-tree measurements.

## HOW
Added the actual `binary --version` output to console and JSON metadata; added each first invocation `cold_ms` to every result and displayed it; renamed median/RSS labels to fresh CLI invocation with warmed filesystem cache and peak exited-process RSS; added an explicit scope disclaimer. No measurement algorithm or workload changed. Updated `/tmp/code-kb-health-performance.md` to reproduce all four launcher samples and to state PSS/RSS without declaring either the contract metric.

## IMPACT
A stale release binary now identifies itself in reports, and benchmark consumers cannot reasonably interpret fresh CLI measurements as retained MCP/process-tree evidence. Verified with `python3 -m py_compile`, a 3-iteration harness run, JSON assertions, and `git diff --check`. Removed the generated `scripts/__pycache__` via trash.

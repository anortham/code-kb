## CI broke after e78d69e: `ensure_index_dir` wrote `*` into workspace roots

**WHAT:** The self-ignoring `.gitignore` helper now writes the file only when the index directory is named `.code-kb`. Regression test `ensure_index_dir_leaves_non_code_kb_directories_alone` covers it.

**WHY:** CI failed on all three platforms in `adversarial_m2_test.rs` with `SymbolNotFound` right after the scan. Those tests place `test.db` at the workspace root, so the helper wrote `<root>/.gitignore` with `*`, and the extractor honoured it and indexed nothing. The same would hit any custom database path outside `.code-kb`.

**HOW:** Read the failed-job log, reproduced with `cargo test -p code-kb-core --test adversarial_m2_test` (7 failed), guarded on the directory name, reran the ids (10 passed), then `cargo test --workspace` once (all 19 suites green), clippy and fmt clean.

**IMPACT:** The local verification for e78d69e ran only the affected scope and missed tests that use a root-level database path. Lesson: when a change touches every index creation, the affected scope is every test that scans a workspace, which is most of the suite.

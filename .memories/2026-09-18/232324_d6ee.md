## Task 7: nested targets match by ancestor namespace and identifier receiver

**WHAT**
- `pending_target_predicate` (queries.rs): the `NOT EXISTS` namespace check now also accepts a namespace value that equals the name of any ancestor of the target symbol (recursive CTE over `parent_symbol_id`, depth guard 32).
- Identifier fallback in `find_references_internal`: a `member_access`/`type_usage` row is dropped when its `metadata_json.receiver` names a container that owns a different symbol with the same name as the target. Rows without receiver metadata still match by name.
- Three tests in `crates/code-kb-core/tests/references_test.rs`: C# nested static class across files (outer class in `Defs.cs`), Scala nested object in `Defs.scala`, and the C# constant/method name collision repro.

**WHY**
- julie 3.1.1 records `Outer.Inner.chain()` as terminal `chain`, receiver `Inner`, namespace `["Outer"]`. code-kb 1.1.0 rejected `Outer` unless it was a segment of the target's file path, so nested targets in a differently named file returned 0 callers.
- The identifier fallback matched by name only, so the string constant's usage leaked into the callers of the same-named method.

**HOW**
- Verified `WITH RECURSIVE` inside the predicate subquery with `sqlite3` on a scanned temp repo before wiring it in.
- The plan's literal rule "receiver differs from the parent name" broke the existing Rust field test (`existing.path` has receiver `existing`, a variable). Narrowed the rule to "receiver owns a same-named member elsewhere", which keeps variable receivers and still separates the C# collision.

**IMPACT**
- `cargo test -p code-kb-core` (179) and `cargo test -p code-kb-cli` pass with the new extractor; repro `code-kb refs AnnualAttestationNotification` lists three `calls` rows and no `member_access` row.
- Both new checks stay on `symbols(name, kind)`, `symbols(parent_symbol_id)`, and `identifiers(name, kind)`; no schema change.

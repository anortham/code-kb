## `.code-kb/` now ignores itself in git

**WHAT:** `ensure_index_dir` in `crates/code-kb-core/src/sync.rs` creates the index directory and writes `.code-kb/.gitignore` containing `*` when that file is absent. Both directory-creation sites (`scan_workspace`, `copy_parent_index`) route through it. `CLAUDE.md` and `AGENTS.md` note this under "Self-cleaning workspaces".

**WHY:** Users had to add `.code-kb/` to every project `.gitignore` by hand or see the index in `git status`.

**HOW:** Chose the nested self-ignoring `.gitignore` (the Cargo `target/`, `.pytest_cache`, `.terraform` pattern) over editing the project `.gitignore`. No user-tracked file changes, no git detection, works in nested repos and worktrees, and `git worktree remove` deletes it with the directory. The walker already hard-excludes `.code-kb` so indexing is unchanged. An existing `.gitignore` in the directory is left untouched.

**IMPACT:** Fresh indexes in any git repo no longer dirty `git status`. Existing indexes get the file on the next rebuild only; users with an older index keep whatever they had.

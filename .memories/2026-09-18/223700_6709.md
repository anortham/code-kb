## Diagnosed user report: find_references missed 7 C# callers of a method (2026-09-18)

**WHAT:** A user report (`~/Downloads/2026-09-18-Claude-explanation-core-kb.md`) said `find_references("AnnualAttestationNotification")` returned 1 caller when the method had 7 call sites. The user's own diagnosis blamed a simple-name collision. Reproduced locally with a 5-file C# repro under the session scratchpad; code-kb 1.1.0 + julie-extract 3.1.0 give the same 1-hit answer.

**Root cause (two defects, both needed to produce the wrong answer):**

1. **julie-extractors C# (`crates/julie-extractors/src/csharp/relationships.rs`, `unresolved_call_target_at_depth`)**: for a chained call `A.B.C(...)` the tree is `member_access_expression(expression: member_access_expression(A.B), name: C)`. The function collects only direct `identifier` children, finds one (`C`), and falls back to `UnresolvedTarget::simple`. So the pending relationship carries no receiver and no namespace. Two-part `X.Y(...)` works (receiver = X). Every nested-static-class call in C# loses its receiver.

2. **code-kb (`find_references_internal`)**: target selection picked the method correctly (kind filter drops the constant). But `pending_target_predicate` rejects a pending row with empty namespace and empty receiver unless the caller shares the target's parent, so all 3 (7 in the real repo) pending calls were dropped. Then the identifiers fallback matches `member_access` rows by name only, ignoring the chosen target and the identifier's own `metadata_json` receiver (`{"receiver":"EmailSettingNames"}`), so the string constant's usage at line 18 was reported as the method's caller. Callees of `Build` miss the call for the same predicate reason.

**Not the cause:** the name collision only explains the one wrong hit. With a unique name the method would still have had zero callers returned. Nesting and project boundaries are incidental.

**IMPACT:** any C# call through a nested static class (`Outer.Inner.Method()`) is invisible to callers, callees, blast_radius and test prediction. Fix belongs first in julie (flatten the member-access chain into namespace + receiver), then in code-kb (filter identifier fallback by receiver when the target is nested).

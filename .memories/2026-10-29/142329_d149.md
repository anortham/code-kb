## Released code-kb v2.10.1 and razorback v0.48.7

**What:** A doc-alignment audit for the 7-tool MCP surface, plus a live test of automatic index management, led to:
- code-kb v2.10.1 (tag on dd5cf59; GitHub Release with 12 assets; code-kb-core and code-kb-cli on crates.io; clean plugin install and binstall verified).
- razorback v0.48.7 (tag on f2285f1; GitHub Release).

**Why:** After the tool count dropped to seven, the docs, the skills, the site, and razorback still named old behavior, such as "tool-driven updates", a manual `code-kb scan` step, and julie 3.6.2 on the site. code-kb never had an MCP tool that manages the index; indexing has always been automatic.

**How:**
- Live index test, 10 groups of checks: one defect. The server retried a failed rebuild of an unreadable index on every call. Fixed with `failed_rebuilds` in server.rs and a regression test.
- The scan remedy now names the running binary, because a plugin install does not put `code-kb` on PATH.
- Dogfood round 20261029T120020Z found two old wrong answers (2.10.0 gave them too), fixed in dd3d8de:
  - A class defined inside a function counted as another definition of sites outside it (Flask `flask.Flask` annotations). The local-type rule now covers Python, Rust, Kotlin, Swift, Scala, Java, C++, C, Go, and Zig.
  - A Zig `@import("widget.zig")` receiver was excluded as an outside import.
- Release checks: reach gate PASS at dd3d8de; corpus check against v2.10.0 PASS with zero changed output; preflight 11/11.

**Impact / lessons:**
- The /tmp per-user quota (13.1 GB) filled up mid-release. With the user's approval, the 2026-10-27 leftover folders of other sessions were deleted. Run heavy jobs with TMPDIR=~/.cache/julie-tmp.
- Intermittent CI tests: `watcher_recovers_a_large_file_event_storm` on windows-11-arm, which failed on 2 main pushes and passed on rerun, and `test_mcp_offline_update_and_delete_failures_return_errors_and_retry` on macOS. Neither was changed by this release. Both need a fix.
- `gh run list --commit` needs the full SHA.
- A pkill pattern that matches its own shell kills the command (exit 144).

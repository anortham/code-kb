## Corpus check found lost related types in get_symbol_context

The v2.10.0 corpus check (v2.9.1 vs candidate) showed `get_symbol_context` dropping related types in Rust, Python, C, C++, C#, and Razor.

- **Root cause:** commit 2033f69 made related types bind only through lexical scope, JS relative imports, Java/Go packages, and same-namespace C#. Rust `use`, Python imports, C includes, and C# `using` lines bound nothing.
- **Fix:** new module `crates/code-kb-core/src/queries/import_scope.rs` (`ScopeReader`) turns imports into `[path, name]` files (Python relative/absolute + re-export follow, Rust use trees with crate/self/super/crate-name, C/C++ include closure, angle includes by suffix only) and `[namespace, rank]` pairs (C# enclosing namespaces rank 0.., usings and global usings rank 1000, Razor `@using` + `_Imports.razor`).
- `type_fact_owner_id_in_scope_sql(.., scope: Option<..>)`: the scope branches are emitted only for related types. The shared receiver-chain SQL keeps its old shape (an always-present empty branch cost +45 ms per context call on Newtonsoft).
- C `extern "C"` blocks are namespace parents; C# partial parts in one namespace count as one owner.
- **Evidence:** jq jv, flask AppContext, code-kb Symbol, Newtonsoft JsonTextReader, radzen LoadDataArgs, miller types restored; nlohmann position_string now names the real header instead of the tests/abi copy. 2,017 tests pass.

## Released code-kb 2.10.0 (GitHub + crates.io)

- **WHAT:** Tag `v2.10.0` on `4b84b73`; GitHub Release with 6 archives; `code-kb-core` and `code-kb-cli` 2.10.0 on crates.io. `cargo install` and `cargo binstall` both run 2.10.0; the clean plugin launcher check passes.
- **WHY:** The release-readiness review found 21 defects; the dogfood round and the corpus check found 6 more (rebuild window, removed-field reads, paging, folder lambdas, related types through imports). All are fixed with regression tests.
- **HOW (release mechanics learned):**
  - `main` is protected: required checks must pass on the exact pushed commit, and CI runs only on PRs and `main` pushes.
  - Preflight step 8 needs the commit before the bump on `origin/main`. So: open a PR whose head is that commit (PR #64), wait for CI, push it to `main`, wait for the push run (preflight reads the latest run), run preflight, then `git push --atomic origin <bump>:main vX.Y.Z` (the bump has CI from its own PR, #63).
  - `/tmp` has a per-user quota (about 13 GB) that other sessions' folders in `/tmp` nearly fill; run `cargo install` checks with `TMPDIR=~/.cache/julie-tmp`.
- **IMPACT:** Gates at release: CI green on all 6 jobs, reach gate PASS, corpus check PASS vs v2.9.1, dogfood PASS with no open defect. Gaps kept: D2, D3, Codex G, D4/F, D5/E, D8, Codex D (see docs/reviews/2026-10-28-v2.10.0-dogfood.md).

## Honest likely labels and a JS/TS module resolver for the callers report

**What:** Two Sonnet implementations, merged on `feat/js-ts-recall`:
- Labels (`reference_report.rs`): per-row *rivals* (other definitions the row can reach) replace k. A call in Go/Java/Rust cannot reach a field/variable (Go func-typed ones stay); a JS member access cannot reach a free (not exported, not on an object) function. The `nearest of N definitions` likely label is deleted (0/393 true on dev). Chain continuation lines (`    .readonly()`) have a hidden receiver. JS heuristic: receiver named for the object a function is assigned on (`res.redirect = function`) -> likely.
- Modules (`js_modules.rs`): resolves JS/TS import specifiers (relative, workspace package.json exports with source conditions, export *, export * as ns, aliased and default exports) to prove or exclude a site.

**Why:** Dev diagnosis (`~/.cache/code-kb-accuracy/js-ts/diag/`) showed likely labels wrong on 454/1059 sites and zod/express/cobra recall losses.

**Evidence (gate, each branch alone vs 6de37ae):** labels: recall 0.803 -> 0.872 (go dev 0.806 -> 1.000, js dev 0.441 -> 1.000); modules: ts dev 0.555 -> 0.881; proven precision 1.000 everywhere; lost_proven empty.

**Open (reviewers, verified with fixtures):** shorthand `{ render }` exposes a 'free' function; .d.ts beats .js; non-workspace bare specifier wrongly External (aliases); trailing-dot chains; Java record components; Go `var Hook func()`; Rust fn-typed statics; candidate branch and time-limit path still count k; import_segment `supertest` bug.

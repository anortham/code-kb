## v1.1.3: ancestor ~/.code-kb hijacked workspace root on Windows; CI gate added

### WHAT
- `Workspace::find_workspace_root` pass 1 now requires `.code-kb/artifact.db`, not a bare `.code-kb` dir. Two regression tests in `workspace.rs`.
- `scripts/release-preflight.sh` step 8: HEAD must be clean, on origin/main, and have a `completed/success` CI run (`gh run list --commit`). `docs/RELEASING.md` step 3.5 documents push → wait CI → preflight → tag.
- Released v1.1.3 (GitHub + crates.io) after green CI.

### WHY
v1.1.2 was tagged and crates published while the Windows CI job was red. User: "we should be making sure that ci passes before we release a version or push the crates." The failing test was real: on Windows, `%TEMP%` lives under the user profile, and `~/.code-kb` (telemetry, plugin dist) exists there, so a git-less Cargo project under home bound to the home dir. Linux never sees it because /tmp is outside $HOME.

### HOW
Reproduced with win-test (guest `C:\work\code-kb`, scripts passed via `powershell -EncodedCommand` because scp to the guest is not allowed and the command line limit is ~8K). The server log at `C:\Users\agent\.code-kb\logs` showed the wrong binding.

### IMPACT
Any user with a non-git project under their home directory was affected on every OS, not only Windows. Do not tag or publish crates until `gh run list --commit <sha>` shows success; preflight enforces it.

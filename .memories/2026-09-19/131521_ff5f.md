## v1.1.2: initial scan moves to MCP server start

### WHAT
- `crates/code-kb-cli/src/mcp/server.rs`: new `spawn_index_prepare` runs in the startup thread from `McpServer::new` and `bind_workspace`. Missing index → `create_index` full scan. Existing index → FTS rebuild + `reconcile_offline_edits`.
- First tool call joins that thread, starts the watcher once the db exists, and returns the real scan error when the scan failed (the old `--root` hint stays only when no scan was attempted).
- `tests/mcp_test.rs`: `test_mcp_telemetry_summary_unindexed_repo_no_autoscan` rewritten as `test_mcp_server_start_creates_missing_index` (asserts `artifact.db` appears after `initialize` alone).
- Invariant 1.5 in CLAUDE.md/AGENTS.md updated. Version bumped to 1.1.2, release notes at `docs/release-notes/v1.1.2.md`.

### WHY
The initial scan only ran on the first tool call. `.code-kb/` was created by logging at server start, so the directory existed with no index, which looked broken. User called the old behavior "totally unexpected".

### HOW
Reused the existing reconcile thread slot (`reconcile: Option<JoinHandle<Result<(), String>>>`) instead of adding a second thread or state. The `.code-kb` dir is created by two independent paths: `logging.rs` (logs/) and `sync.rs::ensure_index_dir` (.gitignore + db).

### IMPACT
Fresh projects index in the background right after `serve` starts. Users on the launcher get the fix at 1.1.2.

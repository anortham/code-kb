## Codex plugin hooks never loaded because of the root plugin.json `$schema`

**WHAT:** Removed `"$schema": "https://agent-plugins.org/schemas/1.0.0/plugin.schema.json"` from the root `plugin.json` (the Antigravity manifest). Added a test in `tests/plugin/plugin-manifests.test.cjs` that fails if a `$schema` returns. Documented the Codex update path in the README (`codex plugin marketplace upgrade`, `codex plugin remove code-kb@code-kb`, `codex plugin add code-kb@code-kb`).

**WHY:** On another machine the Codex plugin reinstall kept fetching 1.0.1 and, after the marketplace upgrade, the code-kb hooks were missing from `/hooks`.

**HOW:**
- Reproduced in an isolated `CODEX_HOME` with `codex exec --dangerously-bypass-hook-trust` and `RUST_LOG=trace`. Only ponytail's hooks appeared in the `codex.hooks.command` spans; code-kb's MCP server loaded but its hooks did not.
- Bisected by editing the cached plugin: hooks file content, `.codex-plugin/plugin.json` keys, root `hooks.json`, and `.codex/` made no difference. Removing the `$schema` line from the root `plugin.json` made Codex load the hooks. Adding a `hooks` key next to the schema did not help.
- Two separate causes for the user's symptoms: (1) `codex plugin remove` deletes the plugin copy but not the marketplace snapshot, so `add` reinstalls the old snapshot version; (2) the `$schema` line disables `.codex-plugin` hook discovery.

**IMPACT:** No release needed; the marketplace snapshot carries the manifests and the launcher still downloads the 1.0.3 binary. Users refresh with `codex plugin marketplace upgrade`, remove and re-add the plugin, then trust the hooks in `/hooks`.

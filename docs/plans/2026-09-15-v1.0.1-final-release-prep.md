### Task 1: Harden Parameter Aliases & Version Guard

**Contract inputs:**
- `crates/code-kb-cli/src/mcp/server.rs`: `search_symbols` accepts `symbol_name` and `symbol` as silent aliases for `query`.
- `crates/code-kb-core/src/sync.rs`: `ensure_index_matches_pin` treats missing or unreadable `binary_version` as non-matching and triggers rebuild.

**File ownership:**
- `crates/code-kb-cli/src/mcp/server.rs`
- `crates/code-kb-core/src/sync.rs`
- `crates/code-kb-core/tests/freshness_test.rs`
- `crates/code-kb-cli/tests/mcp_test.rs`

**Serialization required:** Not applicable - single task.
**Dependency reason:** Not applicable - single task.

**Steps:**
1. Dropped with step 2: no test for a missing `binary_version` because that case does not rebuild.
2. Not done, on purpose: `ensure_index_matches_pin` keeps `Ok(false)` when `binary_version` is missing. Test fixtures and hand-built databases have no `artifact_metadata`; rebuilding them would delete the index under the caller.
3. In `crates/code-kb-cli/tests/mcp_test.rs`, add tests verifying `search_symbols` and `lookup_symbol` succeed when invoked with `symbol_name` or `symbol`.
4. In `crates/code-kb-cli/src/mcp/server.rs`, add `.or_else(|| arguments.get("symbol_name")).or_else(|| arguments.get("symbol"))` to `search_symbols` parameter resolution.
5. Run `cargo test --test freshness_test` and `cargo test --test mcp_test` to verify pass.

**Acceptance criteria:**
- [x] `ensure_index_matches_pin` rebuilds databases with altered `binary_version`.
- [x] `search_symbols` accepts `symbol_name` and `symbol` without returning `Missing required parameter: query`.
- [x] `cargo test --test freshness_test` passes.
- [x] `cargo test --test mcp_test` passes.

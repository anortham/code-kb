# 024: v1.3.1 lookup fixes, then v1.4 (edit_file, recovery, facts, telemetry)

> **For agentic workers:** REQUIRED SUB-SKILL: Use razorback:subagent-driven-development whenever delegation is available and permitted, including for one task; serialize dependent tasks. Use razorback:executing-plans only when delegation is unavailable or the user/session explicitly selected single-agent execution.

Date: 2026-09-21. Status: draft, waiting for approval. Written after the v1.3.0
release review of the same day (telemetry, TODO files, a Codex second opinion,
and the julie and miller edit-adoption data).

**Goal:** Ship a v1.3.1 patch that makes exact and qualified lookups reliable, then a v1.4.0 that adds a text edit tool agents will use, makes every miss recoverable in one turn, repairs structural-fact categories, and makes the tokens-saved headline cover every read tool with a stated baseline.

**Architecture:** No new crate, no new dependency, no schema change to `artifact.db`. `edit_file` reads the target file from disk at call time, matches `old_text` in those bytes, and reuses the validate, write, re-index, and rollback tail of `replace_symbol_body`. Recovery suggestions come from the existing `symbol_names_tri` trigram table and the `files` table. Telemetry gains one column and a coverage figure. Search ranking is frozen at v1.3.0; the eval sets are regression checks only.

**Tech Stack:** Rust, SQLite via `rusqlite` (FTS5 trigram and porter tables), `julie-extract` 3.1.3 for parsing and `check`, MCP JSON-RPC over stdio, clap CLI.

**Spec:** This document, plus the evidence it argues from:
- `docs/2026-09-20-health-review.md` (bounded results, truthful telemetry).
- `docs/toolkit-assessment.md` (target identity, incomplete answers, facts ergonomics).
- `docs/release-notes/v1.3.0.md` (the test-file rule that this plan narrows).
- `~/.code-kb/search-eval/reviews/2026-09-21-codex-v1.4-direction-opinion.md` (the Codex second opinion; every code claim in it was reproduced on `main` at `2d965c6`).
- `~/source/miller/docs/findings/2026-06-28-julie-miller-edit-adoption.md` (why agents used julie's `edit_file` and not symbol rewrites).

**Architecture Quality:** Approved shape: one new core function `edit_file` in `crates/code-kb-core/src/edit.rs` sharing a private `commit_file_edit` tail with `replace_symbol_body`; one new MCP tool `edit_file` with the CLI command `code-kb edit-file`; one shared `suggest_symbol_names` and one `suggest_file_paths` in `queries.rs` used by every not-found path; an explicit category alias table for structural facts. Main risk: a text match that lands on the wrong occurrence writes the wrong place. The tool therefore refuses a non-unique match unless `occurrence` is given, and the unchanged concurrent-modification and rollback checks guard the write.

**Contract inputs:** The v1.3.0 release note rule for test-file rows. The `is_test` parameter text in the MCP schema and README (Task 5 rewrites it).

**File ownership:** Modify `crates/code-kb-core/src/queries.rs` (`search_symbols_scoped`, its tests); test `crates/code-kb-core/tests/disambiguation_test.rs`

**Serialization required:** Yes

**Dependency reason:** Tasks 1, 2, 3 all edit `queries.rs`; run 1 then 2 then 3.

**What to build:** An exact-name lookup must never hide the row it names. - Qualified branch: remove the `test_matches` check. Keep the `kind_matches` check.
- SQL branch: when `include_tests` is false, replace the appended clause with `AND (name = :query OR (is_test = 0 AND test_container = 0 AND NOT <test_path_predicate>))`. The `:query` parameter is already bound.
- Rename the in-file test to `qualified_lookup_in_a_test_file_returns_the_named_row` and invert its assertion: `Helpers.load_fixture` with `include_tests = false` returns the one row. Keep a sibling assertion that the substring query `load_fix` with `include_tests = false` returns nothing from the test file.
- Add to `disambiguation_test.rs`: a fixture with `test_alpha` in `tests/alpha_test.rs` (flagged `is_test = 1`) and `alpha` in `src/alpha.rs`; `search_symbols_scoped(conn, "test_alpha", None, None, false, 10)` returns the test row; `search_symbols_scoped(conn, "alpha", None, None, false, 10)` returns only `src/alpha.rs`; `search_symbols_scoped(conn, "alph", None, None, false, 10)` returns only `src/alpha.rs`.
- Do not touch `fts_search_symbols_scoped` or any rerank code.

Why

Reading a whole file adds up

Reading this 2,473-line file to find one function signature adds about 26,000 tokens to the conversation. That leaves less room for the task and earlier decisions. code-kb can show the signature or the function's context on its own.

What it does

What your agent can find

File outlines
file_skeleton lists a file's types and function signatures without the implementation. codebase_outline gives a short directory overview.
Function context
get_symbol_context shows a function's code, the signatures of functions it calls, related types, and test locations.
Callers and tests
blast_radius follows callers across the repository and suggests tests to run. With no target, it checks your uncommitted changes.
Up-to-date results
Edit files as usual. code-kb picks up changes automatically and refreshes a file before showing its body or outline.
Usage stats
telemetry_summary tracks estimated tokens saved, tool calls, and errors across sessions. Run code-kb stats to see the report.
Windows support
Every release includes a Windows binary tested on NTFS. Results show paths with forward slashes on every platform.
Structural facts
Find routes, queries, config keys, and more alongside symbols. See which categories are indexed in your repository.
Agent hooks
code-kb hook SessionStart tells the agent when to use each tool. The hook runs from the binary without a script runtime.

Web and UI

Data and documents
JSON, Markdown, regex, SQL, TOML, XML, YAML.

Find more than names

Structural facts are indexed details beyond symbol names. Examples include Express and FastAPI routes, SQL statements, TOML keys, and QML bindings. Run code-kb facts to see the categories found in your repository, or code-kb facts route to list routes. See the extractor's supported-language list for more detail.

About latency

code-kb stats reports query times. In our measurements, most queries took 0 to 5 milliseconds. Agent response times also depend on the model and network. See the comparison with earlier designs in the architecture notes.

Steps

From first look to tested change

Here's one way to use code-kb when you start work in an unfamiliar repository.

  1. Orient

    Directory tree and the main exports, about 200 tokens.

    codebase_outline(depth=2)

  2. Find the interface

    Signatures and traits with bodies removed. Search by concept when the name is unknown.

    file_skeleton("src/server.rs")
search_symbols("auth token validation")

  3. Get the context

    The target body, its callees' signatures, parameter types, and tests in one call.

    get_symbol_context("handle_request")

  4. Check the impact

    Callers across several hops and the tests that cover them.

    blast_radius(symbol="compute_hash")

  5. Edit

    Edit with your usual tools. code-kb picks up file changes automatically.

  6. Verify

    Run the suggested tests. Check usage with code-kb stats.

    cargo test compute_hash

Install

Connect it to your agent

Choose your agent below for setup steps. The plugin needs Node.js 18 or newer. On first use, it downloads code-kb and the matching julie-extract for your platform.

You can also download the release archive, put both binaries on PATH, and register the server yourself. GUI apps such as Cursor need --root set to the project path; terminal agents usually start in the project directory. See the README for more setup options.

Install the plugin, skill, and hooks with these two commands:

/plugin marketplace add anortham/code-kb
/plugin install code-kb@code-kb

For manual setup across projects on this machine:

claude mcp add --scope user code-kb -- code-kb serve

For one project, in .mcp.json:

{
  "mcpServers": {
    "code-kb": {
      "command": "code-kb",
      "args": ["serve"]
    }
  }
}

Install the plugin, skill, and hooks:

grok plugin install anortham/code-kb --trust
# or from a local checkout:
grok plugin install /path/to/code-kb --trust

For one project, in .mcp.json:

{
  "mcpServers": {
    "code-kb": {
      "command": "code-kb",
      "args": ["serve"]
    }
  }
}

Install the plugin, skill, and hook:

agy plugin install https://github.com/anortham/code-kb

Or by hand, from the command line:

agy mcp add code-kb code-kb serve

Or in ~/.gemini/config/mcp_config.json with eager tools. The AGY CLI starts the server in the project directory; the Antigravity IDE does not, so add --root for the IDE:

{
  "mcpServers": {
    "code-kb": {
      "command": "code-kb",
      "args": ["serve", "--root", "/absolute/path/to/project"],
      "disabled": false,
      "eager": true,
      "force_all_tools_eager": true
    }
  }
}

In ~/.gemini/config/hooks.json (Antigravity uses PreInvocation):

{
  "code-kb": {
    "PreInvocation": [
      {
        "command": "code-kb hook PreInvocation",
        "timeout": 10,
        "type": "command"
      }
    ]
  }
}

Link the skill so the agent knows when to use each tool:

ln -sf /path/to/code-kb/skills/code-kb ~/.gemini/config/skills/code-kb

Install the plugin, skill, and hooks:

codex plugin marketplace add anortham/code-kb
codex plugin add code-kb@code-kb

Or by hand, in ~/.codex/config.toml:

[mcp_servers.code-kb]
command = "code-kb"
args = ["serve"]

Add this to .cursor/mcp.json in your repository. Set --root to the project's absolute path:

{
  "mcpServers": {
    "code-kb": {
      "command": "code-kb",
      "args": ["serve", "--root", "/absolute/path/to/project"]
    }
  }
}

code-kb hook prints the routing instructions the agent reads at session start. No Node.js or shell needed. Supports SessionStart, SubagentStart, and PreInvocation (Antigravity).

code-kb hook SessionStart
code-kb hook SubagentStart
code-kb hook PreInvocation

# hooks/claude-codex-hooks.json wires both:
{
  "hooks": {
    "SessionStart": [
      {
        "matcher": "startup|resume|clear|compact",
        "hooks": [{ "type": "command", "command": "code-kb hook SessionStart" }]
      }
    ],
    "SubagentStart": [
      {
        "hooks": [{ "type": "command", "command": "code-kb hook SubagentStart" }]
      }
    ]
  }
}

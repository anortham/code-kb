Why

Reading a whole file adds up

What it does

What your agent can find

File outlines
file_skeleton lists a file's types and function signatures without the implementation. On a folder, it gives a short directory overview.
Function context
get_symbol_context shows a function's code and return type, its callers with their evidence, the tests to run with their commands, the markers its sibling symbols share, the signatures of functions it calls, and related types, in one call.
Callers and tests
find_references lists every caller site, and blast_radius follows callers across the repository to the tests to run. Use them when you need the full list. With no target, blast_radius checks your uncommitted changes.
Post-edit check
After you edit, check_edit lists the symbols whose shape changed and every call, construction, or match that your diff did not reach. code-kb hook Stop runs it when the agent stops and blocks once if a site still uses the old shape.
Up-to-date results
Edit files as usual. code-kb picks up changes automatically and refreshes a file before showing its body or outline.
Usage stats
Run code-kb stats to see estimated tokens saved, tool calls, and errors across sessions.
Windows support
Every release includes a Windows binary tested on NTFS. Results show paths with forward slashes on every platform.
Structural facts
Find routes, queries, config keys, and more with the code-kb facts command. It lists the categories indexed in your repository.
Agent hooks
code-kb hook SessionStart tells the agent when to use each tool and records the commit the session started at. code-kb hook Stop and code-kb hook SubagentStop run the edit check. The hooks run from the binary without a script runtime.

Find more than names

Structural facts are indexed details beyond symbol names. Examples include Express and FastAPI routes, SQL statements, TOML keys, Go module dependencies, and QML bindings. About latency

code-kb stats reports query times. On the code-kb repository, a warm symbol body or small skeleton took 1 to 4 milliseconds, and most other calls took 10 to 50 milliseconds. A concept search or a callers report can take up to about 100 milliseconds. Agent response times also depend on the model and network. See the comparison with earlier designs in the architecture notes.

Steps

From first look to tested change

Here's one way to use code-kb when you start work in an unfamiliar repository.

  1. Orient

    Directory tree and the main exports, in a few hundred tokens.

    file_skeleton("src")

  2. Find the interface

    Signatures and traits with bodies removed. Search by concept when the name is unknown.

    file_skeleton("src/server.rs")
lookup_symbol("auth token validation")

  3. Get the context

    Before you change a symbol: its body, its callers, the tests to run with their commands, the markers its siblings share, its callees' signatures, and its types in one call.

    get_symbol_context("handle_request")

  4. Edit

    Read the file you will edit, since the editor needs it, and edit with your usual tools. code-kb picks up file changes automatically.

  5. Check the edit

    The symbols whose shape changed and every site that your diff did not reach. For the full list of callers or tests, call find_references or blast_radius.

    check_edit()

  6. Verify

    Run the tests that the context listed. Check usage with code-kb stats.

    cargo test handle_request
code-kb stats

Tools

Four query commands have no MCP tool: code-kb outline [path] prints a folder's layout, which file_skeleton on a folder also returns, code-kb search <query> prints the ranked search with each row's score (--explain adds the score breakdown), code-kb facts [category] lists routes, queries, models, and config keys, and code-kb stats reports token savings and tool errors.

Install

Connect it to your agent

Choose your agent below for setup steps. The plugin needs Node.js 18 or newer. On first use, it downloads code-kb and the matching julie-extract for your platform.

You can also download the release archive, put both binaries on PATH, and register the server yourself. The same code-kb serve command works in GUI apps and terminal agents. --root is optional; it only prepares that project's index at start. See the README for more setup options.

Install the plugin, skill, and hooks with these two commands:

/plugin marketplace add anortham/code-kb
/plugin install code-kb@code-kb

For manual setup across projects on this machine:

claude mcp add --scope user code-kb -- code-kb serve

For one project, in .mcp.json:

{
  "mcpServers": {
    "code-kb": {
      "command": "code-kb",
      "args": ["serve"]
    }
  }
}

grok plugin install anortham/code-kb --trust

grok plugin install /path/to/code-kb --trust

agy plugin install https://github.com/anortham/code-kb

Or by hand, from the command line:

Link the skill so the agent knows when to use each tool:

ln -sf /path/to/code-kb/skills/code-kb ~/.gemini/config/skills/code-kb

Install the plugin, skill, and hooks:

Run codex, open /hooks, and trust the four code-kb hooks.

To update, refresh the marketplace snapshot first. codex plugin remove followed by codex plugin add reinstalls the version already in the snapshot:

codex plugin marketplace upgrade
codex plugin remove code-kb@code-kb
codex plugin add code-kb@code-kb

Or by hand, in ~/.codex/config.toml:

[mcp_servers.code-kb]
command = "code-kb"
args = ["serve"]

code-kb hook prints the routing instructions the agent reads at session start. No Node.js or shell needed. Supports SessionStart, SubagentStart, and PreInvocation (Antigravity). Stop and SubagentStop read the hook JSON on stdin and run the edit check: they block the stop when a proven site still uses the old shape (never for a likely site, a signature change, or a JavaScript parameter change), skip the diff they checked or blocked on last, and print nothing otherwise. The SessionStart hook records the session base in .code-kb/sessions/.

code-kb hook SessionStart
code-kb hook SubagentStart
code-kb hook PreInvocation
code-kb hook Stop
code-kb hook SubagentStop

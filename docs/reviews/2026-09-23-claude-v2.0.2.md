## Finding and disposition

Claude noted that the new QML pending-call shadow guard checks variables and parameters owned directly by the caller. It suggested walking outer function scopes for a nested call. That is a possible gap in the predicate, but the proposed fix does not address the concrete QML case:

- A QML function `outer(root)` containing `inner() { root.helper() }` produces a direct `inner → helper` relationship, with no pending `helper` row.
- julie-extract 3.3.1 and 3.5.0 produce the same direct row for that source.
- `pending_target_predicate` runs only on pending rows, so changing it would not filter this preexisting extractor result.

The finding is deferred as an upstream extraction limit outside the 3.5.0 upgrade. Adding a recursive SQL scope walk to the pending-call hot path without a failing pending-row case would add query cost and leave the observed false caller in place.

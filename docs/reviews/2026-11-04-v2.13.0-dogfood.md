## Fixed

- `blast_radius` labeled a member read in `Flask.__init_subclass__` as a direct
  caller. The code reads `cls.handle_user_exception` to inspect the method; it is a
  direct reference. Caller labels now require a call-like relationship, and the
  regression tests preserve the reference in impact membership. The tests also
  caught and fixed a lost `name only` qualifier on likely method-group references.
- `blast_radius` described a count of additional `(path, line)` result rows as a
  count of tests. File-seed walks can group constructor-only tests into one row.
  The notice now says “additional distinct test rows”; it does not imply that a
  grouped row contains one test. The session summary reported 9 versus a net row
  increase of 8, but did not preserve both row sets, so the exact group transition
  cannot be checked from the round artifact.
- The Windows ARM64 Cargo Binstall target lacked a ZIP override despite the
  release workflow publishing ZIP archives. The combined fix adds the override
  and a Cargo metadata test for all six release targets.

The code-kb reporting corrections have focused regression tests and exact-call
receipts. The Cargo metadata test checks all six release targets. The Binstall
record-fix lookup is only a CLI smoke check; packaging evidence is the public
2.12.0 ARM dry-run failure (exit 94), passing x64 control, and successful local
fixed-manifest ARM dry-run in `target/release-support/binstall-arm-probe.log`,
`target/release-support/binstall-x64-probe.log`, and
`target/release-support/binstall-arm-fixed.log`. The test-first format failure is

## Gaps

- `check_edit` misses caller binding changes when a required first positional
  parameter is added, and omits three `add_url_rule` reads after a field removal
  while reporting three unresolved sites.
- `check_edit` retains only 50 test rows even when the requested limit is larger;
  later pages cannot reveal the full reported set.
- `blast_radius` misses `test_cli_name`, which reaches `Flask.cli` through
  application construction at import time.
- Tests that exercise `Flask.handle_user_exception` through the test client and
  framework/runtime path are not linked to the method. The answer accurately
  reports no indexed tests and advises running the full suite.
- Exact route matches are followed by unrelated concept matches, and route
  results do not explain implicit HEAD and OPTIONS methods.
- `find_references` prints many documentation-only text matches while abbreviating
  the verified 26 imports across 24 files.

The Codex session's seven direct `check_edit` break sites were correct. The Flask
test suite was not run; the available environment lacked pytest and Werkzeug.

## Gaps retained

Each gap gives a true but incomplete answer. This release changes only
`blast_radius`, so the other tools answer as v2.9.0 did. On `src/flask/cli.py`,
v2.9.0 and the candidate list the same 55 tests. The v2.9.0 round recorded the
removed-attribute, test-client, `cli.py`, annotation, lambda, concept-lookup,
and property gaps.

- `check_edit` does not report a removed class or instance attribute
  (`Request.routing_exception`, `App.subdomain_matching`, `Flask.request_class`).
- `check_edit` says that it does not check functions passed as values. It does
  not list the 12 `_async_wrapper=self.ensure_sync` sites. The word "macro" in
  that line does not apply to Python.
- `blast_radius Flask.handle_user_exception` lists no test. It does not follow
  tests through the WSGI test client; the answer names `Flask.__call__` as an
  open end and says to run the full test suite.
- `blast_radius` on `src/flask/cli.py` misses 10 tests that use the CLI through
  Click, mixes per-file constructor-only rows with named tests, and lists four
  tests that reach `cli.py` only through `Flask()` building an `AppGroup`.
- `flask.Flask` type annotations are `unresolved`; `flask.Flask(...)` calls are
  `proven`.
- `test_cli_runner().invoke(...)` is `unresolved`: julie records no receiver for
  a call on a call result. `super().invoke` is a candidate, not excluded.
- Some sites on a typed local (`app = ctx.app`) are `likely` with the basis
  `receiver not typed`.
- A concept lookup ("view that registers a new user account") ranks helpers
  above the `register` view.
- A folder skeleton lists an inline lambda as `function lambda_48`, and its
  "3 unsupported files" note does not name the files.
- `get_symbol_context` finds no related test for request-path methods, for the
  same reason as `blast_radius`.
- `get_symbol_body` calls a property getter and setter "overloads".
- The open-end list ends with `N more in CLI --json`, which an MCP caller can
  reach only through the CLI. Other `blast_radius` lines use the same pointer.

## Upgrade evidence

A temporary git workspace containing a QML inline component and a C++
`Q_PROPERTY` was first scanned by code-kb 1.6.0 with julie-extract 3.3.0.
Its artifact recorded `binary_version=3.3.0` and `index_level=facts`.

Opening that same artifact with the task build and julie-extract 3.3.1 rebuilt
it once. It then recorded `binary_version=3.3.1` and `index_level=facts`.
The rebuilt `cpp.qt_property.v1` fact retained the new optional Qt metadata:
`designable`, `scriptable`, `stored`, `user`, and `revision`. A second query
left the artifact inode, mtime, and size unchanged, showing that startup did
not rebuild it again.

A task-build MCP server used 20,944 KiB RSS after initialization and 21,352
KiB after the property-facts request. This is a small-fixture smoke check only;
it is not comparable with a release-build baseline.

## Extractor contract review

The upstream [3.3.1 release](https://github.com/anortham/julie-extractors/releases/tag/v3.3.1)
keeps SQLite schema 7, report schema 3, and extraction identity epoch 10, while
adding the `qt-reference-corrections-v1` contract marker. The existing
version-and-level rebuild guard is therefore the required integration path.

- QML call, pending-call, handler-call, inline-component `extends`, and nested
  `parent`/`this` ownership rows now use the exact owning object, including
  local and parameter shadowing.
- Qt C++ `Q_PROPERTY` rows add optional `designable`, `scriptable`, `stored`,
  `user`, and `revision` metadata. code-kb persists those metadata fields and
  property-facts text displays them when present.
- QML JavaScript directive spans exclude trailing `//` comments. Qt C++ macro
  preprocessing preserves runtime calls and `Q_NULLPTR` expressions.

## code-kb facts integration

`StructuralFact` now retains `metadata_json` as JSON. The property-facts query
uses the Qt metadata `name` where present, and its text formatter displays
`property_type`, `read`, `write`, `notify`, plus the optional 3.3.1 attributes.
Focused coverage passes: `qt_qml_test` has 3 passing ownership/reference tests,
and `qt_cpp_test` has 11 passing metadata, header-edit, incremental-scan, and
QML JavaScript directive-span tests. The property test uses the public alias.

## Header update workaround

Focused header-edit coverage found that julie-extract 3.3.1 reports a `.h`
incremental `update` artifact as language `c`, while a full `scan` reports it
as `cpp`. The code-kb workaround forces a workspace re-extraction for
each `.h` refresh or edit, including watcher and offline-freshness paths; other
file types retain incremental updates. Remove this workaround once upstream
`update` preserves C++ language detection for headers. The focused edit
regression passes.

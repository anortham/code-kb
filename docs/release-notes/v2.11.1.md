# code-kb v2.11.1

This patch keeps the answers of `file_skeleton`, `get_symbol_body`, and
`get_symbol_context` within about 8K tokens, so one call can no longer fill a
large part of an agent's context. It bundles julie-extract 3.10.0 and keeps
SQLite schema 8.

## Answer size

A check of 273 calls on nine real projects found answers of 100K to 440K
characters: the skeleton of a lock file or of `json.hpp`, a folder outline of
a wide package, and the body or context of a large class. Each text answer of
these three tools now fits 32,000 characters, below Claude Code's 10K-token
warning for MCP answers. On the 12 largest calls the total fell from 1.59 MB
to 0.34 MB. `lookup_symbol`, `find_references`, `blast_radius`, and
`check_edit` already stayed small and do not change.

- `file_skeleton` on a file keeps the rows that fit, outer rows first. The
  rows it leaves out fold into `/* N more rows: Lx-Ly */`, and a type with no
  row shown becomes `{ /* N rows hidden: Lx-Ly */ }`. The ranges cover every
  member of the type, also members that julie places outside its own lines.
  A note at the top says how to read the hidden lines or list a type's
  members with `lookup_symbol Name.`.
- `file_skeleton` on a folder names fewer definitions per file (3, 2, 1, then
  counts only), then shows fewer levels, then cuts lines. It says what it
  left out and to pass a subfolder for more.
- `get_symbol_body` on a large class, module, or other type returns its
  members with their bodies hidden, and names the lines to read. A large
  function keeps the lines that fit and ends with the line range of the rest.
- All bodies of one answer share the budget: the overloads of
  `get_symbol_body` and the sections of `get_symbol_context`.
- CLI `--json` output keeps the full body.

## Fixes from the dogfood round

- `check_edit` reported fields as removed when a subclass writes an
  attribute that its base class in another file defines. In Flask, a blank
  line in `app.py` gave `fields +0, -2 (_got_first_request, debug)`. The base
  side of the check holds only the changed files, so it could not see the
  base class. The check now asks the current index whether each of those
  writes is inherited. The blank line now gives `no symbol changed shape`,
  and the removal of `session_interface` gives `fields +0, -1
  (session_interface)`.
- A class whose base has its own name
  (`class EnvironBuilder(werkzeug.test.EnvironBuilder)`) counted itself as its
  base. So `file_skeleton`, `lookup_symbol`, and search left out its own
  `self.app` as a write to an inherited attribute.
- The `blast_radius` open-end text said that something calls each open end.
  It now says that the runtime, a framework, a library, or an untied call may
  call them, or nothing does (`_path_is_ancestor` in Flask has no caller).

## Upgrade

- Refresh a running MCP session after upgrading. No rescan is needed.

## Known gaps

The dogfood round on Flask found these gaps. Each answer is true but
incomplete, and each was known in 2.11.0 unless noted.

- `check_edit` keeps 50 test commands in walk order, so the direct tests of a
  changed field can fall outside them.
- `blast_radius` and `get_symbol_context` list no test for
  `Flask.handle_user_exception`, which tests reach through the werkzeug test
  client. The answer names the open end.
- `blast_radius` labels `__init_subclass__`, which reads the target as a
  value, `direct caller (find_references)`.
- `find_references Flask` labels `app: flask.Flask` annotations `likely`, and
  repeats construction sites in three sections.
- `get_symbol_body` calls a property getter and setter `overloads`.
- `get_symbol_context` lists 5 related tests and can leave out the most
  direct one (new).
- `file_skeleton` on a folder lists the HTML elements of templates (new).
- `find_references` labels `builder.environ_base`, a werkzeug object, `likely`
  for `FlaskClient.environ_base` (new).
- `blast_radius` on a file counts test file groups as rows in
  `N returned` (new).

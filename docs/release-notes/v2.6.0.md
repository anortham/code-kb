# code-kb v2.6.0

This release makes Claude Code use code-kb. Before it, Claude Code kept every code-kb tool hidden behind its
tool search, and its agents almost never searched for them. It bundles the same julie-extract 3.7.2. The
SQLite artifact schema stays at version 7, so no index is rebuilt.

## Changes

- **The tools load at session start in Claude Code.** `tools/list` now sets `_meta["anthropic/alwaysLoad"]` on
  every tool except `telemetry_summary`.
  - Before: Claude Code deferred the tools, and in a 30-day telemetry review Claude sent 3–8% of its code
    navigation calls to code-kb, against 59% for Codex. In an A/B test, 0 of 24 Claude runs called code-kb.
  - After: 22 of 24 runs called it. In a later benchmark, 114 of 120 runs did.
  - The flag needs Claude Code 2.1.285 or later; other clients ignore it.
- **Clearer routing.** The session hook and the tool descriptions now say:
  - call `file_skeleton` before you read a source file, then `get_symbol_body` or `get_symbol_context` for the
    symbols you need;
  - use `lookup_symbol` or `find_references` instead of `grep` on a name;
  - use `search_symbols` to find code by concept.
- **Less text at session start.** The routing block, the server instructions, and the tool descriptions are
  shorter. A session starts about 1,900 tokens smaller, and the benchmark showed the same code-kb use (46 of
  48 runs). The routing block no longer claims "80–90%" savings for a whole session.

## Fixes

- **Servers that start together on a stale index.** When several `code-kb serve` processes started on an index
  that another julie-extract version wrote, each one rebuilt it into the same `artifact.db.rebuild` file and
  deleted the others' work. On a large repository, every call then waited and answered `Indexing … started`
  for minutes. The servers now take turns on `artifact.db.rebuild.lock`: the first rebuilds, and the others
  find the index current.

## Measured effect in Claude Code

A paired benchmark on 24 read-only code questions in six repositories (C#, Python, Rust, TypeScript) ran
Claude Code with and without code-kb, five times each. A blind judge checked each answer against the source.

- 9% less time (95% CI 0.84–0.99) and 13% less context growth during a task (CI 0.78–0.96).
- 34% fewer file reads and 38% fewer searches.
- Answer quality was the same.
- In editing tasks, Claude made almost no code-kb calls, so this release does not change editing cost.

## Known gaps

From the dogfood round on flask:

- `blast_radius` for `Flask.handle_user_exception` ranks `test_async_error_handler` below the default limit of
  20, because the error handler is registered in a fixture. It misses `test_bad_request_debug_message`, which
  sets a config key the target reads, and lists `test_wsgi_errors_stream` only because its name shares
  `error`.
- `blast_radius` on `src/flask/cli.py` folds most test files into `constructor-only callers` rows, but not
  `tests/test_subclassing.py`, the tutorial tests that call `create_app()`, or `examples/javascript/tests/`.
- `codebase_outline` at the default depth shows `src/flask/` as a count, with no main exports.
- The import summary of `find_references` for `Flask` does not count the 16 test files that use
  `import flask` and then `flask.Flask`.

## Release checks

- `scripts/release-corpus-check.py` against v2.5.3 on 14 real projects plus the julie fixtures: PASS. Symbols, call edges, and tool outputs did not change, and scan times stayed the same.
- One dogfood round in Claude Code on a flask worktree used all 10 tools (24 calls) and checked each answer
  against the source. It found no wrong answer; the gaps above come from it. The Codex session did not run
  because the Codex account is not active.
- Linux, macOS, Windows, and plugin launcher test suites pass.

## Distribution

The GitHub release provides archives for six targets. Each archive bundles `code-kb` and the pinned
`julie-extract` 3.7.2 with a `.sha256` checksum.

# code-kb v2.8.0

This release closes most of what `check_edit` missed on real commits, and it sharpens the labels of `find_references`. It bundles julie-extract 3.9.0, which brings SQLite artifact schema 8 and the smaller `references` index level. The first start rebuilds each existing index once, because the extractor version and the index level changed.

## How the misses were measured

`scripts/edit_replay.py` replays `code-kb check` and the Stop hook offline on three sets of real changes, from the 9 projects of the reach gate:

- **Clean commits** (105): each commit changes the shape of a symbol, and the author's commit is the truth. A Stop hook block on such a commit is false.
- **Holdback** (219): each commit changes a definition in one file and its uses in others. The harness applies only the defining file and asks which changed uses the check lists.
- **Sessions** (231): missed-site events from the owner's agent sessions, rebuilt from the session's own edits. The session text stays outside the repository; the repository holds the harness and counts only.

Each set has a dev half and a holdout half. Fixes were tuned on dev only, and the holdout halves were scored once. That first holdout score found a loss in JavaScript and Python. The owner chose to spend the holdout half to fix it, so both halves are now tuning data, and a later release needs new holdout cases. `docs/replay-baseline.md` has every number.

| Set | Half | v2.7.0 | v2.8.0 |
|---|---|---|---|
| Clean commits: false Stop blocks | dev | 1 of 56 | 0 of 56 |
| Clean commits: false Stop blocks | holdout | 1 of 49 | 1 of 49 |
| Holdback: truth sites listed | dev | 174 of 396 (43.9%) | 342 of 396 (86.4%) |
| Holdback: truth sites listed | holdout | 586 of 1073 (54.6%) | 840 of 1073 (78.3%) |
| Holdback: judged rows outside the diff that are true | dev | 43 of 76 | 53 of 59 |
| Holdback: judged rows outside the diff that are true | holdout | 81 of 90 | 90 of 96 |
| Sessions: rebuilt cases caught | dev + holdout | 8 of 88 | 8 of 88 |

On the holdout half, TypeScript goes from 46.5% to 80.7% of truth sites listed, JavaScript from 49.5% to 77.1%, Java from 51.9% to 58.9%, Go from 75.0% to 82.5%, and C# from 82.9% to 84.2%; Python stays at 78.3%. The first holdout score showed JavaScript at 33.3% and Python at 72.5%. Two commits caused all of it: a zod commit that deletes compiled `.js` files beside their `.ts` sources, and a flask commit whose 21 removed names passed the old cap of 10 symbols. Most session cases cannot be rebuilt (shell edits, a changed git state), so that set measures little yet.

## check_edit

- A removed exported constant, variable, or type alias is a shape change. Before, a removed TypeScript constant or type alias was not compared, and that was the largest miss cause on dev (118 of 139 TypeScript truth sites).
- A removed pytest fixture lists the tests and fixtures in its scope that take it as a parameter, each `proven`.
- An import of the old file proves the sites of a removed top-level symbol, also when the edit deleted the file, through `export *` and `export … from` rows.
- A removed Java class lists its `import p.G;` lines and the `import static p.G.m;` lines of its members, and a removed member lists its own static import. A static import that names the class file proves a bare call.
- A removed JavaScript method keeps the object it was assigned on (`req` for `req.param = function`), so a call through `req` stays `likely`.
- A relative JavaScript or TypeScript import line counts only when it resolves to the symbol's file. An import of a mirror copy (`deno/lib/`) is no longer listed.
- A JavaScript file that imports `./util` takes `util.js` before `util.ts`, as Node and bundlers do, and a deleted file keeps its own place in that order. A removed compiled `.js` file lists the uses in the `.js` files that import it, and not those in `.ts` files.
- A removed constant, variable, or type alias that the old file defines twice in one scope (`text_type` in both branches of `if PY2:`) reports once.
- A check covers at most 30 changed symbols, up from 10. The extra symbols are the ones with the fewest uses, so they cost the least: the Stop time p95 on the holdback set went from 7.05 s to 7.83 s, and to 5.62 s with the `references` index of julie 3.9.0.
- A removed C# type of a deleted file takes the namespace of that name in the index, so a use whose file does not open the namespace is excluded.
- A C# call whose argument types are all known and equal the parameter types of another overload of the same owner binds that overload, so a parameter or signature change of the first overload no longer lists it. julie 3.9.0 writes the argument types (`arg_types`).
- julie 3.9.0 writes a property for a JavaScript value assigned on a named object (`res.locals = res.locals || …`; not a function, a bare name, or another assignment), so a read of that property is another definition, not a `likely` site of a removed function with the same name.
- The one false Stop block of the dev clean set is gone: an object-literal method no longer takes the calls of a module function with the same name.
- The Stop rule is unchanged: a block needs a `proven` site outside the diff.

## find_references: proof rules

Each rule has a regression test and a line in `CLAUDE.md`.

- A bare Java call reaches only the methods of the caller's classes, the classes around it, their ancestors, and its static imports: ``a bare call reaches only the classes of `Caller` and its static imports``.
- A Python receiver bound by an import that reaches no project file (`_json.dumps()` after `import json as _json`), and a Java receiver imported from a package that no project folder holds (`Assert.assertEquals()` after `import org.junit.Assert;`), exclude the site: ``receiver `_json` is imported from `json` ``.
- A Python receiver that names a project module reaches no class member, and a function nested in a Python, Rust, Kotlin, C#, Swift, Scala, or Dart function is no other definition outside that function.
- A bare C# use of a top-level type is excluded when its file neither holds nor opens the type's namespace (``namespace `App.Utilities` is not open here``), and such a type is no other definition of the use. An MSBuild `<Using …/>` item in a project file opens every namespace.
- In C#, Java, Kotlin, Scala, Swift, Dart, Rust, Go, C++, C, and VB.NET, a place that names a type never names a field, constant, variable, property, parameter, or enum member.
- A bare C# use of a type that julie kept from an `#if !X` branch is `unresolved` when its file always opens a namespace that another file opens under `#if X`: ``ConcurrentDictionary` is defined only without `HAVE_CONCURRENT`, and this file always opens `System.Collections.Concurrent`, which other files open with it``. A file that opens the namespace under `#if X` keeps the use, which a build without `X` needs. julie 3.9.0 records the condition (`preprocessorIf`).
- A JavaScript file's relative import takes the JavaScript twin of a module before the TypeScript one (`./util` names `util.js` beside `util.ts`).
- A JavaScript or TypeScript call on a call result, an index result, a string literal, or a `const` that holds a call never reaches a top-level function, variable, or constant that no object holds: ``a call on a call result never reaches the top-level `refine` ``. A receiver that loads a module (`require(…)`, `import(…)`) keeps the old rules.
- A bare JavaScript or TypeScript read inside the block body of a callback parameter, loop variable, or catch parameter with its name (`catch (error) { return error; }`) is excluded: ``line 13 binds the name as a callback parameter, loop variable, or catch parameter``. Before, such a read was excluded only when another definition of the name was nearer; the corpus check found two zod reads that lost their exclusion when phase 3 stopped counting an object-literal method as that definition. An expression body (`(e) => e()`) keeps the old rule: an import or same-file proof becomes `likely`.

The reach gate now scores 9 projects: goldfish (TypeScript) and jsonschema2pojo (Java) joined. Against v2.7.0 on the same 9 projects, the metric tables are equal except Java excluded precision, 0.999 to 0.998, and Python, where the write `self.static_folder = static_folder` became a proven site of the property: recall 0.904 to 0.908, and accounted share 0.996 to 1.000. ## Body and lookup

- A Python write `self.static_folder = …` whose own class defines `static_folder` as a property or a value is a write, not a definition, like a write to an inherited attribute. `get_symbol_body Scaffold.static_folder` returns the getter and the setter, not the write as a third overload; lookup, search, and skeletons leave the write out; and the callers report lists it as a site of the property.
- The range in the header of a Python body, and of a context target, starts at the first decorator, where the returned text starts (`App.name` is 422-437, not 423-437).

## Scan memory

julie sizes its page cache at an eighth of physical memory, so a scan's memory grew with the index. code-kb now sets `JULIE_BULK_CACHE_KIB` to 1 GiB unless the environment sets it. hermes-agent: peak 5.4 GB, now 2.0 GB, for about 1.4% more scan time. `SCAN_SLOWDOWN_LIMIT` in the corpus check is 1.5 again.

## Index level

New indexes use julie's `references` level instead of `full`: the call and variable-reference identifiers with their call metadata, without the annotations, complexity metrics, source regions, and type-argument rows that code-kb never reads. julie 3.9.0 also writes no reference-site row for an identifier that no relationship shares. With a 1 GiB page cache:

| Project | v2.6.0 `facts` | v2.7.0 `full` | v2.8.0 `references` |
|---|---|---|---|
| hermes-agent | 1.8 GB | 3.95 GB | 2.45 GB, peak 1.97 GB, 69 s |
| aspnetcore | 2.0 GB | 3.52 GB | 2.14 GB, peak 1.87 GB, 46 s |
| code-kb | | 276 MB | 175 MB, 4.3 s |

Both large projects are within 1.5 times their v2.6.0 `facts` size and peak memory (2.60 GB and 2.81 GB at `facts`).

## Telemetry

- `tool_telemetry` gains a nullable `client` column, from `clientInfo.name` of the MCP `initialize` request.
- A new table `hook_telemetry` records each Stop and SubagentStop check: the event, the diff hash, the sites listed, whether it blocked, and `followed`, which is true when the next Stop after a block changed a line of a site the block listed.
- An old telemetry database upgrades in place. Telemetry stays local, follows the existing disable flags, and records no source text.

## Known limits

`docs/edit-check.md` "Known limits" names each gap. The ones the replay still shows:

- julie gives a C# argument type only for the forms it can read (a literal, `new T(…)`, a cast, `as`, `typeof`, `nameof`, `this`, a typed local, parameter, or field), and the rule needs an exact match, so a call that reaches another overload through a conversion is still listed.
- A use of a C# fallback type under `#if !X` stays `likely` when no file of the project opens a namespace under `#if X`.
- julie writes no JavaScript property for a member chain (`res.locals.user = …`), a prototype, or a bare name as the value (`req.res = res`), so a read of such a property is still a `likely` site of a removed function with the same name.
- A call of a member of a removed class is not listed when it names the member, not the class.

Gaps from the release dogfood round on Flask:

- `check_edit` misses a removed `self.` attribute (a known limit), lists only the tests that call a changed symbol, and its MCP text folds the sites after 12 rows (CLI `--json` has every row).
- `blast_radius` misses tests that reach a method only through the test client at run time (`Flask.handle_user_exception`) and tests that use a CLI object as a value (`cls=FlaskGroup`, `run_command.make_context`). It repeats a file header when rows come from several tiers, and its count includes the constructor-only file rows.
- A `flask.Flask` type hint is `unresolved` when a class of that name is nested in a test function in another file.
- `find_references` callees leave out a call on a subscript result (`environ[…](ctx)`).
- `lookup_symbol` adds rows that match one common word of a concept query. A folder `file_skeleton` names julie lambdas (`lambda_48`), and a file skeleton hides the decorator of a route nested in a function.
- `get_symbol_context` shows at most 5 related tests and has no parameter to show more.

## Release checks

- The reach gate passes on 9 projects (proven precision, excluded precision, and accounted share at least 0.98 in every language), and `lost_proven` prints nothing for the 9 projects.
- The corpus check compares v2.7.0 with this release on the projects of `scripts/release-corpus.txt` and passes. Every changed output was traced to a rule in these notes.
- The release dogfood round (one Claude Code and one Codex session on Flask) passes with no open defect. It found two wrong answers, both fixed before the tag (see "Body and lookup").
- `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`, and the workspace tests pass.

## Upgrade

- The first start rebuilds each index once, because the extractor is now julie-extract 3.9.0 and new indexes use its `references` level.
- julie-extract 3.9.0 refuses to write into a schema 7 index, even with `--force`. `code-kb scan` on such an index now removes it and scans a new one. The server already rebuilt it on start.
- Refresh a running MCP session after the upgrade.

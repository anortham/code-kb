# code-kb v2.7.0

This release makes `find_references` answer "what must a change reach?" and adds a check that lists what an edit missed. It bundles julie-extract 3.8.0. The SQLite artifact schema stays at version 7. The first start rebuilds each existing index once (see "Upgrade").

## Breaking changes for agents

- **Four MCP tools are removed.** A call returns `Unknown tool`. The CLI commands stay.

  | Removed MCP tool | Use instead |
  |---|---|
  | `search_symbols` | `lookup_symbol` with a few words; CLI `code-kb search` stays |
  | `codebase_outline` | `file_skeleton` on a folder; CLI `code-kb outline` stays |
  | `find_structural_facts` | CLI `code-kb facts` (no MCP tool) |
  | `telemetry_summary` | CLI `code-kb stats` (no MCP tool) |

- **The tool list has seven tools:** `file_skeleton`, `lookup_symbol`, `get_symbol_body`, `get_symbol_context`, `find_references`, `blast_radius`, and the new `check_edit`. Every one requires `project_root` and sets `_meta["anthropic/alwaysLoad"]`; no tool is an exception now. Refresh a running MCP session after the upgrade so it sees the new list.
- **`blast_radius` lists only tests that the call graph reaches:** callers, fixture users, the tests of a setup member's class, and tests that reach the target through a constructor. The rows that a word match produced are gone: stem-matched and module-matched test files, shared words, error-handler evidence, and `possible` tests. The JSON field `test_file_ceiling_reached` is removed. When no test is found, the text says `No test reaches it through the index. Run the full test suite.`
- **CLI JSON changed.** `code-kb refs --json` for callers prints the report object (`target`, `counts`, `sites`, `text_only`, and so on) in place of an array of rows; callees keep the array. `code-kb lookup --json` prints an object with `names`, `ranked`, and, for a miss, `miss`.

## find_references: every site of a name, with its evidence

Before, `find_references` listed the rows that the resolver matched and did not say what it left out. On 12 symbols in flask, express, and gson, v2.6.0 found 23% of 593 true call sites, and `code-kb refs safe_tempdir` said 108 found where 209 call sites exist.

- Each indexed site of the name gets one label and a basis: `proven` (index evidence ties it to the target), `likely` (only the name ties it, and no other definition can reach it), `unresolved` (another definition can reach it and the index cannot choose), or `excluded` (evidence ties it to another definition, an unindexed import, another type, or another language).
- A whole-word text scan of the project accounts for every line of the name: a site, a definition, an import, or text only (docs, comments, strings, or code the index did not record). The header reads `Sites: N · proven · likely · unresolved · excluded`, then a `Text:` line with the reconciliation.
- Counts are always complete. `limit` caps only the listed rows; `--json` prints the whole report. The checks stop after 3 s, and the answer counts the sites it left unchecked.
- Rust path-qualified calls (`crate::util::f()`, `my_crate::module::f()`) now match a top-level function. v2.6.0 dropped them without a notice.
- New indexes use julie's `full` level, which keeps call and variable-reference identifiers.

A new offline gate, `scripts/reach_gate.py`, scores the report against compiler (SCIP) truth for 30 symbols in each of 7 projects (flask, express, zod, gson, cobra, Newtonsoft.Json, code-kb), in Python, JavaScript, TypeScript, Java, Go, C#, and Rust. Proven precision, excluded precision, and accounted share must each be at least 0.98 in every language. `scripts/release-preflight.sh` requires a fresh PASS. Recall (proven and likely sites that cover a truth line), v2.6.0 against this release:

| Language | v2.6.0 | v2.7.0 |
|---|---|---|
| csharp | 0.698 | 0.899 |
| go | 0.074 | 1.000 |
| java | 0.947 | 0.950 |
| javascript | 0.032 | 0.995 |
| python | 0.895 | 0.904 |
| rust | 0.902 | 1.000 |
| typescript | 0.358 | 0.651 |

Overall recall goes from 0.529 to 0.911. Proven precision is 1.000 in every language (v2.6.0: 0.171 to 0.993, because it labels nothing and the gate scores each of its rows as proven). Fixes were tuned on the dev half of the symbols only.

## JavaScript and TypeScript

- A module resolver (`reference_report/js_modules.rs`) follows `export … from`, `export * from`, and namespace re-exports to a relative file or a workspace package, through `package.json` `exports`, `module`, `main`, and `types`; `require()` and an ES import follow their own conditions; the nearest `tsconfig.json` or `jsconfig.json` (`paths`, `baseUrl`, `extends`) decides first. So `z.strictObject()` through `import * as z from "zod/v4"` is proven.
- A callback parameter, a `for … of` variable, and a `catch` parameter are read from the source (`reference_report/js_bindings.rs`), because julie records no symbol for them. When such a binding has the name, an import, same-file, scope, or qualified-path proof becomes `likely` and names the line.
- A call on a call result, an index result, or a string literal, and a call after a leading `.`, is never a bare call.
- `likely` now means that no other definition can reach the site, and a site counts only the other definitions it can reach. On TypeScript, `likely` was right on 28 of 558 sites and is right on 11 of 12.

## lookup_symbol is the one search tool

- A query that names no symbol exactly also lists the ranked matches (name words, signatures, docs) under `No exact name match; N full-text matches for "q":`. A query that names a symbol prints no ranked section. A total miss prints the `Did you mean` suggestions.
- `file_skeleton` on a folder returns its layout and main exports.

## find_references: what else a change reaches

After the sites, `find_references` for callers lists up to six sections, each only when it has rows. They never change a site's label, basis, or count. `--json` adds them as arrays.

- `Overrides` and `Overrides of`: the same-named methods in the subtypes and in the ancestors of the owner.
- `Constructions`: the lines that build a class, struct, or record (`Foo()`, `new Foo()`, and the Rust and Go literal `Foo { … }`).
- `Variant uses`: the functions that name variants of an enum, with `names k of m variants`.
- `Registrations`: route facts that register the target as a handler, by decorator or by name (`add_url_rule("/y", view_func=target)`).
- `Tests that call it`: each test with the command that runs it (`pytest`, `cargo test`, `go test`, `vitest`, `jest`, `mocha`, `node --test`, `mvn test`, `gradle test`, `dotnet test`), or without one when no runner can run it alone.

The rules and the run-command forms are in `docs/reach-sections.md`.

## Argument counts (julie-extract 3.8.0)

- julie-extract 3.8.0 writes `arg_count` on each call identifier in Python, JavaScript, TypeScript, TSX, Java, C#, Go, Rust, Kotlin, C, and C++, and `arg_spread` when an argument is a spread or splat. It also stops writing Rust type facts cut out of signature text.
- A call site shows `; N args` after its basis, and `--json` adds `arg_count`.
- A `likely` or `unresolved` Python, Java, C#, Go, Rust, Kotlin, or TypeScript call is `excluded` when its count fits no definition of the target: ``3 args; `render` takes 1-2``. A `proven` site never changes, JavaScript never uses the rule, and a spread site has no count. The range comes from the parameter rows, counts a receiver that a call can pass, and joins the ranges of the same-named methods of every base type, so a call through a base reaches an override.
- A receiver typed `any`, `unknown`, `object` (TypeScript), `Any` or `object` (Python), `dynamic` (C#), or a type parameter no longer excludes a site. A call through `super` or `base` is judged by its receiver, not by julie's link to the caller.
- On the gate projects, excluded sites rise in C# (317 to 419), Java (2407 to 2429), Rust (2627 to 2631), and TypeScript (1852 to 1964). The excluded sites that cover a truth line stay at 2 in Java and 2 in TypeScript. Every other cell is equal.

Every rule is in `docs/argument-counts.md`.

## check_edit and the Stop hooks

- **`check_edit`** (CLI `code-kb check [--base REV]`) compares the working tree with a base revision (`base`, else the commit the session started at, else `HEAD`). It lists each symbol whose shape changed (removed or renamed, parameters, signature, a renamed parameter in Python, Kotlin, C#, and Swift, fields of a class, struct, or record, variants of an enum), the sites that your diff reached, the `proven` and `likely` sites it did not reach, a count of the `unresolved` ones, and the tests to run. A removed or renamed symbol also lists the import lines of its old name, and a changed method lists the overriding members of its subtypes. It checks at most 200 files and 10 symbols, starts no new step after 20 s (the clock is read between steps, so a scan or a refresh that already runs can pass it), and states each cut. The base symbols come from a scan of the base content of the changed files in `.code-kb/check/<pid>/`, which the check removes.
- **`code-kb hook SessionStart`** now also reads the hook JSON on stdin and writes `.code-kb/sessions/<session_id>.json` with the commit the session started at. It does this in any git repository with a commit, also when the project has no index yet (the first session in a new clone or worktree): it then creates only `.code-kb/` with its `.gitignore` and the session file, and no index. Its routing text gains one line (below).
- **`code-kb hook Stop` and `code-kb hook SubagentStop`** run the check against that base. They block the stop with `Before you finish: N sites still use the old shape of …` and up to 15 site lines when a `proven` or `likely` site is outside the diff. They skip the diff they checked last and the diff they blocked on last, never block when `stop_hook_active` is true, and print nothing on any error. `hooks/claude-codex-hooks.json` wires both for Claude Code and Codex.
- **A hook skips the last diff it saw.** The session file keeps the hash of the last diff a hook checked (`checked_diff`, blocked or not) and of the last diff it blocked on (`blocked_diff`). A hook computes the hash first, from the base, the changed files, and their content. When the hash matches one of the two, it prints nothing and runs no scan and no report. The file keeps no longer list: a block on one diff, then a block on a second, then a return to the first blocks again. A turn that changes no file therefore costs 0.07 to 0.08 s (zod, 17 changed files; the first check took 5.35 s), not a whole check. The hooks of one session also take a lock file, so parallel `Stop` and `SubagentStop` hooks block once between them; a hook that cannot get the lock within 2 s prints nothing.
- **What blocks a stop.** Only a site that the check lists, and only a `proven` or `likely` one outside the diff; an `unresolved` site never blocks. By change:
  - Removed or renamed symbol: the sites of the old name, and the import lines that name its file (top-level symbols). When overloads of the name remain, only a call that the removed overload took and no remaining overload takes.
  - Parameters: a call that passes a count the new range rejects (also when your diff touched its line), and a call whose count the index cannot judge that your diff did not reach (a spread call is only counted as unresolved). A signature change (a return type, a parameter type, a bound, or an added or removed `async`, `suspend`, or `static`) lists every call. A renamed parameter lists the calls that still pass the old name as a named argument. A changed method also lists the overriding members of its subtypes. A change of a parameter name, a default value, or an annotation is not a signature change.
  - Added field: only the constructions that must name every field: a Rust literal, `Self` literal, or destructuring pattern, a Go unkeyed literal, a Python dataclass call when the new field has no default, and a Java record call. A removed field lists the constructions that name it.
  - Added enum variant: only a function that has a `match`, `switch`, or `when` in which every arm names a variant and no arm is a fallback. Any other use of the enum counts as unresolved: a fallback arm, an arm that names no variant (`Some(_)`, `(_, _)`, `var other`), a dictionary or `if` chain over variants, or code that builds or compares a variant.
  - Removed enum variant: every function that still names it, at the line of its first use. A function that names only other variants is not a site.
- **A hook never rebuilds the index.** When another `julie-extract` version or extraction level wrote the index, `Stop` and `SubagentStop` print nothing and start no scan. The first write after an upgrade would rescan the index in place (9.26 s on zod, and a large repository can pass the 60 s hook timeout). The next server start or `code-kb` command rebuilds it.
- The routing block gains one line: `- **After you edit**, call `check_edit` before you say the change is done.`

The rules and the known limits are in `docs/edit-check.md`.

## Upgrade

- **The first start rebuilds each index once.** julie-extract changes from 3.7.2 to 3.8.0, and new indexes use the `full` level; the version guard rebuilds an index that another extractor version or level wrote. The rebuild scans into `artifact.db.rebuild` and replaces the index when the scan succeeds.
- **The index grows.** On this repository the `full` index is 137 MB against 70 MB at `facts`, and a scan takes 3.25 s against 2.6 s. On aspnetcore the index grows from 2.0 GB to 3.6 GB, the scan from 40.7 s to 57.6 s, and the peak scan memory from 2.81 GB to 4.75 GB. On hermes-agent: 1.8 GB to 4.0 GB, 55.6 s to 86.8 s, 2.60 GB to 5.38 GB.
- The new hooks arrive with the plugin update. Codex lists four code-kb hooks in `/hooks` (two before); trust them.

## Performance

- `find_references` reads every row of a name and scans the text of the project, where v2.6.0 stopped at the row limit. On the first labeled build, p50 on aspnetcore `ThrowIfNull` went from 8.2 ms to 169.7 ms, and on hermes-agent `_build_api_kwargs` from 19.0 ms to 178.0 ms. A name with tens of thousands of rows stops at the 3 s check limit (hermes-agent `get` takes 3.3 s).
- The reach sections cost at most 6% p50 on the 10 benchmark symbols, and the argument counts at most 3% more. Live `serve` memory after the calls stays within 3 MB and 1 MB of the build before each.
- Live `serve` memory after a heavy callers report is 58.5 MB on aspnetcore (v2.6.0: 38.3 MB) and 51.4 MB on hermes-agent (31.6 MB). On Linux with glibc, `release_freed_memory` calls `malloc_trim(0)` after each tool call, which returns freed heap to the system. It is the only unsafe code, and the workspace lint is `unsafe_code = "deny"`.
- A warm `code-kb check` takes 0.15 to 0.17 s on a two-file change in a small repository (0.19 to 0.25 s on the first check after the edit). On zod (205 MB index), shape edits in 1, 5, and 30 files took 0.23, 0.82, and 4.89 s on the first check (0.18, 0.32, and 1.12 s on the second); the 30-file edit changed 17 files and 15 symbols, and the check covered 10 of the symbols. A 400-file body edit on Newtonsoft.Json, cut to 200 files, took 6.10 s. Shape edits in 30 and 75 files of Newtonsoft.Json took 13.4 and 12.5 s on the first check (6.9 and 9.3 s on the second), each cut at 10 symbols.
- The worst first check recorded was 17.5 s, a 39-file change in a copy of this repository. The CLI spent 14.6 s of it on the reconcile of the index before the check, and the check took 3.0 s. The server keeps the index fresh, so a hook in a running session does not pay the reconcile. 17.5 s is close to the 20 s budget and under the 60 s hook timeout. A hook skips the diff it checked last (see "check_edit and the Stop hooks"), so the cost falls on the first Stop after an edit only. Peak memory of the CLI with its extractor child was 317 MB at most (400 files of Newtonsoft.Json).

## Known gaps

- TypeScript holdout recall is 0.517; most missing sites are `unresolved`.
- Go methods are not linked to their types across files, the Go receiver typer is missing, and Java chain typing is missing.
- A Java field still makes a call to a method of the same name `likely`, not `proven`.
- A C# `base.F()` whose base class is in another file, and a Python `super().f()` whose base class is in the same file, stay `unresolved`.
- A TypeScript abstract or interface method has no argument range.
- `check_edit` does not read calls inside macro arguments or functions passed as values, and it does not list the reads of a removed field.
- `check_edit` sees no field change of a TypeScript `interface` or `type` alias, no change of a Rust tuple struct's element count, no field added to the payload of an enum variant, and no TypeScript type parameter or bound (the TypeScript signature in the index holds neither).
- A new method on a trait or interface is no shape change, so its implementors are not listed.
- A call through an alias of a removed symbol is not listed (Python `import x as y`, TypeScript `import { x as y }`, Rust `use … as`), and Java `import` and `import static` lines of a removed symbol are not listed.
- `check_edit` lists a renamed parameter only in Python, Kotlin, C#, and Swift; named-argument renames in other languages are no shape change.
- A file moved with a plain `mv` and not added to git reports each function in it as removed; `git add` the new path first.
- A `SubagentStop` block stores the same diff hash as a `Stop` block, so a later `Stop` on the same diff is silent. Two sessions on one root can see each other's base in `check_edit`; pass `base` to pick one. After a `julie-extract` upgrade the hooks check nothing until the server or a `code-kb` command rebuilds the index.
- `check_edit` does not see a removed class attribute or `self.` attribute of a plain Python class; only dataclass, record, and struct fields count.

Gaps from the release dogfood round on Flask:

- `check_edit` lists the tests that call a changed symbol, not the tests that reach it through a pytest fixture, and its MCP text folds the sites after 12 rows (CLI `--json` has every row).
- `blast_radius` misses tests that use a function as a value (a Click command callback) and tests that reach a method only through the test client at run time (`Flask.handle_user_exception`).
- A `flask.Flask` type hint is `unresolved` when a class of that name is nested in a test function in another file; `self.application.session_interface` is not typed through `application: Flask`.
- `lookup_symbol` ranks some long concept queries poorly, and a folder `file_skeleton` names julie lambdas (`lambda_48`) among the functions of a file.
- A `self.x = …` write to a property of the same class is an `attribute` row, and `get_symbol_body` calls a write, a getter, and a setter of one name overloads.

The full list is in `docs/edit-check.md`.

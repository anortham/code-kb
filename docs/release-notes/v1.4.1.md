# code-kb v1.4.1

## Highlights

A patch release that returns two latencies to the v1.3.0 level. A benchmark rerun of v1.4.0 against the v1.3.0 and v1.3.1 release binaries found `lookup_symbol` four times slower since v1.3.1 and every read tool a little slower since v1.4.0. Search ranking is unchanged: the v1.4.0 and v1.3.0 binaries rank all 166 evaluation cases the same on the same index. No schema change to `artifact.db`, no index rebuild, and no tool schema change.

## Performance

- **`lookup_symbol` is back to 2.4 ms.** v1.3.1 let an exact name bypass the test-file filter with `name = :query OR (...)`. SQLite planned that as a multi-index OR and ran the test-path predicate over every non-test row, so a lookup took 10.5 ms on this repository's index instead of 2.4 ms. The term is now written as `+name = :query`, which keeps the same rows and stops the planner from using the name index for that arm. A query-plan test guards the statement.
- **Every read tool drops about 0.7 ms.** The v1.4.0 tokens-saved baseline opened a second database connection on every call to sum file sizes. The dispatcher now sums `baseline_bytes` on the connection it already holds.
- **`file_skeleton` is back to 6 ms.** The result count loaded every symbol of the file a second time. A `COUNT` query replaces the second load. Like the loader, an exact-case path wins and the case-insensitive match is only the fallback.

Measured with `scripts/benchmark_quality.py` on this repository, persistent MCP session, p50 of 10 calls:

| Tool | v1.3.0 | v1.4.0 | v1.4.1 |
|---|---:|---:|---:|
| `lookup_symbol` | 2.4 ms | 10.6 ms | 2.2 ms |
| `file_skeleton` (5,900-line file) | 6.2 ms | 10.6 ms | 6.1 ms |
| fresh CLI query, median | 15.0 ms | 21.8 ms | 14.9 ms |

Retained memory is unchanged.

## Compatibility

- **The index is read as is.** No table is added to `artifact.db`, and a v1.3.x or v1.4.0 index needs no rebuild. The pinned extractor stays `julie-extract` 3.1.3.
- **No tool schema changed.** The twelve tools of v1.4.0 keep their parameters.
- **Search ranking is unchanged.** Lookup, search, and the not-found recovery return the same rows as v1.4.0.

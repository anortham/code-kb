# code-kb v1.4.0

## Highlights

`edit_file` is the twelfth tool. It replaces text in any file without reading the file first, so an agent spends one turn on an edit instead of three. Every miss now names the bound workspace and up to three near candidates, so a typo costs one more call and not a search session. Structural-fact categories match only the families their alias names, and facts and literals each get the whole limit. The tokens-saved headline states a baseline for every read tool and the share of calls that baseline covers. No schema change to `artifact.db`, no index rebuild, and no change to the eleven older tool schemas.

## `edit_file`

- **The tool.** `edit_file` takes `file_path`, `old_text`, `new_text`, and the optional `occurrence` of `only`, `first`, `last`, or `all`. The CLI command is the same: `code-kb edit-file src/lib.rs --old "let timeout = 5;" --new "let timeout = 30;"`. The backend also accepts `file` and `path`, `old` and `find`, `new` and `replace`.
- **Two match tiers and no more.** An exact substring match wins. When no exact match exists, the lines of `old_text` are matched with their indentation ignored, and the replacement takes the indentation of the first matched line. There is no edit-distance matching in this release.
- **A second match is refused.** The default `occurrence` is `only`. Two or more matches answer `The file 'src/lib.rs' has more than one match for old_text, at lines 12, 48. Pass occurrence, or add more context lines.` Pass `first`, `last`, or `all` to choose. Overlapping matches count: `ana` in `banana` is two matches, `last` replaces the one that starts last, and `all` replaces the non-overlapping ones. The message names up to ten lines and then the count of the rest.
- **The same write path as `replace_symbol_body`.** Both tools call one shared `commit_file_edit`: syntax check through `julie-extract`, concurrency check, atomic write, re-index, and rollback when the re-index fails. `replace_symbol_body` behaves exactly as in v1.3.1.
- **The answer states what happened.** `Edited src/lib.rs: 1 replacement at line 12 (exact match). Syntax: checked. Touched: connect.` The touched list names the symbols the edited lines belong to.
- **Refused without a write.** An empty `old_text`, an `old_text` equal to `new_text`, a path that is not a file, a file above 8,388,608 bytes, and an edit whose result would pass that size are each refused with one sentence. A match is recorded as an offset, not as a copy of the replacement, so a file with a million matches costs a million offsets and no more.
- **A miss stays out of telemetry.** A failed edit quotes the three nearest file lines to the caller. Telemetry keeps only the first line of that error, so the quoted lines never reach `~/.code-kb/telemetry.db` or a bug report.

## Recovery on a Miss

- **Every miss names the workspace and the nearest candidates.** `get_symbol_body`, `get_symbol_context`, `file_skeleton`, `codebase_outline`, `find_references`, `blast_radius`, `replace_symbol_body`, and `edit_file` share one message: `Symbol 'format_sybmol_body' not found in feat-v1.4. Did you mean one of:` and then up to three rows as ``function `format_symbol_body` (crates/code-kb-core/src/formatters.rs:263)``.
- **A typo still finds the symbol.** The substring search runs first. When it finds nothing, trigram rows from `symbol_names_tri` are kept within an edit distance of the query, so `format_sybmol_body` reaches `format_symbol_body`.
- **A wrong path finds the file.** File candidates match by file name, then by the file-name stem, then by the last two path segments, so `crates/code-kb-cli/src/mcp/format.rs` points at the real `formatters.rs`.
- **Nothing close is said plainly.** When no candidate is near, the message ends `No similar name is indexed; check the workspace and spelling.` instead of a bare "not found".

## Structural Facts

- **An alias matches only the families it names.** `CATEGORY_ALIASES` in `queries.rs` is the whole table: `sql`, `query`, `queries`, `route`, `routes`, `config`, `model`, and `models`. `code-kb facts sql --limit 3` no longer returns `css.media_query.v1` rows, and `route` no longer matches every pattern id that holds the word. An unknown category keeps the substring behaviour, so a raw pattern id still works.
- **The listing starts with the aliases.** `code-kb facts` with no category prints an alias line before the raw pattern list, for example `Aliases: config (12 patterns, 647 facts), model (1 pattern, 1 fact)` on this repository. An alias that matches nothing answers with that listing instead of an empty result.
- **Facts and literals each get the whole limit.** One shared limit used to leave literals with whatever the fact list did not take. Both lists now state when their limit is reached.

## Telemetry

- **Tokens saved covers every read tool.** A skeleton, body, or context answer is measured against its own file. A lookup, search, references, blast-radius, or facts answer is measured against the distinct files its rows name, at most 20 files. A call with no file to point at records no baseline.
- **The coverage figure sits beside the number.** The summary header reads `Est. Tokens Saved: ~N (baseline known for K of M calls)`, and each tool row reads `~N (K/M)`. The new column `est_tokens_saved_known` marks the rows with a baseline; rows written before this release keep 0 and stay out of the known count.
- **Result counts are recorded.** `codebase_outline`, `file_skeleton`, `get_symbol_body`, and `get_symbol_context` now report a result count, so `result_count_known` is no longer 0 for them.

## Documentation

- **Canonical parameter names everywhere.** The routing block taught `codebase_outline(subpath, depth)` and `blast_radius(path="file")`; the schema names are `path` and `file`, and every example in the hook, the skills, and the README now uses them.
- **One routing block.** The binary compiles its own copy at `crates/code-kb-cli/src/routing-block.md`, and that copy was stale. A sync test keeps it byte-for-byte equal to `hooks/code-kb-routing-block.md`.
- **The edit guidance names both tools.** `edit_file` is the default edit path for any text file; `replace_symbol_body` is the path for a whole symbol body. `TODO.md` is now a pointer to `docs/plans/` and `docs/release-notes/`.

## Compatibility

- **The index is read as is.** No table is added to `artifact.db`, the `fts_rule` marker does not move, and a v1.3.x index needs no rebuild. The pinned extractor stays `julie-extract` 3.1.3.
- **No older tool schema changed.** The eleven tools of v1.3.1 keep their parameters. `edit_file` is new, and no tool takes a workspace parameter.
- **Search ranking is unchanged.** The v1.3.0 rerank, stop-word list, tie order, and `--explain` output are the same, and `is_test` and `--include-tests` work as in v1.3.1.
- **What changes for a caller:** nothing is required. A `find_structural_facts` call with `sql`, `route`, or `model` returns a narrower and correct set; a not-found answer is longer and carries candidates; the telemetry header carries a coverage figure; and `edit_file` is available for text edits.

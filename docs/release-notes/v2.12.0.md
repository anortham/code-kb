# code-kb v2.12.0

This release answers an edit in one call. `get_symbol_context` now carries the
callers, the tests to run, the markers that sibling symbols share, and the open
ends. It bundles julie-extract 3.11.0, which adds annotations and read/write facts.
SQLite schema 8 stays.

In the 2026-10 edit study, agents made 46% fewer code-kb calls per task (11.2
against 20.6), and 12 of 12 patches passed. Input tokens stayed level (0.7% more,
inside the spread between repeats). See `evals/edit-2026-10-31-one-call/report.md`.

## One-call edit context

- `get_symbol_context` prints, in order: the target, its signature and
  `Returns: <type>`, the body, `### Callers`, `### Tests to run`,
  `### Conventions`, `### Dependencies`, `### Types`, and `### Open Ends`.
- `### Callers` gives the `Sites:` line of `find_references`, the first 8
  `proven` and 8 `likely` sites, and the calls that list the rest.
- `### Tests to run` lists the tests that call or use the target, with run commands.
- `### Conventions` lists the annotations that at least two thirds of the
  target's siblings carry, and says whether the target has each one. Example:
  a new C# method in a class where every method is `[Pure]`.
- `### Open Ends` lists the symbols that no indexed code calls on a two-level
  walk from the target.
- CLI `context --json` adds `return_type`, `callers`, `tests`, `open_ends`, and
  `conventions`.

## Read and write sites

- `find_references` for a field, property, variable, or constant lists writes
  first in each label group. It tags each site `write`, `read-write`, or `read`,
  and the `Sites:` line counts each group.
- `check_edit` lists the writes first for a changed field.
- The labels and their counts do not change.

## Lookup and skeletons

- A lookup that names one definition ends with its body when the body is short.
- A lookup with `/`, `.`, `{`, or `:` also finds routes (`GET /users/{id}`) and
  config keys (`server.port`).
- `file_skeleton` takes `public_only` (CLI `--public-only`) to show the public surface.
- `find_references` and `blast_radius` print a `Coverage:` line for a language
  that records no reference sites (JSON, Markdown, and other data files).

## Guidance

- The routing text says: `file_skeleton` to orient, `get_symbol_context` for
  the symbol you change, and Read for the file you edit.
- The skill, README, site, and razorback guidance use the same wording.

## Fixes

- A miss on a qualified name with a path filter (`ScriptInfo.get_db`) no longer
  says that the name is defined at a module-level `get_db`.
- julie 3.11.0 writes a JavaScript catch parameter as a write. The callers
  report treats that row as the binding, so it stays excluded and cites its
  own line.

## Speed

- Lookup of a common name on a 988,000-symbol index: 407 ms to 12 ms.
- Ranked search no longer runs its broad query when the narrow one fills the list.
- Receiver proof reuses its owner evidence inside one report. An ASP.NET Core
  callers report went from 4.1 s to 0.95 s and checks more sites.
- Each `blast_radius`, callers report, and context reads one index snapshot.

## Known gaps

From the dogfood round:

- `blast_radius` lists no test for a method that the runtime calls
  (`Flask.handle_user_exception` through the test client). The answer names the
  open ends and says to run the full suite.
- A `flask.Flask` type annotation is `likely`, while `flask.Flask(...)` calls are `proven`.
- A file target's default page can hide its constructor fold, and its
  "returned" count counts groups and tests together.
- `check_edit` leaves out Python `obj.name = …` writes of a removed attribute.
- Concept lookup can fill its limit with rows that match no word.
- A folder outline does not name its unsupported files.
- A skeleton does not show a function nested in a function.
- Callees leave out a call of a subscript result.

From julie 3.11.0:

- Ruby and R write no annotation rows.
- A Python `global` assignment and a first Ruby `@ivar =` are not write sites.
- A Java `total++` is a `write`, not a `read-write`. Erlang has no variable sites.
- julie 3.11.0 writes a Ruby block parameter (`|url|`) as a write. The callers
  report does not model Ruby block parameters, so that row of a method name is
  `likely`, like the reads of the parameter before.

## Upgrade

- The version guard rebuilds each index once with julie-extract 3.11.0.
- Refresh a running MCP session after upgrading.

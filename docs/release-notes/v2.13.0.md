# code-kb v2.13.0

This release bundles Julie 3.12.0 and fixes how code-kb consumes corrected
extractor facts. It also publishes the completed toolkit efficiency study,
including its negative result. SQLite schema 8 and the seven-tool MCP interface
stay unchanged.

## Julie 3.12 integration

- Corrected body boundaries improve C typedefs, Go function types and interface
  methods, Swift function-type parameters, and HTML script bodies.
- Corrected parameter and annotation facts reach T-SQL procedures and VB.NET.
- Stable extracted identities preserve supported rename behavior across line
  shifts and unrelated edits.
- PowerShell reference proof respects explicit and nested module exports.
  Missing or dynamic export evidence remains unproven.
- TypeScript and TSX bodyless ancestor methods retain conservative argument
  checks instead of falsely excluding calls from inferred declaration ranges.
- Existing indexes refresh once for the new extractor. Restart running MCP
  sessions after upgrading.

## Reporting and installation fixes

- Impact reports distinguish a direct reference from a direct caller. Reading
  a method in a tuple no longer claims to invoke it.
- Deeper impact summaries count grouped result rows without presenting that
  number as individual tests.
- Cargo-binstall selects the published ZIP archive on Windows ARM64, matching
  the existing Windows x86-64 setting.

## Toolkit guidance and efficiency evidence

The skill explains when to run broader tests after an incomplete edit-check
result and how Stop hooks remember the last checked and blocked diff. These
guidance changes were not timed.

The shorter-instructions experiment was rejected and removed. Across the frozen
36-trial study, all three arms accepted 12 of 12 patches. The candidate used
14.47% more total input tokens and took 10.35% more time, including indexing,
than current code-kb. Current code-kb also cost more than native tools in that
sample. This release retains no optimization from that experiment and makes no
whole-task efficiency claim. The study used Julie 3.11.0, so it is not a new
performance measurement of the 3.12.0 integration.

See the [complete study](https://github.com/anortham/code-kb/blob/v2.13.0/evals/edit-2026-11-03-toolkit-efficiency/results/report.md),
[Julie integration evidence](https://github.com/anortham/code-kb/blob/v2.13.0/docs/reviews/2026-11-04-julie-3.12-integration.md), and
[release dogfood findings](https://github.com/anortham/code-kb/blob/v2.13.0/docs/reviews/2026-11-04-v2.13.0-dogfood.md).

## Known gaps

- Runtime-dispatched and import-time test paths can be absent from impact
  predictions. Follow the reported open ends and run the full suite for final
  verification.
- Edit checks can miss changed positional bindings and unresolved reads after
  removing a field. Inspect unresolved sites with `find_references`.
- Edit-check test pagination retains at most 50 rows even when more are found.
- Route lookup can append unrelated concept matches and omits automatic HTTP
  methods. Reference reports can spend many lines on documentation matches
  while abbreviating imports.
- Python calls through a subscript result remain incomplete.
- Erlang occurrence-level local-variable facts have no target for the existing
  symbol-based reference interface.
- Julie 3.12.0 marks a T-SQL `SELECT @variable = ...` assignment as a read;
  code-kb preserves that upstream limitation.

# code-kb v2.2.0

code-kb now bundles julie-extract 3.6.0. The extractor records the type of a local whose value comes from a call to a function in the same file, so `find_references`, `get_symbol_context`, and `blast_radius` find calls such as `let workspace = resolve_root(..)?; workspace.nested_project_root()`. This release also makes search, reference, and context output shorter and clearer, and adds a real-project release check. The SQLite artifact schema stays at version 7.

## More callers found (julie-extract 3.6.0)

- A local with no written type now gets the type of its initializer when the initializer calls a same-file function or method with a declared return type. Every general-purpose language is covered. The language's own unwrap layers are removed, for example `?`, `.unwrap()`, `await`, `try`, and `!!`.
- A written type always wins. A generic return, a call that another local or import could bind instead, and a chain that ends in an unknown method record no type, so a wrong caller is not added.
- On 15 real projects, 518 more `local.method()` calls now match a method of the local's type, and no match was lost. Examples: code-kb (Rust) +53, miller (C#) +397, radzen-blazor (C#) +56, zod (TypeScript) +5, flask (Python) +3.
- Wrong type rows are removed. For example, C++ macros such as `JSON_HEDLEY_WARN_UNUSED_RESULT` and keywords such as `friend` are no longer read as types.

## Clearer output

- `search_symbols` and the full-text fallback of `lookup_symbol` print each `Match:` snippet on one line. Before, the snippet stopped at the first line break and could hide the matched word. A snippet that only repeats the signature is left out, and the first line of the docstring is shown instead. Search output is about 10% smaller on the benchmark queries.
- `get_symbol_context` lists under `### Types` the project types of the target's parameters and locals, each as `signature (path:line)` on one line. Before, it listed only the return type's bare name, such as `Result` or `String`.
- `find_references(direction="callees", include_external=true)` shows a long unresolved call chain as its last call (`….ok_or_else`) instead of the whole multi-line receiver expression.
- A misspelled file path in `file_skeleton` and the other file tools now suggests a file whose name is within two edits (`workspce.rs` suggests `workspace.rs`).
- `code-kb hook --help` names the `PreInvocation` event.

## Upgrading

The first call for each project rebuilds its index once, because the index was written by julie-extract 3.5.0. The rebuild takes about as long as a first scan (1 s for a small repository, about 14 s for one with 250,000 symbols), and the old index stays in place until the new one is ready. Restart running MCP sessions after you update.

## Release checks

- `scripts/release-corpus-check.py` compares the previous release with the candidate on 15 real projects in 14 languages plus the julie fixtures. It fails on a failed scan, lost symbols, a slower scan, an index the candidate does not upgrade, a broken tool call, or an index written by the wrong extractor. It lists call-edge and typed-call changes with their source lines for review. `scripts/release-preflight.sh` step 9 requires a fresh PASS.
- `scripts/benchmark_quality.py` sends `project_root` again. Its MCP benchmark failed on every build since v2.1.0.
- Latency, memory, scan time, and index size match v2.1.0 within measurement noise on code-kb, cobra, zod, radzen-blazor, and miller.

## Distribution

The GitHub release provides archives for six targets. Each archive bundles `code-kb` and the pinned `julie-extract` 3.6.0 with a `.sha256` checksum.

# code-kb v2.5.3

This patch release fixes five problems that the tool telemetry showed. It bundles the same julie-extract 3.7.2. The SQLite artifact schema stays at version 7, so no index is rebuilt: an existing index gets the Rust fix below the first time a server or CLI command opens it.

## Fixes

- **Rust methods in an `impl` block in another file.** julie writes no parent for a Rust method when its `impl` block is in a different file than its type. code-kb now links each such method to the type with that name nearest to the method's folder, after every scan, update, and delete. Before this fix, `find_references` gave no callers for these methods, `Type.method` and `Type::method` were not found, `lookup_symbol "Type."` left them out, and `blast_radius` and related tests missed them. In the julie repository, 210 of 219 such methods now link; the other 9 implement types from other crates.
- **A wrong `file_path`.** When `file_path` names a file that does not define the symbol, the error now names the file that does: `` `src/handler.rs` does not define it; it is defined in: `` followed by the definitions. Before, it said `No similar name is indexed`.
- **Slow `get_symbol_context` in large indexes.** The related-tests query now tests the symbol name before the test-path rule. In a C# index with 253,000 symbols, one call took 995 ms before and 122 ms after, with the same answer.
- **Overloads.** When a name selects overloads, which are methods with the same name and owner in one file, `get_symbol_body` returns the body of each overload under one header line, and `get_symbol_context` returns a context for each overload, up to four. Before, both returned an `Ambiguous symbol` error. Same-named members of different owners still return that error with each candidate's `id`. The CLI `--json` output is an array when there are several overloads.
- **A folder as `file_path`.** `get_symbol_body` and `get_symbol_context` accept a folder as `file_path`; it narrows the name lookup to that folder. Before, a folder was refused.
- **Related tests that were not tests.** `get_symbol_context` listed every function in a test folder as a related test, so `Flask.__init__` showed the app factories `create_app` and `create_app2` as tests, and some symbols showed themselves. Now:
  - A function in a test folder that julie does not flag counts only when it is a member of a test class or its name reads like a test. `blast_radius` already uses this rule.
  - A helper defined inside a test counts as that test, so `app_url_defaults` in flask shows `test_app_url_processors` rather than the helper `add_language_code`. A helper inside a setup hook, such as mocha's `before`, does not bring the hook in.
  - A symbol is never its own related test.

## Known gaps

- `blast_radius` `possible` tests for flask `handle_user_exception` include tests that never reach it (for example `test_teardown_request_handler` and `test_baseexception_error_handling`), and miss some that do (for example `test_test_client_context_binding`). Each `possible` row also repeats the same long reason.
- `blast_radius` on flask `src/flask/cli.py` folds most test files into `constructor-only callers` rows, but not `tests/test_subclassing.py` or the example tests that build `Flask` through `create_app`, and it misses `src/flask/__main__.py`.
- `file_skeleton` shows Python in code-kb's language-neutral form (`class Flask extends App {`) rather than in Python syntax.
- `codebase_outline` gives no count for root files it does not index, such as `CHANGES.rst` and `uv.lock`.
- The name and full-text stages of related tests can still add weak matches when fewer than five tests call the symbol, such as doctest's `TestCase::TestCase` for nlohmann-json's `char *`.

## Release checks

- `scripts/release-corpus-check.py` against v2.5.2 on 15 real projects plus the julie fixtures: PASS. Symbols, call edges, and scan times did not change. 26 `get_symbol_context` outputs changed, all in Related Tests and all from the related-tests fix above. Two follow-up fixes came from reading these changes: helpers inside a test now stand for that test, and a setup hook never does.
- One dogfood round in Claude Code on a flask worktree used every tool and checked each answer against the source. It found one wrong answer, the app factories in related tests, which this release fixes. The gaps above come from that round. The Codex session did not run because its login had expired.
- Live checks on copies of the julie (Rust) and miller (C#) indexes: qualified lookup and callers of detached Rust `impl` methods, the overloads of `DashboardIndexFactsCache.Read`, the wrong-file message, and the faster `get_symbol_context`.
- Linux, macOS, Windows, and plugin launcher test suites pass.

## Distribution

The GitHub release provides archives for six targets. Each archive bundles `code-kb` and the pinned `julie-extract` 3.7.2 with a `.sha256` checksum.

# code-kb v2.9.1

This release makes `blast_radius` say when its test list cannot be complete,
and it reaches more of the tests that a change can break. It bundles
julie-extract 3.9.1 and keeps SQLite schema 8.

## Blast radius

- A test, fixture, or setup member that a change touches is now a test to run:
  - a test whose own lines the diff changed (`changed in the diff`);
  - the tests that take a changed fixture;
  - the tests that a test-file target defines.

  Before, an edit to a test body gave "run the full test suite", and a
  changed fixture listed none of its users.
- `### Open Ends` names up to three symbols that the walk reached and that no
  indexed code calls, such as `Flask.__call__`, which the test client reaches
  through the runtime. The list does not show the tests that reach the target
  through them. JSON adds `open_ends`.
- When the walk stops at the depth limit, the answer says how many more tests
  a walk to depth 5 lists: ``The walk stopped at depth 2. A `depth` of 5 lists
  N more tests.`` JSON adds `tests_past_depth`, and `tests_past_depth_cut`
  when that count is a lower bound.
- When the callers report supplies the callers, the walk goes on from them,
  and the report's tests join a list that the walk started.
- The walk finds callers one level at a time and expands each symbol once.
  Against 2.9.0, p95 falls on Gson (2.5 s to 2.0 s) and Newtonsoft.Json
  (3.4 s to 2.0 s). The median rises by 5 to 65 ms. Peak memory per call does
  not change.
- A JavaScript call that julie stores only as an identifier (`res.send()`) is
  a caller when its receiver names the object that the target is assigned on
  (`res.send = function`), and no other definition is assigned on an object of
  that name.
- A diff answer walks from the function, method, or type that holds each
  changed line. It walks from the whole file only when a hunk changes
  module-level lines. It adds the callers-report tests of up to 5 changed
  functions, as a symbol answer does.
- A method of a class defined inside a test maps to that test, as a function
  defined inside a test already did. The `Tests that call or use it` section of
  `find_references` follows the same rule.

## Measurement

- `scripts/bug_replay.py` plants one bug in each of 96 commits of Cobra,
  Express, and Flask, runs the real test suites, and scores the `blast_radius`
  answers against the tests that fail. `evals/bug-replay/README.md` explains
  it, and `docs/bug-replay-baseline.md` has the numbers.
- On those bugs, answers that list tests and miss a failing test without a
  warning fell from 28 of 44 (dev) and 32 of 46 (holdout) to 0. Warnings on
  answers that miss nothing are 11% (dev) and 16% (holdout).
- `scripts/blast_perf.py` times two builds against each other on fixed
  targets of each corpus project.

## Upgrade

- A diff answer lists fewer tests. It no longer walks from every symbol of a
  changed file, which listed 54% to 63% of the Flask and Cobra suites. When
  it cannot be complete, it warns or says to run the full test suite.
- JSON adds `open_ends`, `tests_past_depth`, and `tests_past_depth_cut`.
- Refresh a running MCP session after upgrading. No rescan is needed.

## Known limits

- The default depth stays 2. Cobra tests reach most code through `Execute`,
  more than 2 calls away, so most Cobra answers stop at the depth and say so.
  A depth of 5 finds most of those tests but lists about 70% of the suite.
- Runtime entry points (`Flask.__call__`, `__enter__`, `__exit__`) and
  `express()` stay open ends: the index does not tie them to their callers.
- A test that calls the target through `getattr(app, method)` is not found,
  and no warning names it.
- The dogfood round kept the v2.9.0 gaps: `check_edit` does not report a
  removed attribute; `blast_radius` does not follow tests through the WSGI test
  client or through Click; `flask.Flask` annotations stay `unresolved`.
  [The dogfood report](../reviews/2026-10-22-v2.9.1-dogfood.md) lists every
  finding.

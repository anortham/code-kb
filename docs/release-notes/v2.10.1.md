# code-kb v2.10.1

This patch stops the server from rebuilding a broken index again and again,
names a scan command that a plugin install can run, fixes two wrong callers
labels, and brings the docs, the skills, and the site in line with the seven
MCP tools. It bundles
julie-extract 3.9.1 and keeps SQLite schema 8.

## Index management

No MCP tool manages the index, and none is needed. The index is created on
the first call, a watcher keeps it current, and a reconcile at startup picks
up changes made while no server ran. A live check of creation, the watcher,
ignore files, offline changes, root switches, worktrees, corrupt indexes, CLI
reconcile, and refused roots found one defect, fixed here:

- When the rebuild of an index that SQLite cannot read failed, the next call
  started the rebuild again, and so did every call after it. Now each later
  call for that root returns the same error until the index is readable
  again, as the docs said.
- The error names the running binary, for example
  ``Run `/home/me/.code-kb/dist/2.10.1/x86_64-unknown-linux-gnu/package/code-kb scan --root /repo` to rebuild the index.``
  A plugin install does not put `code-kb` on `PATH`, so the old text named a
  command that did not run.

## Callers report

- A class, struct, enum, interface, trait, union, or type alias defined inside
  a function, method, or constructor is local to it in Python, Rust, Kotlin,
  Swift, Scala, Java, C++, C, Go, and Zig. It is no other definition of a site
  outside that function. In Flask, 13 `app: flask.Flask` annotations were
  `unresolved; 2 definitions` because of a `class Flask` inside one test; they
  are now `likely`.
- A Zig receiver bound by `@import("widget.zig")` reaches that project file.
  Before, `widget.Widget{}` was excluded as an outside import.

## Tools

- The server instructions name `check_edit` as the step after an edit.
- `blast_radius` says that `depth` is at most 5. `find_references` says that
  `file_path` can name a folder. The `check_edit` description no longer
  mentions a filter that it does not take.
- `code-kb --json skeleton <folder>` lists the folder's files. Before, it
  printed `[]`.
- CLI help for `skeleton`, `--symbol-id`, `--depth`, and `logs` matches what
  they do. `code-kb logs` prints the latest lines; it does not stream.

## Docs, skills, and site

- The README explains automatic indexing, the rebuild, the ignore files, the
  paths that are never indexed, and `code-kb scan` as the manual fallback. Its
  tool table lists the parameter aliases that the server accepts.
- The section name is `Tests that call or use it` in every doc and skill.
- The `code-kb-telemetry` and `report-issue` skills run the CLI through the
  plugin launcher when `code-kb` is not on `PATH`. The telemetry skill says
  that rows for `search_symbols`, `codebase_outline`,
  `find_structural_facts`, and `telemetry_summary` are calls from before
  those tools left MCP.
- The site names julie-extract 3.9.1, shows demo output from this release,
  lists every tool parameter, and gives the step to trust the four code-kb
  hooks in Codex.

## Upgrade

- Some callers-report sites change label: uses outside a function no longer
  count a type defined inside it.
- Refresh a running MCP session after upgrading. No rescan is needed.

## Known gaps

The dogfood round on Flask found these gaps. Each answer is true but
incomplete, and each was known in 2.10.0 unless noted.

- `blast_radius` and `get_symbol_context` on `Flask.handle_user_exception` find
  no test, because the tests reach it through werkzeug. The answer names the
  open end and says to run the full suite.
- `blast_radius` on `src/flask/cli.py` misses tests that use `run_command`, the
  module-level `cli`, and `FlaskGroup`.
- `check_edit` test lists for a new required parameter or a removed field can
  be too small when the symbol is used on every request.
- A concept lookup does not credit a word in the folder name (new).
- A call through a subscript (`environ[key](ctx)`) is no callee, because
  julie does not record it.

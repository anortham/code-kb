# code-kb v1.5.0

## Highlights

Expanded QML and Quickshell support, validated on pinned corpus revisions; Qt C++ headers are indexed with known macro gaps; static reference results have documented limits; `.ui` and CMake files are not indexed.

A QML component now renders as its object tree, `find_references` answers the everyday Qt questions (who extends this component, who reads this singleton, who handles this signal), Qt test files are hidden from search by default, and `find_structural_facts` knows the QML vocabulary. No tool was added or removed, and no tool schema changed.

## Qt and QML

- **Skeletons show the object tree.** Any symbol with children renders as a container with its children nested under it, so `ToolTip`, `Row`, `MouseArea`, and `HoverHandler` hold their own properties and handlers instead of flattening into the root. A symbol that starts and ends on the same line stays a leaf, so an inline table in a `Cargo.toml` still prints as one line. Other languages are unchanged.
- **`refs <Component>` lists the components that extend it.** A base-type edge resolves to the base component and never to the component it came from, so a file named after its own base type no longer answers itself. These rows print as `kind: extends`.
- **Qualified names resolve.** An import alias satisfies a pending receiver, so `Kirigami.Page` counts as a use of `Page`. An alias whose import source starts with `Qt` (`QtQuick.*`, `QtQml.*`) never names a workspace symbol, so a Qt module import does not produce a false match.
- **`refs <Singleton>` lists the files that read it.** When the target is a type-like kind, callers include the member accesses whose receiver names the target, grouped one row per file with an occurrence count.
- **Signal handlers are labelled.** A handler row prints as `handler` when its receiver names the owner of the signal, and `handler (candidate)` when the receiver did not resolve. A candidate is a name match, not proof.
- **One row per reference site.** An identifier row is dropped when a relationship row already covers the same site, so a single use no longer prints twice.
- **Qt test files are hidden by default.** The test path rule adds `/autotests/` directories and file names that start with `tst_`. `--include-tests` (MCP: `is_test: true`) shows them, and an exact-name lookup still returns them.
- **New fact aliases.** `find_structural_facts` accepts `signal`/`signals`, `import`/`imports`, `binding`/`bindings`, `component`/`components`, `module`/`modules`, and `pragma`, each mapped to explicit pattern-id families. The raw substring fallback still works.

## Known limits

- Qt C++ headers index, but the Qt macros still break parts of them: `Q_PROPERTY` yields no property symbols, and `Q_SIGNALS:` sections mis-parse. A later extractor release fixes this.
- `.ui` designer files and CMake files are not indexed.
- A QML module imported through an alias resolves to a workspace file only when the alias is not a Qt module.
- A reference list caps at 200 rows. For a heavily used singleton, `refs` groups the member accesses per file, one row per file with a count.

## Compatibility

- **Requires julie-extract 3.2.0.** The QML object tree, inline components, qualified type usages, base-type edges, signal-handler metadata, pragmas, and the Qt JavaScript dialect all come from the extractor. `scripts/julie-pins.json` pins 3.2.0 with the six archive checksums, and every release archive bundles that binary.
- **The index rebuilds once after the pin bump.** The version guard compares the index against the extractor in use, so the first command after the upgrade rescans the workspace and later commands do not.
- **No schema change to `artifact.db`.** Identifier metadata uses the existing `metadata_json` column.
- **No tool schema changed.** The twelve tools of v1.4.1 keep their parameters.

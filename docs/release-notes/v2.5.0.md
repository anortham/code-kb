# code-kb v2.5.0

This release makes `find_references` and `blast_radius` more exact, ranks the tests that matter first, and makes `search_symbols` prefer rows that match more of a multiword query. It bundles julie-extract 3.7.1. The SQLite artifact schema stays at version 7. The first start rebuilds an index that julie-extract 3.7.0 wrote.

## Reference correctness

- A name-only `type_usage` or `member_access` row now matches a target only in the same language, except among JavaScript, TypeScript, TSX, JSX, and Vue, between Razor and C#, and from QML to C++. Before, a Python `Widget` type usage could reach a C++ `Widget` class, and a Swift `body.utf8` was a reference to the HTML `body` element.
- The grouped `(N in file)` rows of a type-like receiver leave out a file that defines its own type with that name. Before, gson `Foo.BAR` in a file with its own `enum Foo` was a reference to another test's `Foo` class.
- A name-only `type_usage` does not match a type when a type with the same name is nearer to the use: nested in an enclosing scope, or at the top level of the same file.
- A resolved call in the same file now counts as receiver evidence. For example, `app = load()` with `def load() -> Server` ties `app.ctx()` to that `Server`, not to another class with the same name.
- A Python lambda caller shows as `<lambda> in <enclosing symbol>`, not as julie's `lambda_312`. A reference site with no caller shows as `(no enclosing symbol)`.
- An ambiguous name now lists each candidate with its kind, source line, and `id=`. The error says to pass that id as `symbol_id` (CLI: `--symbol-id`) to `get_symbol_body`, `get_symbol_context`, `find_references`, or `blast_radius`.
- Two Flask routes on the same line now come in a fixed order.

## Blast radius

- Tests that register an error handler or call `abort` now rank ahead of tests that only share words with the target, and the output keeps that order.
- For a file target, the tests in one test file that reach the target only through a constructor fold into one row for that file, `constructor-only callers (N targets)`. A whole-file run on flask `src/flask/cli.py` no longer lists 312 separate tests.

## Search

- For a query with two or more different words, a row that matches one word is dropped once enough rows that match two or more words rank above it, unless its name holds a rare query word.
- A function or method gets a `field coverage` bonus of 6 when its name, signature, and docstring each support the query and it matches at least half the query words. The rerank now reads the first 640 bytes of a docstring.

## Telemetry

- The saved-token baseline now counts only the files that an answer shows. Before, `lookup_symbol` also counted the files of rows it folds into one line, so a lookup of flask `Flask` claimed 28,588 saved tokens where the shown file supports 16,242.

## julie-extract 3.7.1

- Flask route facts point at the route decorator, not the view's `def` line.
- `super().member` reads carry a `super` receiver, so they no longer match unrelated members.
- An unannotated Python factory that returns a constructed local gets an inferred return type, which code-kb uses as the factory's return type.
- C# files with interpolated verbatim strings such as `@$"...""{x}"""` parse without errors.

## Performance

- Reference checks stop at the result limit.
- The builder scope check is skipped for a call that returns no class.
- The receiver definition scope runs once per candidate. Newtonsoft.Json `refs Value`: 1.52 s before the fix, 0.66 s after, with the same output.
- The error-handler test evidence reads calls through an index. flask `blast-radius handle_user_exception`: 331 ms before the fix, 205 ms after, with the same output.

## Known gaps

- `blast_radius` `possible` tests for flask `handle_user_exception` still include tests that never reach it and miss the malformed-JSON tests in `test_json.py`.
- `blast_radius` on flask `src/flask/cli.py` leaves out `tests/test_subclassing.py` and `src/flask/__main__.py`.
- `find_references` on a widely used class gives its imports only as a count line.
- `lookup_symbol` lists a `self.x = …` write through a property setter in the same class as an attribute.
- `lookup_symbol("AppContext._push")` does not prefix-match the qualified member `AppContext._push_count`.
- `search_symbols` can rank `client` rows for the query `cli`.
- The flask tutorial tests still have no caller rows for `app.app_context()`, `test_client`, and `test_cli_runner`.

## Release checks

- A release review of every change since v2.4.0 found two regressions and two slow queries. All four were fixed before the tag with regression tests (#28).
- `scripts/release-corpus-check.py` against v2.4.0 on 15 real projects plus the julie fixtures: PASS. A source check of every changed output found three wrong reference rows (radzen-blazor, alamofire, gson), fixed before the tag with regression tests (#30). The only new call edges are in radzen-blazor C# files that julie-extract 3.7.1 now parses, and each is a real call.
- One dogfood round in Claude Code and Codex on a flask worktree used every tool and checked each answer against the source. It found one wrong answer, the telemetry baseline, fixed before the tag with a regression test (#29). The gaps above come from that round.
- Linux, macOS, Windows, and plugin launcher test suites pass.

## Distribution

The GitHub release provides archives for six targets. Each archive bundles `code-kb` and the pinned `julie-extract` 3.7.1 with a `.sha256` checksum.

# code-kb v2.2.1

This patch fixes defects that the v2.2.0 release check and the 2.2.1 dogfood sessions found in real projects. It also bundles julie-extract 3.6.2, which fixes Python signatures, Flask route methods, and `cls` calls. The SQLite artifact schema stays at version 7.

## Fixed

- `blast_radius` listed every file under a folder whose name contains the seed file's stem as a test to run. For flask `wsgi_app`, every file under `tests/test_apps/` was listed, including `.flaskenv`, CSS, and HTML files. A stem-matched test file must now match the stem in its own file name. A matched file also counts only when it holds a test or its name has `test` or `spec` as a whole word (`test_app.py`, `app_spec.rb`, `AppTest.java`), so fixture apps such as `tests/test_apps/cliapp/multiapp.py` and templates such as `test/fixtures/user.tmpl` are no longer listed.
- `lookup_symbol Flask` returned 17 import rows in 20. When an exact lookup finds a definition, the import rows with the same name now fold into one line with the count and the first three locations. `lookup_symbol` with `kind="import"` lists them.
- `get_symbol_context` could list a test helper before a real test in the same test file, and the order could change between scans. The related tests now have a stable order: flagged tests first, then by path and line.
- Python (julie-extract 3.6.1): `self.x = v` in a method showed as the class attribute `x = v` in `file_skeleton`. The signature now keeps the receiver (`self.cli = cli.AppGroup()`).
- Python (julie-extract 3.6.2): a function signature showed its return type after a colon (`def run(self): None`). It now uses the arrow (`def run(self) -> None`).
- Flask (julie-extract 3.6.2): `methods=("GET", "POST")` and `methods={"GET"}` gave one route with the default method `GET`, because only a list was read. Tuples and sets now give one route row for each listed method.
- Python (julie-extract 3.6.2): `cls(...)` counted as a call to the enclosing class in every function. In flask `Flask.test_client`, `cls` is a local variable that holds the test client class. `cls` now names the class only when the nearest function that binds it takes it as a parameter.
- A new git worktree copied its parent repository's index and kept the rows of the older `julie-extract` that wrote them, until the next server start. The copy is now rebuilt at once when another extractor wrote it.
- `file_skeleton` left out class attributes such as Python `request_class: type[Request] = Request`. It also cut a value at its first `{`, so `self.blueprints: dict[str, Blueprint] = {}` showed as `self.blueprints: dict[str, Blueprint] =`. A value row now keeps its first line, at most 120 characters, and ends with `…` when the value goes on.
- `codebase_outline` showed a directory at the depth limit as empty (`src/flask/`). It now shows the number of indexed files below it (`flask/ (26 indexed files)`). A file that shows only its first five definitions now says how many it left out (`+85 more`), and a test file shows its number of tests in place of test names.
- `find_structural_facts` shows a route with its method (`POST /auth/register`), so the rows of a route with several methods differ. Before, `@bp.route("/register", methods=("GET", "POST"))` showed as `/auth/register` twice.
- A fact query that matched nothing under a `path` said "in this repository". It now names the path, and telemetry counts the call as an empty result.
- `get_symbol_context` says when it found no related test, instead of leaving the section out.
- `get_symbol_context` matched test names with a raw SQL `LIKE`, where `_` matches any character, so `__init__` listed `test_init_once` and `fake_init_db`. The name now matches literally. A dunder method such as `__init__` gets no tests by name, because the name does not say which class a test covers.
- `get_symbol_body` returned the body with its first line not indented and without the decorators of a Python definition. It now returns the source as written, from the first decorator to the end of the symbol.
- `find_references` showed one row for each access when a line accessed the same member twice. Those rows now merge into one row.
- `file_skeleton` left out Python module variables, and a `self.x = v` row did not say which method set it. Module variables now show, and the row names its method (`in __init__()`, `in run()`). A property whose only child rows are its parameters showed an empty `{ }` body; it now shows its hidden lines.
- `find_structural_facts` showed a Flask route in the normalized form (`/users/{id}`) even when the source spelled it another way. A route now shows the full template with its blueprint prefix when julie-extract knows the prefix, and otherwise the template as written in the source.
- `lookup_symbol` and `search_symbols` listed Markdown links as imports. Documentation links are no longer import rows. Kinds from HTML, SQL, and Markdown now show as `element`, `table`, `section`, and `link`.
- `lookup_symbol` ranked names that contain the query above names that start with it. Exact names come first, then names that start with the query, then names that contain it. `self.x` attribute rows come after definitions with the same name.
- `search_symbols` ranked a function nested in another function as high as a top-level one. A nested function now gets a small penalty, and `--explain` shows it as `+ nested`. Test methods show as `Class::test_name`.
- `find_references` for callers said nothing about imports. It now ends with one line that counts the files that import the target (`Imported 26 times in 24 files: …`).
- `find_structural_facts` with a category that has no facts said only that nothing matched. It now lists the categories that have facts in the index, and for `import` it points to `lookup_symbol` with `kind="import"`.
- `telemetry_summary` cut error messages short, and the "today" and "this month" windows used local time while the rows use UTC. Errors now keep the full text, and every window uses UTC.
- `codebase_outline` shows the number of tests and fixtures in a file. The tool descriptions now say the outline costs "a few hundred tokens".
- Python (julie-extract 3.6.2): decorator arguments stay in a signature on one line (`@app.route("/u/<id>") def show(id)`). An annotation with no value no longer ends in ` = ` (`x: int`). The class argument of `isinstance` and `issubclass` is a type usage, so `find_references` lists those checks.
- `file_skeleton` cut a multi-line value row at its first line, so `self.url_build_error_handlers: list[` lost its type. A value row now joins onto one line, keeps its whole declaration, and cuts only the value.
- `codebase_outline` left out files with no function or class (`__init__.py`, `signals.py`) without a word, and listed an overloaded function once for each overload. Such files now show in one row per directory, and an overloaded name shows once.
- `lookup_symbol` and `search_symbols` showed a method without its class, so twenty `__init__` rows looked the same. A member now shows as `ScriptInfo.__init__`, and a lookup header says how many rows have exactly the query name.
- `get_symbol_context` showed an empty `Signature:` line when the source body already held the whole declaration (F# `type Person = {…}`, Kotlin `fun toString() = …`). The line is now left out.
- `get_symbol_context` on `Flask.__init__` missed `App.__init__`, which `super().__init__()` calls. It also listed both `App.add_url_rule` and `Scaffold.add_url_rule` for `self.add_url_rule()`, and no tests. A `super` call now reaches the parent class, a `self` or `super` call reaches only the nearest class that defines the method, and a constructor gets the tests that build its class.
- `get_symbol_context` listed setup methods, plain classes in test files, and tests for HTML elements as related tests, and matched generic names such as `error` or `Contains` against any test with that word. Related tests now hold only tests and test helpers, and the name match runs only for a name with one definition.
- `find_references` counted `Assert.Contains(...)` as a call to a `Contains` method in the project, and `parsed.error` as a use of a private `error` function in another file. A member access on an unknown capitalized type, or to a function nested in another function or private to another JavaScript or TypeScript module, is no longer a reference. A call to a class defined inside the calling function is now found.
- `find_references` with `direction="callees"` listed rows out of source order. They are now sorted by line.
- `find_structural_facts` named the function around an `add_url_rule` call as if it handled the route. A decorator route now names its `handler`, a call route says `registered in`, and Flask route lists say that Flask adds `HEAD`, `OPTIONS`, and the static route at runtime. The category list keeps string-literal kinds under their own heading and no longer lists the internal `python.decorated_definition.v1` pattern.
- `telemetry_summary` did not say what its token savings are measured against. It now names the baseline: reading each file an answer names in full.

## More callers and tests found

- `find_references` matched `flask.Flask(...)` only when the import metadata had an alias field, which Python imports lack. A receiver that names an import binding in the caller's file now matches a target whose path holds that module. On flask, `Flask` has 163 callers instead of 97.
- A bare call no longer matches a definition in another file when the caller's file defines that name. `class Flask(flask.Flask)` inside a test no longer made the test a caller of `flask.Flask`.
- A `self.method()` call now reaches a method inherited from a base class in another file. `find_references(direction="callees")` and `get_symbol_context` on flask `handle_user_exception` now list `trap_http_exception` and `_find_error_handler` from `sansio/app.py`.
- `blast_radius` labels a pytest fixture as a fixture and adds the tests that take it as a parameter, also through a fixture that takes that fixture. A setup member in another framework, such as an xUnit test-class constructor, is labelled `setup`, and the tests of its class follow it. When the walk reaches a class's `__call__`, which the runtime calls, it adds the tests that build that class, ranked by the words they share with the target. A test that gets the class from a fixture names that fixture. For flask `handle_user_exception`, all eight tests in `tests/test_user_error_handler.py` now appear. Before, the only test was `tests/test_appctx.py`, matched by file name.
- `blast_radius` shows every row that `limit` returns. Before, it showed at most 20 tests and 50 impacted symbols and pointed MCP agents at `CLI --json`.
- `blast_radius` labelled Python `setUp` and `tearDown` methods as pytest fixtures. They are now `setup` rows, and the tests of their class follow them.
- A test that calls a method on an object that a fixture built (`client.get(...)`, where the `client` fixture calls `app.test_client()`) now counts as a caller of that method.
- `blast_radius` added every test that built a class with a `__call__` method, even when the test shared no word with the target. Those tests are now left out. When `limit` is at its maximum and rows remain, the message says to narrow the target, not to raise the limit.
- A stem-matched test file must now match the stem as whole words of its file name, so `app` no longer matches `apps.py` or `happy_test.py`.
- `get_symbol_context` now also finds related tests through references, so a test that calls the target but has another name is listed.
- `blast_radius` listed pytest fixtures and setup methods as tests to run. They are now replaced by the tests they serve. A direct caller is labelled `direct caller`, whole-file rows for matched test files come first, and a cut list says `Showing 20 of 45 likely tests`.
- `blast_radius` tests that reach the target only through `Flask.__call__` gave a reason that fit every test, missed tests such as `test_errorhandler_precedence`, and listed tests that only share the word `exception`. These rows are now marked `possible` and name the words they share. The words also come from the functions the target calls, a test that builds a subclass counts, a fixture declared as `@pytest.fixture(name="async_app")` is found by that name, and generic words such as `find` no longer count. For flask `handle_user_exception`, the answer now finds 45 tests.

## Dogfood round 3

- `blast_radius` `possible` rows now need a test that uses a test client (a `client` fixture, `app.test_client()`, or another name with `client`). A test that only builds the app never sends a request, so it never reaches `__call__`. Checked against the traced flask test run for 272 functions: 92% of `possible` rows are right, up from 73%.
- `blast_radius` listed a matched test file and then the tests inside it. The file row now replaces them.
- `find_references(direction="callees")` names the definition each call reaches, for example `push` → `AppContext.push` (src/flask/ctx.py:416), or lists up to three candidates.
- `find_references("Flask")` stopped at "Ambiguous symbol" because a test defines a local `Flask` class. A name with one definition outside the tests now resolves to it.
- `lookup_symbol("debug")` listed `self.debug = …` in `Flask.run` as a property of `Flask`, and the skeleton of `app.py` listed `self._got_first_request = False` in `run()`. Both write attributes that the base class `App` defines. Lookup, search, and skeletons now leave such writes out. A base class that only declares a type (`cli: Group`) does not count, so `self.cli` in `Flask.__init__` stays.
- `search_symbols` now credits a query word that is the whole name of a member's class, when another word matches the member. `attributes set in Flask __init__` ranks `Flask.__init__` second; before, it was not in the top 20. `search_symbols("Flask", kind="property")` finds the properties of `Flask`. The search evaluation sets give the same ranks as before.
- `lookup_symbol` printed full rows for names that only contain the query. When some rows are named exactly, the other rows now fold into one line of names, kinds, and counts. JSON keeps every row.
- The outline hid a class inside a C# namespace or a Ruby module, and then said the file had no functions or classes. It also cut the file list at 1,000 files in path order, so later folders vanished, and it read symbols for a different set of files than it listed. It now shows those classes, counts only the files it lists toward the cap, and lists at most 40 files per subfolder (the folder you ask for lists all). On a 12,788-file project the outline takes 0.44 s instead of 5.5 s.
- A skeleton shows the functions defined inside a hidden body, such as `create_app { /* … defines `hello` */ }`.
- A multi-line `#define` or other value row without `=` drops its `\` line breaks and is cut to one line.
- Blueprint and router mount facts name what they mount and where (``blueprint_registration `auth.bp` ``).
- The routes note says that HEAD, OPTIONS, and the static route are Flask defaults that the app or a rule can turn off.
- `telemetry_summary` labels its token saving as an upper bound.
- The import fold says "1 import", not "1 imports".

## Dogfood round 4

- `telemetry_summary` calls its token figure "Tokens Saved, upper bound" and says what the baseline is: reading each file an answer names in full.
- Each outline folder row counts the files in it that no extractor reads, for example `docs/ (1 indexed file, 86 unsupported)`.
- `find_references` swapped the callers of two same-named TypeScript functions in zod. `import * as util from "../core/util.js"` never matched `core/util.ts` because of the `.js` extension, and `import { util } from "../helpers/util.js"` matched every file named `util`. A relative import now names only the file its path gives.
- A lookup that folds import rows said "1+ import" when the limit cut only rows with longer names. It now gives the exact count, and says "at least" only when the cut can hide imports.
- A skeleton no longer lists a function inside a C or C++ function body as a nested definition. C and C++ do not allow one, so such a row comes from a misread macro (`JSON_CATCH`). Test sections stay. A repeated name shows once.
- `find_references("parse")` in zod's `parse.ts` stopped at "Ambiguous symbol": an `export` row repeats the top-level `const parse`, and two functions have a local `parse`. A name now resolves to the one definition left without such export rows and function locals.
- A Dart named constructor shows as `Cart.empty`, not `Cart.Cart.empty`.
- julie-extract 3.6.2 names a Python lambda for its own line (it was one line too low), keeps a `#:` comment on a `self.x` attribute in a method, and keeps a `self.x` row in `__init__` beside a property with the same name.


The first call for each project rebuilds its index once, because the index was written by julie-extract 3.6.0. The old index stays in place until the new one is ready. Restart running MCP sessions after you update.

## Release checks

- `scripts/release-corpus-check.py` against v2.2.0 on 15 real projects in 14 languages plus the julie fixtures: PASS. Symbols, call edges, typed receiver calls, and scan times are unchanged. Every changed tool output was reviewed: the Python skeleton and search signatures, the folded import lines, the shorter test lists in `blast_radius`, and the related-test order.
- Dogfood sessions in Claude Code and Codex on a flask worktree used every tool and checked each answer against the source. The fixes above for worktree indexes, skeletons, the outline, routes, fact messages, and related tests come from those sessions.
- The corpus check also found two defects in the first 2.2.1 candidate, fixed before release. The import fold counted prefix matches (`lookup read` folded `readline` as an import of `read`). A file name that contained `spec` inside a word (`search-inspect.py`) counted as a test.

# code-kb v2.1.0

Every MCP tool except `telemetry_summary` now requires `project_root`, the absolute path of the project or git worktree the agent works in. The server reads the root from each call, so a session that moves into a git worktree gets answers from that worktree's index, not from the folder where the server started ([issue #3](https://github.com/anortham/code-kb/issues/3)). The extractor pin stays at julie-extract 3.5.0 and the SQLite artifact schema stays at version 7, so existing indexes are kept.

## Required `project_root`

- Send the same `project_root` on every call, and change it when you move to a worktree or another project. The agent hooks, the `code-kb` skill, and the server instructions tell agents to do this. `workspace` and `root` are accepted as silent aliases.
- A plain path or a `file://` URI is accepted. A subfolder or a file resolves to its project. A relative path, a missing path, a filesystem root, the home directory, and a folder with no project marker and no index are refused. The error names the path and the reason, and a refused call creates nothing.
- `path` and `file_path` are relative to `project_root`, or absolute inside it. An absolute path outside `project_root` is an error that names both paths. A path inside a nested git worktree or submodule is also an error, and it names the nested root to pass instead. A path never switches the project.
- The server keeps one active index and switches when a call names another root. A root with no index gets one on its first call: a git worktree copies and reconciles its parent repository's index, and anything else runs a full scan. A call waits up to 5 s. If the index is not ready, the answer is `Indexing <root> started; call again in a few seconds.`
- The server no longer takes a root from the MCP `initialize` request or from a path argument. Both methods went stale when a session changed directory.

## Setup changes

- `--root` is optional for every client, including GUI apps. When you pass it, the server prepares that project's index at start. When a GUI app starts the server in its install folder or in the home folder, the server skips that start-up index.
- `--db <file>` now pins the index file of the launch root only. Calls for other roots use their own `<root>/.code-kb/artifact.db`.
- The CLI refuses a home directory or a filesystem root the same way the tools do, and creates a missing index only for a root the tools accept. `code-kb scan` still runs on any root you give it.
- A server or CLI started in a folder the tools refuse writes its log to `~/.code-kb/logs` and leaves no `.code-kb` folder there. `code-kb logs` reads the same folder.

## Bug fixes

- An unknown tool name gets `Unknown tool` before any missing-parameter error.
- A failed first scan of a root that cannot be scanned again no longer promises a retry. The error says how to recover.
- Offline reconcile errors at start-up are written to the log. Before, the server dropped them without a record.
- A background index build that finishes after the session switched to another project no longer keeps its file watcher running.
- On Windows, a drive-relative `project_root` such as `C:src` is refused as a relative path.
- A language project inside a home folder that is itself a git repository (a dotfiles home) resolves to that project, not to the home folder.

## Upgrading

Restart running MCP sessions after you update. Agents discover the new `project_root` parameter from `tools/list`; no MCP configuration change is needed. Scripts that call the tools directly must add `project_root`.

## Distribution

The GitHub release provides archives for six targets. Each archive bundles `code-kb` and the pinned `julie-extract` with a `.sha256` checksum.

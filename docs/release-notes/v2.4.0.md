# code-kb v2.4.0

This release makes `find_references` and `blast_radius` more exact about which class a member access reaches, labels uncertain rows, and makes reference queries on large projects much faster. It still bundles julie-extract 3.7.0. The SQLite artifact schema stays at version 7; the first call adds three indexes to an existing index.

## Reference correctness

- A member access (`runner.invoke`) now uses the same receiver evidence as a pending call: a local variable or pytest fixture that a call builds, the builder's return type, the nearest inherited override, and the module that an import names. A proven different receiver is left out. For example, `Runner.invoke` no longer lists a `Shell().invoke` read, and a base-class instance no longer references a subclass override.
- A member access that the index cannot tie to one receiver shows as `member_access (candidate)` in text and JSON. Supported rows come before candidates, and candidates add no impact edges in `blast_radius`.
- julie writes no receiver for `super().x` reads or for Bash, CSS, HTML, Vue, and XML names. Such a row is a candidate for a class method and is never a caller of anything else. Before, an HTML element's references could list every other page's element of the same name, and CSS selectors such as `.post` could match `Scaffold.post`.
- A receiver's class is checked against the import that names it. A relative package import (`from . import Flask`) matches any file in that package, and a class defined after a same-named import in its file is the one that name binds.
- Duplicate rows merge in the query, so a limit of 20 returns 20 rows when that many exist.

## Performance

Measured with interleaved A/B runs against v2.3.0 on the same indexes:

| Call | v2.3.0 | v2.4.0 |
|---|---:|---:|
| hermes-agent `find_references get` (file scoped) | 20.0 s | 3.4 s |
| hermes-agent `blast_radius run_agent.py` | 7.4 s | 4.6 s |
| hermes-agent `get_symbol_context execute` | 71 ms | 52 ms |
| flask `find_references FlaskCliRunner.invoke` | 5 ms | 17 ms |
| flask `get_symbol_context FlaskCliRunner.invoke` | 12 ms | 30 ms |

Three new SQLite indexes carry the large-project gain; they add up to 3% to the index file. The added receiver checks cost 5 to 20 ms per reference call on small projects. Retained memory is 1 to 3 MB higher.

## Known gaps

- `blast_radius` `possible` tests are still picked by shared words; for flask `handle_user_exception` they miss tests that reach it only through a registered error handler, and a whole-file run on `src/flask/cli.py` lists 312 tests.
- `search_symbols` can rank a row that matches only one query word inside the top 20.
- Python lambdas show julie's name, such as `lambda_312`.
- Route facts point at the view's `def` line, not the decorator, and the method order differs between routes.
- A factory with no return annotation (the flask tutorial's `create_app`) does not type its result, so `app.app_context()` in the tutorial tests has no caller row. v2.3.0 found these only through an unrelated `create_app -> Flask` in another example.
- julie's C# grammar fails a file that contains `@$"...""{x}"""`, so member accesses in such a file have no caller and show as candidates.

## Release checks

- One dogfood round in Claude Code and Codex on a flask worktree used every tool and checked each answer against the source. The sessions found no wrong answers; the gaps above come from it.
- `scripts/release-corpus-check.py` against v2.3.0 on 15 real projects plus the julie fixtures: PASS. Symbols and call edges are unchanged; every changed tool output was checked against its source.
- A caller sweep over every flask class method compared v2.3.0 and v2.4.0 row by row. It found three wrong answers that were fixed before the tag, each with a regression test. A Codex review found a fourth, also fixed.
- Linux, Windows, and plugin launcher test suites pass.

## Distribution

The GitHub release provides archives for six targets. Each archive bundles `code-kb` and the pinned `julie-extract` 3.7.0 with a `.sha256` checksum.

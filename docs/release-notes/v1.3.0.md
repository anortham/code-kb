# code-kb v1.3.0

## Highlights

The search rerank scores each query term once, from the strongest field that holds it, weighted by how rare the term is across the whole index. A row that covers three different query words now beats a row that repeats two of them across its name, signature, and docstring, and prose words such as `into` or `between` no longer outweigh the content words beside them. `search_symbols` and `lookup_symbol` also stop returning rows from test files by default: a path rule hides helpers, fixtures, constants, and imports inside a test file together with the test functions the extractor flags. No schema change to `symbols`, no index rebuild, no change to any MCP tool schema.

## Search Ranking

- **One credit per query term.** For every query term the rerank takes the strongest evidence a row holds: a whole token of the name (3), a stem match in the name (2), a hit in the signature or the first 400 bytes of the docstring (1), or a substring of the name (1). Nothing is counted twice, so repeating a word across fields earns no more than holding it once.
- **Index-wide term rarity.** Each term's credit is weighted by `ln(1 + N / (df + 1))`, where `df` is the number of indexed symbols whose name, signature, or docstring holds the term. The counts come from a new `fts5vocab` table over `symbols_fts`, created on the next writable open of an existing index (it stores nothing and needs no rebuild); an index without it falls back to a `MATCH` count per term. The lookups cost about 100 µs per query.
- **Whole-name and all-words bonuses stay.** A name equal to the collapsed query adds 100; a name whose tokens cover every term as whole tokens or stems adds 60, so identifier-shaped queries keep their order from v1.2.0. The kind, path, documentation-row, and test-intent priors are unchanged.
- **Function words earn nothing.** The stop-word list grows from 23 to 116 English function words (`was`, `how`, `so`, `whether`, `another`, and the rest), because the rarity weight is computed over code text, where such words are rare, and a method named `_was` used to win a prose query on that word. Directional words that live inside identifiers (`up`, `down`, `out`, `over`, `under`, `back`, `into`, `onto`) stay content words, and a query made only of stop words still searches them.
- **A whole-name match is worth 100 only for definitions.** A constant, enum member, variable, property, or namespace whose name equals a one-word query now gets the all-words bonus of 60, so `matches_glob_pattern` outranks the enum member `Glob` on `glob`, and `fileSha256` outranks the constant `SHA256`.
- **Ties break by name strength, then public before private, then BM25.** The sum of the per-term name strengths decides equal scores; a name that does not start with `_` then beats one that does, so `create_skill` outranks `_create_skill`; the word index's BM25 decides last.
- **Explain adds up.** `code-kb search --explain` prints `score = terms + name <tier>(<strength>) <bonus> + kind + path [+ doc] [+ test]` and then every term with the field that credited it, for example `terms strip=name:3 ansi=doc:1 escape=doc:1 codes=none:0`. The JSON `explain` object carries `term_score`, `name_bonus`, `name_strength`, `terms`, and the IDF `word_weights`; the coverage fields of v1.2.0 are gone. The MCP tool schema is unchanged and takes no `explain` parameter.

## Test-File Rows

- **Hidden by default.** `julie-extract` sets `is_test` only on callable symbols that carry a test marker, so a helper or a constant inside a test file stayed visible. `code-kb` now adds its own path rule beside the two flags: `is_test_path` in `crates/code-kb-core/src/queries.rs` and its SQL mirror `test_path_predicate`, which a unit test over 44 paths keeps rule for rule identical.
- **The rule.** Back slashes become forward slashes, and the path is split into the directory part and the file name. A directory rule matches when the directory part, framed by slashes, contains `/test/`, `/tests/`, or `/__tests__/`, so it matches at the repository root too. A file-name rule matches when the lowercased file name starts with `test_` and ends with `.py` or `.rb`; when it contains `_test.`, `.test.`, or `.spec.`; when it is exactly `test.rs` or `tests.rs`; or when the raw file name ends with `Tests.cs`.
- **Production files keep their rows.** A file-name rule never reads a directory name, so `src/protocol.spec.v1/parser.rs` and `pkg/test_support/runtime.py` stay visible. The `Tests.cs` rule is case-sensitive, so `Contests.cs` stays visible. The bare endings `test.rs`, `tests.rs`, and `test.go` are not rules, because they hid `likely_tests.rs`, `latest.rs`, and `latest.go`. The `test_` prefix rule applies to Python and Ruby only, because a Rust module such as `test_quality.rs` is production code.
- **Lifted the same way as before.** `is_test: true` on the MCP tools and `--include-tests` on the CLI show test functions, test containers, and rows from test files again.
- **`blast_radius` inherits the corrected rule.** Its likely-tests list already used `is_test_path`; the rule as it stood needed a slash before `tests/` and so matched 225 of the 384,268 symbols under a root `tests/` directory on the hermes-agent index.

## Evaluation (`docs/plans/023-search-v1.3-rerank-ties-stop-words.md`, results section)

Every miss on the plan 021 and plan 022 builds was reviewed for label quality first (89 cases across the four sets: 50 kept, 39 gained a second legitimate answer such as an async twin, the public entry point in front of a helper, or the entry method that carries a tool's description; none removed), so v1.2.0 and v1.3.0 are measured on the same reviewed labels. Numbers are file@1 / file@3 / symbol@1 / symbol@3, on the released v1.2.0 binary and this release, same machine.

| set | v1.2.0 | v1.3.0 |
|---|---|---|
| regression (plan 019, 26) | 25 / 26 / 22 / 26 | 26 / 26 / 23 / 26 |
| development (89) | 72 / 87 / 68 / 85 | 82 / 84 / 76 / 83 |
| development-2 (60, README wording) | 29 / 43 / 27 / 39 | 40 / 52 / 35 / 47 |
| development-3 (40, README wording, the former sealed set) | 20 / 27 / 15 / 22 | 21 / 29 / 17 / 25 |
| acceptance-3 (40, sealed README wording, one run, summary only) | 13 / 17 / 8 / 10 | 14 / 19 / 10 / 12 |

- The regression set has no case lower than v1.2.0. Every file@1 and symbol@1 column is above v1.2.0; development file@3 and symbol@3 stay two to three cases below it.
- The sealed set is hard for any lexical engine: 19 of its 40 answers share no word with the name, signature, or docstring of the answer on either build. v1.3.0 leads it by one file@1 and two symbol@1.
- The scorer was chosen on a grid over the term credit for signature and docstring hits (2, 1.5, 1, 0.75, 0.5) and the weight source (index-wide IDF, uniform, candidate-sample rarity); plan 022 records the whole grid. The stop-word, tie-order, and member-bonus rules were then chosen by an offline simulation over the cached candidates of all 189 tuning cases; plan 023 records every lever measured, including the ones not built (parent and file-name context, a body-word index, an all-terms bonus, damped rarity).
- **Warm `code-kb search` p50** on the code-kb checkout: 20 ms (v1.2.0: 19 ms in the same session).
- **Live `serve` RSS** after 20 searches: 28.0 MiB (v1.2.0: 30.4 MiB; both move by about 2 MiB between runs).

## Compatibility

- **`symbols_fts`, `symbol_names_tri`, `skipped_files`, and their triggers are unchanged**, and the `fts_rule` marker does not move. A v1.2.0 index is read as is. The only addition is the `symbols_fts_vocab` virtual table, created with `CREATE VIRTUAL TABLE IF NOT EXISTS` on the write path; it is a view over the FTS index and holds no rows of its own.
- **No MCP schema change.** `search_symbols` and `lookup_symbol` keep exactly `query`, `path`, `kind`, `is_test`, and `limit`. Explain stays CLI-only, and its JSON shape changed as described above.
- **`blast_radius` and `find_related_tests` keep their test rows.**
- **What changes for a caller:** results for concept queries move, a search that used to return a helper from a test file now returns production code, and `is_test: true` or `--include-tests` restores the test-file rows.

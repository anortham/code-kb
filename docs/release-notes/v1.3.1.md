# code-kb v1.3.1

## Highlights

A patch release for the lookup path. `lookup_symbol` and `code-kb lookup` now return the row a query names, resolve a qualified name against the whole parent chain, accept a directory as a path filter, and report a failed full-text fallback instead of printing an empty answer. No schema change to `symbols`, no index rebuild, and no change to any MCP tool schema.

## Bug Fixes

- **An exact name lookup returns the row it names.** The v1.3.0 path rule hid every row from a test file, including the row whose name the query spelled in full. `code-kb lookup test_format_search_results_discloses_a_reached_limit` answered "No exact name match" although `code-kb body` with the same name found the symbol. The qualified branch of `search_symbols_scoped` no longer applies the test check, and its SQL branch applies the test filter only to rows whose name differs from the query. Substring and prefix lookups still hide test rows by default, and `is_test: true` / `--include-tests` still shows them.
- **A qualified name checks the whole ancestor chain.** Only the segment beside the terminal name was checked, so `code-kb body DefinitelyMissing::McpServer::sanitize_symbol_name` returned the real method. The resolver now splits the whole name. For a name with more than one ancestor segment it walks `parent_symbol_id` upward and keeps only candidates whose real parent chain holds every ancestor segment in order. Gaps between named segments are still allowed, and a name with one ancestor segment keeps the old path and cost. A name with more ancestor segments reads up to 2000 candidates before the walk, so a chain that sorts past the old 25-row cap is still found and a second valid chain past it still raises the ambiguity error.
- **A path filter on a qualified name accepts a directory prefix.** The qualified resolver matched an exact file path or a file-name suffix only, so `code-kb lookup McpServer::sanitize_symbol_name --path crates/code-kb-cli/src` answered "No exact name match" while the same query without `--path` found the method. The path clause now also accepts a directory prefix, in both slash styles, the same three shapes `search_symbols_scoped` accepts. The exact-path filter used by the edit path still requires the exact file.
- **A failed full-text fallback is reported.** The `lookup_symbol` fallback called `unwrap_or_default()` in the MCP handler and in the CLI, so a database error printed as "No exact name match; 0 full-text matches". The MCP handler now returns an error that carries the query error text, the CLI propagates the error and exits non-zero, and telemetry records the call as an error.

## Compatibility

- **No MCP schema change.** `lookup_symbol` keeps exactly `query`, `path`, `kind`, `is_test`, and `limit`. The `is_test` description states the new exception.
- **The index is read as is.** `symbols_fts`, `symbol_names_tri`, and their triggers are unchanged, and the `fts_rule` marker does not move.
- **Search ranking is unchanged.** The v1.3.0 rerank, stop-word list, tie order, and `--explain` output are the same.
- **What changes for a caller:** a lookup that spells a test symbol's name in full now returns it without `--include-tests`; a wrong ancestor segment now returns no match; a directory `--path` now scopes a qualified lookup; and a broken search index now returns an error instead of an empty answer.

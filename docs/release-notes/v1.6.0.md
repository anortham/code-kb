# code-kb v1.6.0

## Highlights

First-class Qt support: QML, `qmldir`, `.qmltypes`, Qt JavaScript, and Qt C++ headers, validated on pinned corpus revisions; static reference results have documented limits; `.ui` and CMake files are not indexed.

v1.5.0 closed the QML side of plan 025. This release closes the Qt C++ side. julie-extract 3.3.0 blanks Qt's macros before the parse, so a Kirigami header parses clean and carries its Qt evidence as ordinary rows: a `property` symbol per `Q_PROPERTY`, an `event` symbol per signal, `qt_slot` and `qt_invokable` on the members that declare them, and the QML element name on the class. `find_structural_facts` gains a `property` alias. No tool was added or removed, and no tool schema changed.

## Qt C++

- **A `Q_PROPERTY` is a property row.** Every `Q_PROPERTY(...)` in a class or struct body is a `property` symbol named by the property, parented to its class, with the whitespace-collapsed macro text as its signature. `lookup_symbol` of the property name returns that row. The `READ`, `WRITE`, `NOTIFY`, `MEMBER`, `RESET`, and `BINDABLE` accessors, and the `CONSTANT`, `FINAL`, and `REQUIRED` flags, are recorded as metadata.
- **A signal is an event row.** A method declared in a `Q_SIGNALS:` or `signals:` section, or prefixed by `Q_SIGNAL`, is an `event` row with public visibility, not a `method` row. `file_skeleton` marks the row `// event L47-47`, because its C++ signature reads like a method; a QML `signal` row already spells its kind and is unchanged.
- **Slots and invokables are marked.** A method in a `Q_SLOTS:` or `slots:` section carries `qt_slot`, and a `Q_INVOKABLE` method carries `qt_invokable`. A method can carry both.
- **A class records what it declares to QML.** `Q_OBJECT`, `Q_GADGET`, `QML_ELEMENT`, `QML_NAMED_ELEMENT`, `QML_SINGLETON`, `QML_UNCREATABLE`, `QML_ATTACHED`, and `QML_ANONYMOUS` each set a metadata key on the class.
- **A forward declaration emits no row.** `class ColumnView;` names no new type, so `lookup_symbol("ColumnView")` returns one row, at the definition.
- **One row per declared constructor and destructor.** A declaration and its inner declarator no longer both produce a row at the same line, and a `private:` constructor keeps its real visibility.
- **Declared return types survive.** A member reads `QQuickItem *contentItem() const`, `const QString &name() const`, and `QList<int> *items()`. `override` and `final` are trailing specifiers again, and a sibling member's `explicit` or `static` no longer leaks onto every method of the class.
- **New `property` fact alias.** `find_structural_facts` accepts `property` and `properties`, mapped to the `.property_declaration.` and `.qt_property.` pattern families, so one category answers for QML and for Qt C++. The raw substring fallback still works.

## Known limits

- A project macro that the extractor does not know is not blanked before the parse, so it can still cause a parse diagnostic. Diagnostics remain on both C++ corpora: 31 on Kirigami and 298 on plasma-workspace, down 97% and 94% from julie-extract 3.2.0. None is macro-shaped; a file-local `#define` used as a statement accounts for 12 of Kirigami's 31.
- `Q_DECLARE_FLAGS(Modes, Mode)` and a `Q_OBJECT_BINDABLE_PROPERTY(...)` member are blanked as whole statements, so the typedef and the member emit no row.
- A macro used inside a line, such as `Q_ARG(bool, true)`, is left alone by design, because rewriting it would delete real arguments.
- `.ui` designer files and CMake files are not indexed.
- A reference list caps at 200 rows. For a heavily used singleton, `refs` groups the member accesses per file, one row per file with a count.

## Compatibility

- **Requires julie-extract 3.3.0.** The macro pre-pass, the property and event rows, the slot and invokable metadata, the class metadata, and the `cpp.qt_property.v1` facts all come from the extractor. `scripts/julie-pins.json` pins 3.3.0 with the six archive checksums, and every release archive bundles that binary.
- **The index rebuilds once after the pin bump.** The version guard compares the index against the extractor in use, so the first command after the upgrade rescans the workspace and later commands do not.
- **No schema change to `artifact.db`.** The Qt evidence uses the existing `metadata_json` column and the existing `structural_facts` table.
- **No tool schema changed.** The twelve tools of v1.5.0 keep their parameters. The only output change is the `// event` marker on a skeleton row whose signature does not spell `signal` or `event`.
- **New `property` fact alias.** `find_structural_facts(category="property")` and `code-kb facts property` are new spellings of an existing tool. No parameter changed.

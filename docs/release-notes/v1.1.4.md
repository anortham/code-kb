# code-kb v1.1.4

## Highlights

Search ranking is measurably better, every result set is bounded, and the release ships for six targets, including Linux ARM64 and Windows ARM64. A `/report-issue` skill turns a diagnostic bundle into a GitHub issue in one step.

## Search Ranking

- **Identifier splitting:** `search_symbols` splits camelCase and digit boundaries in the query and keeps each identifier unsplit as an alternative, so `ValidateSyntax` finds `validate_syntax` and `validate syntax` finds `validateSyntax`. English stop words are dropped, and two- or three-word queries also try their concatenation.
- **Code before documentation:** when every word matches only markdown sections, the search falls through to an any-word query, so `syntax validation before edit` returns `validate_syntax` first instead of five doc sections.
- **Exact name first:** an exact, case-insensitive name match sorts ahead of longer names that share its tokens.
- **Related tests stay strict:** `find_related_tests` matches the symbol name as typed, so `isReady` does not pull in `test_ready`.
- Measured against Julie 8.0.0 and Miller lexical search on a tuning set and a held-out set (`docs/plans/019-search-quality-comparison.md`). code-kb now beats Julie's lexical search on both sets at symbol level and stays 4 to 9 times faster. Miller still wins the held-out set on camelCase names split at index time; that work is planned for v1.2.

## Bounded Output and Telemetry

- **Result limits are validated (0 to 200)** in core queries, MCP schemas, and CLI arguments. An oversized limit can no longer wrap into an unbounded SQLite `LIMIT`.
- **Qualified lookups** honor the symbol-kind and test filters, and facts plus literals share one requested allowance instead of each consuming it.
- **Compact output says when the cap was reached** in search and lookup results.
- **Telemetry reports logical result counts**, records known empty answers as successful empty results, and no longer invents savings baselines. `telemetry_summary` and `code-kb telemetry` add phase-separated latency (startup, reconciliation, query), percentiles, and a `--version` filter (`current`, `all`, or an exact version).
- The health review behind these repairs, with measurements, is in `docs/2026-09-20-health-review.md`.

## Diagnostics

- **`code-kb bug-report`** bundles extractor, schema, and index-level facts, the recent log tail (`--logs N`), and a `--description`. Home directories and secrets are redacted.
- **`/report-issue` skill** files that bundle through `gh issue create`, and the repository gains a bug-report issue template.

## Distribution and Build

- **julie-extract 3.1.3** is pinned. Release archives ship for six targets: Linux x86_64 and ARM64, macOS Apple Silicon and Intel, Windows x86_64 and ARM64. CI runs on `ubuntu-24.04-arm` and `windows-11-arm` as well.
- **Launcher memory:** `bin/code-kb-launcher.cjs` replaces itself with the `code-kb` process through `process.execve` where Node supports it, so the plugin no longer keeps a Node parent process alive.
- **Release gate:** the release workflow requires green CI on the exact tagged commit and matching versions in Cargo and every plugin manifest before it builds or publishes.
- **Benchmarks:** persistent-MCP and disposable large-corpus benchmarks, and a cross-language answer-quality corpus with absent-match cases and predicted tests.
- The published memory figure is the measured value, about 25 MB RSS on a live server.

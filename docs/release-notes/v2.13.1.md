# code-kb v2.13.1

This patch stops `check_edit` and the Stop hook from treating a moved function
or type as removed. It bundles julie-extract 3.12.0 and keeps SQLite schema 8
and the seven-tool MCP interface.

## Moved symbols

The edit check compares each changed file with its base. A function that an
agent moved to another file had no pair in its old file, so the check reported
it as removed and listed every call left in the old file as a `proven` site.
The Stop hook then blocked the turn, and the agent had to explain that no
change was needed. Each new edit made a new diff, so the block came back.

- When the old file now imports the name from the file the symbol moved to,
  the import decides each call there. This covers Python `from … import` and
  CommonJS `const { f } = require(…)`. ES `import` already worked.
- A symbol that reappears with the same key in another changed file of the
  same scope pairs with the new symbol: a Go package (the folder), a Java,
  Kotlin, or Scala `package`, a C# namespace, or a SwiftPM target. Only a real
  shape change reports, under the new file, such as a moved Go function that
  also gained a parameter.
- A move to another package, namespace, or target, and a move in a language
  whose callers import the file (Python, JavaScript, TypeScript, Rust), still
  reports as removed when a caller imports the old file.
- A real removal stays flagged, also when an unrelated module or another Go
  package defines a function with the same name.

A Swift file outside a SwiftPM target (an Xcode project) has no known module,
so a move between two such files still reports as removed.

## Removed Python fields

The release dogfood round removed `Flask.response_class` and
`ScriptInfo.create_app` and compared `check_edit` with the source.

- A use of the removed field in a type position
  (`isinstance(rv, self.response_class)`) is now a site. Before, the check
  left it out, so its count was one short.
- A base class that only annotates the name (`response_class: type[Response]`)
  no longer counts as a definition. Such an annotation binds nothing at run
  time, so the `self.` reads in the subclass keep their proof.
- A call of a removed field (`self.response_class(rv)`) is no longer proven
  when a base class still assigns the field, since the call still works. This
  could make the Stop hook block on correct code.
- A `self` read reaches only the caller's class and its ancestors. A
  same-named attribute of an unrelated class no longer hides it, and a class
  that writes its own `self.create_app` keeps its own reads out of the list.

Flask: removing `response_class` now lists all 12 reads (4 proven, 8 likely),
and removing `ScriptInfo.create_app` proves both reads in `load_app`.

## Known gaps from the dogfood round

- `blast_radius` and `get_symbol_context` find no test for a method that only
  the WSGI runtime reaches (`Flask.handle_user_exception`); they name the open
  end and say to run the full suite.
- The whole-diff `blast_radius` follows calls, not reads of a removed field.
- `check_edit` keeps 50 test commands and ranks constructor tests early.
- `flask.Flask` annotations after `import flask` stay `likely`.
- Concept search and route lookups still add weak word matches.

# code-kb v2.13.3

This patch bundles julie-extract 3.12.1, which fixes the Razor comment parse
error behind the false "removed" reports of v2.13.2, and fixes one `check_edit`
gap found in the release dogfood round. SQLite schema stays 8 and the MCP
interface keeps its seven tools.

## julie-extract 3.12.1

- A `@* … *@` comment first in an `@if`, `else`, or `@foreach` block, first in
  an element, or first in a `@code` block no longer turns the whole Razor file
  into one parse error ([julie-extractors #29](https://github.com/anortham/julie-extractors/issues/29)).
  Such a file now indexes every `@code` member, so `check_edit` and the Stop
  hook compare real rows instead of skipping the symbols the parse lost.
- Code inside a Python `@property` (also `@x.setter`, `@cached_property`) or a
  Dart getter or setter now belongs to that property. `find_references` names
  `AppContext.session` as the caller of the write `session.accessed = True` in
  Flask, where 3.12.0 named the class `AppContext`, and the `blast_radius` walk
  steps from the property to its readers.
- A 3.12.0 index is rebuilt once on the first call, as for every extractor
  change.

## find_references

- A member read on the line that defines a local variable of the same name is
  a site again (Flask: `cli = self.app.cli` in `FlaskCliRunner.invoke` for
  `Flask.cli`). Before, the definition-line rule dropped it with the
  definition.
- A member access on a call result (`info.load_app().cli`) is no longer
  excluded as a use of a module-level variable of the name in the same file
  (`cli = FlaskGroup(...)`); julie records no receiver for it, so the site is
  `likely (receiver not typed)` or `unresolved`, like a call on a call result.

## check_edit

- When a check lists several changes, their direct tests now take turns in the
  50 commands the check keeps, so a change with many tests (Flask: the 79
  constructions of `Flask` after a removed field) no longer pushes the direct
  test of a later change (`test_get_debug_flag` for a new `get_debug_flag`
  parameter) out of the list.
- For a class, struct, or record that lost a field, the tests that read that
  field are now among the tests to run, right after the tests that construct
  the type. Before, the check listed such a test as a `proven` site and then
  dropped it from the 50 commands it keeps, while deeper tests of the walk
  stayed (Flask: `tests/test_basic.py::test_session_accessed` for the removed
  `SessionMixin.accessed`).

## Known gaps

The dogfood round against Flask found these gaps; none is a wrong answer:

- `blast_radius` and `get_symbol_context` list no test for
  `Flask.handle_user_exception`; the walk stops at `Flask.__call__`, which the
  werkzeug test client calls, and at `wsgi_app`, which a test reads as a value
  (`PrefixPathMiddleware(app.wsgi_app, …)`) rather than calls.
- `get_symbol_context` lists the tests that call the target directly, not the
  tests that take a fixture that builds it; `blast_radius` does follow the
  fixture (`uses fixture `auth``).
- `lookup_symbol` matches a route by its shape or its tail, not by a prefix
  (`/auth` lists no `/auth/login`), and appends ranked full-text rows after an
  exact route match.
- `find_references(direction="callees")` hides a call on a local variable
  (`response(environ, start_response)`) unless `include_external` is set, and
  julie records no callee for a call on a subscript result.
- `find_references` for callers prints the first three import locations; the
  26 imports of `Flask` need `lookup_symbol(kind="import")`.
- `check_edit` labels a read of a removed class attribute `unresolved` when a
  test defines a subclass with the same attribute inside a test function
  (`Flask.session_interface` against `tests/test_reqctx.py`); the local-type
  rule covers the class, not its members.
- `blast_radius` on `src/flask/cli.py` misses `test_cli_name`, which reaches
  `FlaskGroup` only through an import-time construction in a test app.
- `lookup_symbol` lists a route's declared methods; `HEAD` and `OPTIONS`, which
  Flask adds at run time, are not shown.
- `check_edit` keeps 50 commands and prints `… N more` with the count of every
  other test found; `blast_radius()` on the whole diff walks from the symbol
  that holds each changed line, so a removed class attribute seeds its class.
